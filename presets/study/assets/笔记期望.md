# 笔记期望

> 这是「学习伙伴」写笔记前**必读**的文件（vault 根固定位置）。
> 它是笔记写法的唯一来源：结构、详略、文风、公式与图表偏好、领域侧重，都由这里决定。
> 改完保存即可生效——Agent 会发现签名变了并重新读取，不需要重启。
> 想删条款就直接删；想加条款就按小节往下写，自由 Markdown，没有语法要求。
>
> 唯一的"可检查项"语法（可选）：`- [检查] 禁止 xxx` / `- [检查] 必须 xxx`
> 写了才会被 `note_lint` 检查；不写就不检查。

---

## 受众与目标

- 读者是**半年后的我自己**：当时学过，现在基本忘光。
- 判据：只读这一篇，能不能把这件事重新学会、并且知道怎么验证。
- 目标不是应试速查，而是**可独立阅读的完整记录**。

## 文风

- 书面技术体，句子偏短；每段不超过 5 行，长内容拆段。
- 用加粗小标签起句分隔信息块：`**设计思想**：…`、`**易错点**：…`。
- 术语中英并置，首次出现给完整定义（`> ` 引用块），例如 `**球谐函数（Spherical Harmonics）**`。
- 少用 emoji；不用个人造词的短代号；不写"我认为/我觉得"这类主观句。
- 面向读者的作业式表达可以保留（"**模拟执行日志**"、"**验证的两层口径**"）。

## 详略

- **结论与判定条件详，推导过程按需保留**：重要定理与公式给完整推导，不跳步；"如何分辨/如何选择/条件是否满足"比"为什么成立"写得更细。
- 引入教材或权威来源时用引用块摘录关键句，并标注书名/作者/章节。
- 明确标注范围裁剪：老师说不要求、不考、未做——这类只在复习语境成立的标注要留着。
- **不吝啬篇幅**：为了省字数而压缩信息是本末倒置；但也别把同一结论换措辞写两遍。

## 结构

- 需要导航的长笔记：首行一级标题 → `## 目录`（锚点链接）→ 正文小节；章末用「本章知识脉络图」或「速查表」收束。
- 层级最深 4 级（`#`/`##`/`###`/`####`）；标题可用问句（"什么是有效数字？"）。
- 大类目内部按「概念 → 公式/定理 → 算法 → 例 → 对比」的顺序排。
- 不同知识点之间空一行；标题与内容之间空一行；小节之间用 `---` 分隔线切分。

## 公式与代码

- 行内公式 `$...$`；长公式与重要公式用块级 `$$...$$` 并编号 `\tag{3.1}`。
- 符号首现就地解释；多个符号集中出现时给符号说明表。
- 伪代码用三反引号围栏（`csharp` / `python` / `cpp` / `text`）并加中文注释；块前一句"这段在做什么"。
- 单块代码 ≤60 行；完整演示代码单次 ≤100 行（超出拆片段并标注作用/依赖/输入输出）。

## 图表与对比

- 表格承担三类职能：速查表、对比表、参数表；表头短，列数尽量 ≤4。
- 容易混淆的概念、算法、公式**必须**用表格做明确对比，可加「关键差异」列。
- 复杂关系可以用 Mermaid 流程图；不用颜色标记、不用 `==高亮==`、不用删除线。

## 交叉引用

- 笔记之间用 Obsidian wikilink：`[[目标标题]]`；关联小节写 `- 前置：[[目标]]`。
- 引用同资料的其他章节时写清"详见第N章 N.N节"。
- 提到旧笔记（无 ID 的 `.md`）时标 `（详见笔记：<根>/<相对路径>）`。

## 命名与落盘习惯

- 目录层级：`资料 / 章 / 节 / 块`（课程笔记四层）；项目类笔记可以是 `主题 / 块`。
- 章既可以是目录，也可以是 `第N章 章标题.md` 文件——按本 vault 的既成习惯走。
- 文件名**不加序号前缀**；阅读顺序由 frontmatter `顺序` 键与微目录承担。
- 每个主题目录都要有 `微目录.md`（由 `note_toc` 生成；手写导读段会被保留）。

## 领域侧重

> 这一节让 Agent 知道"这个学科该重什么"。没写的领域，Agent 会先问你再写。

- **图形学 / 渲染**：高精度数学推导，公式编号；伪代码用 HLSL；关键步骤给数值代入。
- **算法 / 数据结构**：复杂度推导写全（最好/最坏/平均），伪代码优先，配一道可手算的例。
- **操作系统 / 体系结构**：硬件行为与调度逻辑讲透，多画框图与时序。
- **人工智能 / 机器学习**：数学原理（链式法则、梯度）与训练流程并重，Python + NumPy 示例。
- **游戏引擎 / Unity**：讲清生命周期与装配时机，C# 片段给出"为什么这样接"。
- **美术 / DCC**：讲"为什么这样做"，不写"怎么点按钮"；给拓扑/UV/布线的判断标准。
- **数学 / 数值分析**：推导过程与收敛性、数值稳定性（为什么收敛、何时失效）都要写；LaTeX + 简单数值验证。
- **项目复盘类**：保留决策过程、被否方案与失败模式；省略开源项目的具体实现细节。

## 自我检查（写完过一遍）

- 半年后的我读完，能复述主线吗？关键结论有推导或出处吗？有可执行的验证或反例吗？
- 术语第一次出现时给了定义吗？容易混淆的地方给了对比吗？
- 有没有留下会话痕迹（"你"、"上次"、本机绝对路径、源码行号）？
- 篇幅是否由信息完备性决定，而不是为了凑字数或省字数？
