# 笔记期望

> 这是「学习伙伴」新会话和写笔记前**必读**的文件（vault 根固定位置）。
> 它是用户个性化文风的唯一来源：对话表达、自适应讲解，以及笔记的结构、详略、公式与图表偏好、领域侧重，都由这里决定。
> 改完保存即可生效——Agent 会发现签名变了并重新读取，不需要重启。
> 想删条款就直接删；想加条款就按小节往下写，自由 Markdown，没有语法要求。
> 文风优先级：用户当前明确要求 > 本文件的个性化偏好 > Agent 的内置默认文风。
>
> 唯一的"可检查项"语法（可选）：`- [检查] 禁止 xxx` / `- [检查] 必须 xxx`
> 写了才会被 `note_lint` 检查；不写就不检查。
> 唯一的模式设置语法（可选）：`- [设置] 快节奏复习窗口：30 天`。

---

## 对话表达

- 冷静技术搭档语气，直接、平实、有判断；不训导、不刻意热场。
- 自然正文优先；列表只用于并列项或步骤，标题只用于多个独立小节，表格只用于真实的二维对照。
- 同一结论不重复。不用机械加粗标签、空泛寒暄、过程复述或结尾总结填充篇幅。
- 问答直接回答后补必要机制与边界；追问可选且最多一个。
- 默认不出笔记预览；用户明确要求或准备归档时才生成。

## 自适应讲解

- 默认自动模式：先用 `note_search` 找相关笔记，再由 `study_mode` 综合当轮意图、问题范围、计划阶段、笔记证据与接触窗口判断。
- 单点直答保持简洁；从零学习、系统设计、应用、排错和比较默认详细；证据不足或主题不确定时一律详细。
- 模式只影响讲解和答疑，正式笔记始终完整。
- 快速/详细/自动是会话级覆盖；新会话恢复自动。默认不展示模式标签。
- 不做主动复习提醒，不生成待复习队列。
- [设置] 快节奏复习窗口：30 天

## 受众与目标

- 读者是**半年后的我自己**：当时学过，现在基本忘光。
- 判据：只读这一篇，能不能把这件事重新学会、并且知道怎么验证。
- 目标不是应试速查，而是**可独立阅读的完整记录**。

## 文风

- 克制技术散文：直接、平实、有判断。段落承载事实、机制、证据或边界，不靠铺陈和重复强调。
- 中性陈述为主；只有归属、踩坑经历和设计取舍使用“我”。
- 删除“真正值钱的是”“一句话收口”“顺带一句”“这站/下一站”等讲者旁白。章节自然结束，不默认追加口播稿或行动号召。
- 比喻只用于降低理解成本，同一机制最多一个；不只用于评价、煽情或制造金句。
- 只在纠正真实误解时使用“不是 X，而是 Y”，不把它当固定句式。
- 术语首次出现时就地给一句定义；外部原文才使用 `> ` 引用块。
- 少用 emoji；不用个人造词的短代号；不写"我认为/我觉得"这类主观句。
- 面向读者的作业式表达可以保留（"**模拟执行日志**"、"**验证的两层口径**"）。

## 表达方式

- 按关系选择最轻且最准确的形式：线性因果用箭头链或编号步骤，层级与依赖用 Mermaid `flowchart`，类关系用 `classDiagram`，数据结构用 `erDiagram`，交互时序用 `sequenceDiagram`，状态迁移用 `stateDiagram-v2`，版本与事件顺序用 `timeline`，多对象共同维度用表格。
- 分类使用缩进树，设计取舍使用共同维度矩阵，排障使用“触发 → 症状 → 根因 → 修复”链。
- 依赖、状态、时序、数据流和复杂失败链优先画图；简单定义和单点事实直接写正文。
- 图必须承载结构信息。图旁只解释关键边、触发条件、失效点和判断依据，不逐节点复述。
- 图中使用中文标签，不用装饰色和 emoji；不为“图文感”制造无用图。

## 详略

- **结论与判定条件详，推导过程按需保留**：重要定理与公式给完整推导，不跳步；"如何分辨/如何选择/条件是否满足"比"为什么成立"写得更细。
- 引入教材或权威来源时用引用块摘录关键句，并标注书名/作者/章节。
- 明确标注范围裁剪：老师说不要求、不考、未做——这类只在复习语境成立的标注要留着。
- **保信息，删噪声**：保留足以独立复读的机制、证据、失败模式和边界；删除讲者旁白、重复强调、无关延伸和机械收尾。
- 篇幅由技术信息决定。长不等于完整，短也不等于简陋。

## 结构

- 每篇只有一个 H1，正文从 H1 开始；H1 后接一段普通导语，说明结论和范围。
- 引用块只用于外部原文或需要原样保留的材料，不放在 H1 前充当重复摘要。
- H2 表示主要论证阶段，H3 表示 H2 内的具体机制。不设固定小节模板，按内容组织。
- 加粗只标记术语、关键条件或真实风险，不用 `**设计思想**：`、`**易错点**：` 等标签给每段起头。
- 需要导航的长笔记可以在 H1 后加入 `## 目录`；不要求每篇都用「知识脉络图」或「速查表」收束。
- 层级最深 4 级（`#`/`##`/`###`/`####`）；标题可用问句（"什么是有效数字？"）。
- 不同知识点之间空一行；标题与内容之间空一行。优先用标题层级和留白分组，`---` 只在确需分隔两个大块时使用。
- 前置、后续与关联集中在文末，不进入正文主线。正文不默认附加“90 秒口径”或面试问答；用户明确要求时再单独生成。

## 公式与代码

- 行内公式 `$...$`；长公式与重要公式用块级 `$$...$$` 并编号 `\tag{3.1}`。
- 符号首现就地解释；多个符号集中出现时给符号说明表。
- 伪代码用三反引号围栏（`csharp` / `python` / `cpp` / `text`）并加中文注释；块前一句"这段在做什么"。
- 单块代码 ≤60 行；完整演示代码单次 ≤100 行（超出拆片段并标注作用/依赖/输入输出）。

## 图表与对比

- 表格承担三类职能：速查表、对比表、参数表；表头短，列数尽量 ≤4。
- 容易混淆的概念、算法、公式按共同维度做明确对比，可加「关键差异」列。
- 线性短链可用 `asmdef → csproj → MSBuild` 这类文本箭头；分支、循环、层级、时序和状态迁移优先用 Mermaid。
- 不用颜色标记、不用 `==高亮==`、不用删除线。

## 交叉引用

- 笔记之间用 Obsidian wikilink：`[[目标标题]]`；关联小节写 `- 前置：[[目标]]`。
- 引用同资料的其他章节时写清"详见第N章 N.N节"。
- 提到旧笔记（无 ID 的 `.md`）时标 `（详见笔记：<根>/<相对路径>）`。

## 命名与落盘习惯

- 目录层级：`资料 / 章 / 节 / 块`（课程笔记四层）；项目类笔记可以是 `主题 / 块`。
- 章既可以是目录，也可以是 `第N章 章标题.md` 文件——按本 vault 的既成习惯走。
- 文件名**不加序号前缀**；阅读顺序由 frontmatter `顺序` 键与微目录承担。
- 每个主题目录都要有 `微目录.md`（由 `note_toc` 生成；手写导读段会被保留）。

## 领域侧重

> 这一节让 Agent 知道"这个学科该重什么"。没写的领域，Agent 会先问你再写。

- **图形学 / 渲染**：高精度数学推导，公式编号；伪代码用 HLSL；关键步骤给数值代入。
- **算法 / 数据结构**：复杂度推导写全（最好/最坏/平均），伪代码优先，配一道可手算的例。
- **操作系统 / 体系结构**：硬件行为与调度逻辑讲透，多画框图与时序。
- **人工智能 / 机器学习**：数学原理（链式法则、梯度）与训练流程并重，Python + NumPy 示例。
- **游戏引擎 / Unity**：讲清生命周期与装配时机，C# 片段给出"为什么这样接"。
- **美术 / DCC**：讲"为什么这样做"，不写"怎么点按钮"；给拓扑/UV/布线的判断标准。
- **数学 / 数值分析**：推导过程与收敛性、数值稳定性（为什么收敛、何时失效）都要写；LaTeX + 简单数值验证。
- **项目复盘类**：保留决策过程、被否方案与失败模式；省略开源项目的具体实现细节。

## 自我检查（写完过一遍）

- 半年后的我读完，能复述主线吗？关键结论有推导或出处吗？有可执行的验证或反例吗？
- 术语第一次出现时给了定义吗？容易混淆的地方给了对比吗？
- 有没有留下会话痕迹（"你"、"上次"、本机绝对路径、源码行号）？
- 是否删掉了讲者旁白、重复收口和无信息比喻？图示是否真的表达了关系，而不是装饰？
- 标题能否直接看出主次？篇幅是否由技术信息决定，而不是为了凑字数或省字数？
