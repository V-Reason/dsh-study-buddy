# 课程编译器

讲解质量的根因通常不是句子，而是教师手里没有课程模型。先完成全量覆盖与课程重建，再开始讲课。

## 不可跳过的顺序

```
来源盘点 → 证据登记 → 系统重建 → 课程设计 → 覆盖验证 → 用户批准 → 分轮授课
```

用户没有明确批准课程母图前，只能展示备课结果、解释取舍或继续修改，不进入正式课程。
课程母图经用户明确批准后才可激活；沉默和追问都不算批准。

## 全量覆盖，分层精读

全量覆盖不等于把全部文件塞进一次上下文。大项目必须分轮处理：

1. `study_course(action=inventory)` 建立全文件清单与来源指纹。代码、配表、场景、预制体、资源、音频、工具、文档、测试都进清单。
2. 每个文件至少进入一个覆盖范围；被排除的第三方 DLL、缓存、`.meta`、无法读取的二进制必须写原因。
3. 文本资料全量搜索并分层精读；图片只写实际观察到的内容，音频无法理解时标为待验证，不假装听过。
4. 当前源码/测试/运行事实优先于项目文档；项目文档优先于旧笔记。冲突必须登记，以可核验来源为准。

“全量覆盖”指没有系统被静默遗漏；“分层精读”指主轴深读、外围按需读。不要用“文件太多”当漏读理由，也不要用“都读过了”掩盖没有综合。

## 系统重建

先建立四张关系视图：

- 内容生产链：策划表/美术/音频/场景 → 管线 → 运行期消费。
- 启动与帧循环：构建 → 资源与配置 → 装配 → 物理帧/渲染帧。
- 玩法闭环：输入 → 决策/状态 → 世界变化 → 结算 → 表现。
- 工程约束：层依赖、所有权、单一写者、事件方向、失败边界。

再定义 4–6 条**完整运行链**。每条运行链必须能从起点观察到终点，例如“一次投掷进入地块反应并产生反馈”。专题、类、接口、配表都挂在运行链下，不按源码目录排课。

每个机制回答：

```text
上一节点输出什么
→ 本节点接收什么
→ 本节点改变什么
→ 下一节点消费什么
```

## 概念分级

课程中明确标注：

| 级别 | 含义 |
| :-- | :-- |
| 主轴必懂 | 不理解就无法解释整个运行链 |
| 当前支撑 | 只服务当前机制，但要能解释 |
| 实现细节 | 知道入口与作用，不要求记忆全部字段 |
| 以后可查 | 外围工具、兼容分支、低频实现 |

从每个主轴机制反向计算前置闭包。距离场、SDF、状态机、时间步、所有权等概念如果挡住当前因果，必须在依赖它的代码之前出现；不由用户提醒。

## 可见课程母图

课程母图是 vault 内普通 Markdown，可读、可编辑、可版本控制。它不是实际 PowerPoint；“讲义 PPT”只作为课程框架的比喻。

母图至少包含：

- 目标能力与不适用范围。
- 来源快照、覆盖矩阵和未验证项。
- 四张系统视图与完整运行链列表。
- 主轴概念、支撑概念及其依赖。
- 运行链的入口、可观察终点、证据和讲次。
- 每讲上一输出、本步输出、源码/测试证据与失效边界。

机器可校验字段放在 `course-json` 围栏中；其外保留正常可读的说明和 Mermaid。不要让课程结构只存在于聊天。

## 证据与课程质量闸

激活前同时满足：

- 清单内每个来源命中覆盖范围，或不覆盖原因明确。
- 每条运行链有可观察终点和真实证据。
- 每个讲次有上一输出、本步输出、前置概念、证据与边界。
- 所有概念引用存在；所有前置依赖有定义。
- 主轴概念至少有一个 `core`，不能全是外围索引。
- 蓝图指纹与来源指纹仍属于本次批准版本。
- 用户已经明确批准；沉默、继续追问和“先看看”都不算批准。

使用：

```text
study_course(action=inventory, courseId, roots)
study_course(action=validate, blueprintRef)
study_course(action=activate, blueprintRef)
study_course(action=status)
study_course(action=position, run, lesson, previousOutput, mapSlice)
```

验证失败先修母图或重新盘点，不绕过 `activate` 门禁。

## 交给授课阶段

激活后课程按固定路线推进。每轮带出：

- 当前地图位置；
- 上一节点输出；
- 本轮只改变的一条边；
- 一个真实 trace 与对应证据；
- 下一节点会消费什么。

不推断掌握，不做主动测验。只有用户明确说没懂、乱了或唐突时才局部改道；改道结束回到母图。课程状态只记录已覆盖位置和用户明确的疑问，不写“已掌握”。

## 常见错误

- 把课程母图写成目录：只有标题和文件，没有因果边。
- 把完整运行链拆成互不相识的模块：InputBuffer 讲完直接跳 ActorLedger。
- 把“源码全部读过”当课程模型：没有综合、优先级和证据。
- 把外围资产全部同深度展开：覆盖到了，但主轴被稀释。
- 让旧笔记冒充源码证据：可以作线索，不能覆盖当前事实。
- 用户未批准就 `activate`：流程上等于伪造拍板。
