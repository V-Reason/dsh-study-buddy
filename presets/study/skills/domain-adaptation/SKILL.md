# 跨领域适配细则

## 单一来源：侧重写在《笔记期望.md》里

**讲解与笔记的领域侧重由用户的期望文件决定**，本技能不再自带一份"标准侧重表"——两套口径必然漂移（需求 R9）。

所以流程是：

1. 按下面的速查表识别**领域与关键词**（这只是"这是什么学科"的判断，不是写法规定）。
2. 打开 vault 根的《笔记期望.md》，看它有没有写这个领域的侧重（如"图形学：高精度数学推导 + HLSL + LaTeX""美术：讲为什么这样做，而不是怎么点按钮"）。
3. 有 → **照期望写**，不要再掺入本技能的偏好。
4. 没有 → 按通用模式讲（通俗重构 + 底层逻辑 + 反诘），并**建议用户补一条期望**，例如：

   ```
   ## 领域侧重
   - 图形学/渲染：高精度数学推导，公式给编号；代码用 HLSL
   - 美术/DCC：讲"为什么这样做"，不写操作步骤
   ```

   用户同意后再写进期望文件（或由他说"记住…"，落到 `study_memory` 的 `prefs.*`）。

## 交叉领域联动

两领域问题必须联动两套知识（这类"联动"是内容判断，不受期望文件影响）：

- 渲染管线缓存未命中 → 体系结构 + 图形学
- 协程底层线程 → 引擎 + 操作系统
- 矩阵乘法加速 → AI + 体系结构

联动时在笔记里用 wikilink 互链（`note_link` 的 `sibling`），让两块在 Obsidian 里能互相跳转。

## 判定边界

- 领域不明**先问一句**，不猜。
- 资料自带领域（如 GAMES101）按资料切入；发现跨领域依赖主动提示。
- 未覆盖领域：通用模式 + 落 `未分类/<领域>/`（或按用户规划给的路径）。
- 加载边界：纯复述/复习/常识性提问可不加载本技能（通用模式够用），避免白付上下文。
