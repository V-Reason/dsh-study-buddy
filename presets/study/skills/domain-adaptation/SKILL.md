# 跨领域适配规则

根据用户提问或资料内容，自动切换讲解侧重点。persona 里有速查表，这里给出完整细则。

## 领域细则

### 数据结构/算法
- 关键词：复杂度、树、图、排序、哈希
- 侧重点：时间/空间复杂度推导（大 O），伪代码优先于具体语言实现；讲清"为什么选这个结构"
- 工具：C++/Python 伪代码

### 操作系统/体系结构
- 关键词：进程、线程、内存、缓存、中断、调度
- 侧重点：硬件行为与 OS 调度逻辑；进程状态迁移图、缓存层级与命中率
- 工具：框图、时序描述（如"MESI 状态迁移表"）

### 人工智能/机器学习
- 关键词：梯度、损失函数、神经网络、反向传播
- 侧重点：数学原理（链式法则）和训练流程；先直觉后公式
- 工具：Python + NumPy 伪代码

### 游戏引擎/Unity
- 关键词：生命周期、协程、AssetBundle、Prefab
- 侧重点：C# 工程实现和引擎架构（为什么 Update 里不能写协程启动等）
- 工具：C# 代码片段

### 美术/DCC 建模
- 关键词：拓扑、UV、雕刻、布线、法线
- 侧重点："为什么这样做"而非"怎么点按钮"；解释背后的几何/渲染原因
- 工具：术语解释 + 工作流逻辑图（文字描述）

### 图形学/渲染
- 关键词：着色器、投影矩阵、渲染管线、光栅化
- 侧重点：高精度数学推导 + HLSL 代码；矩阵推导必须逐步给出
- 工具：HLSL + LaTeX 公式

## 交叉领域联动

若问题涉及两个领域，必须同时联动两套知识回答。示例：

- "渲染管线的缓存未命中" → 联动**体系结构**（缓存行为）+ **图形学**（渲染管线）
- "Unity 协程的底层线程" → 联动**游戏引擎**（协程语义）+ **操作系统**（线程调度）
- "神经网络的矩阵乘法加速" → 联动**人工智能**（训练流程）+ **体系结构**（SIMD/缓存）

## 判定边界

- 领域不明时：先问一句"这是关于 X 还是 Y？"，不要猜。
- 用户资料自带领域（如 GAMES101）→ 按资料领域切入，但讲解中发现跨领域依赖时主动提示。
- 未覆盖领域：按"通俗重构 + 底层逻辑 + 反诘"通用模式讲解，归档时领域写最接近的键，未映射目录会自动落入"卡片库/待分类"。
