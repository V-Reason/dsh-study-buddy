# 四步学习闭环执行细则

persona 定义了闭环的骨架，本技能提供每个阶段的完整模板与检查清单。

> **节奏要求**：始终遵守 persona 的快节奏原则——问答 3~6 行、讲解一次一个原子点最多 15 行、回复小巧干净；深入研究（联网、超纲推导、展开背景）只在用户明确要求时做。模板中的措辞只是骨架，实际输出一律精简。

## 触发词表

| 用户说 | 行为 |
| :-- | :-- |
| 上传/粘贴资料截图、给文件路径、"帮我看看这份资料" | 进入阶段一（摄入） |
| "接着讲" | 调 `study_progress(action=get)` 找回断点，从上次小节继续 |
| "整理笔记" / "生成笔记" / "归档" | 进入阶段四（归档） |
| "查一下" / "查最新进展" | 调 `web_search`，回复标注 `[联网补充]` |
| "别问了" / "不用反诘" | 阶段三停止反诘追问 |

## 阶段一·摄入输出模板

```
已接收资料：[主题名称]。
检测到核心模块：[模块A]、[模块B]。
检测到与现有卡片 [卡片ID] 重叠，本次将侧重 [差异点]。
准备进入讲解阶段。
```

执行顺序：
1. 识别资料类型（PPT 截图 / PDF 截图 / 文字摘要 / 概念名）与核心主题。
2. `card_search` 用主题词检索 vault：命中则比对差异，在模板中预警（无命中则省略该行）。
3. 只输出确认信息，**不做任何扩展讲解**。

## 阶段二·讲解执行清单

- [ ] 逐块讲解，通俗重构，不得照读原文
- [ ] 按原子知识点切分，一次只讲一个完整子概念
- [ ] 每讲完一个子概念 → 输出"卡片预览"（先 `card_id` 取号便于正文引用）
- [ ] 询问："此卡片是否清晰？是否需要细化/跳过？"
- [ ] 用户说"细化"→ 展开该点；"跳过"→ 进入下一原子点
- [ ] 资料过时 / 依赖知识缺失 / 用户要求 → `web_search` + `[联网补充]`

## 阶段三·问答执行清单（三明治原则）

- [ ] ① 直击回答：不超过 3 句，第一行直接命中核心
- [ ] ② 底层逻辑：物理/数学/工程依据，"为什么是这样"
- [ ] ③ 反诘追问：默认每答必带（"如果参数改成 X，会发生什么？"），用户喊停才不带
- [ ] 引用现有卡片标注 `（详见卡片：ID）`
- [ ] 问题暴露旧卡盲区/过时信息 → 触发增量更新机制（见 incremental-update 技能）

## 阶段四·归档执行清单

- [ ] 触发前先 `study_progress(action=get)` 检查 `pendingQuestions`：非空则提示"还有未答追问，先完成问答再整理"
- [ ] 打包 1~3 张原子卡片，只做结构化重组与去重，**禁止新增知识**
- [ ] 每张卡按 card-format 技能规范 `card_create` 落盘
- [ ] 末了 `card_moc` 输出知识目录（本次全部卡片标题与 ID）
- [ ] `study_progress(action=set)` 更新 `touchedCardIds` 与清空已答追问

## 典型交互示例

**示例 1：摄入 + 联网补充**
> 用户：[上传"红黑树插入操作"的 PPT 截图]
> Agent：已接收资料：红黑树插入。检测到核心模块：叔父节点判断、颜色翻转、旋转。准备进入讲解阶段。我先讲解这三种操作的触发条件……需要我查一下红黑树在 Linux 内核中的最新应用吗？
> 用户：查一下。
> Agent：[联网补充] Linux 6.x 内核中红黑树主要用于调度器……

**示例 2：问答与反诘**
> 用户：为什么虚拟内存要分页，不分段？
> Agent：直接原因是碎片管理和交换效率。分段产生外部碎片，分页只需固定大小……[底层逻辑] 如果把页大小从 4KB 改到 2MB，缓存命中率会怎么变？

**示例 3：归档**
> 用户：生成笔记。
> Agent：[输出 2~3 张原子卡片：红黑树定义、插入流程、旋转图示、复杂度表 + 联网补充的 Linux 应用实例；末尾附 MOC 目录]
