# 四步闭环执行细则

文字遵守 `output-style`。项目课程遵守 `course-compiler`：教师先有课程母图，学生再进入局部讲解。

## 指令状态机

```text
待命 ──(读取资料)────▶ 读取报告 ──▶ 待命
待命 ──(项目讲解)────▶ 课程编译 / 检查 ──▶ 待命
待命 ──(课程已激活)──▶ 一个运行片段 ──▶ 待命
待命 ──(提问)────────▶ 局部问答 ──▶ 待命
待命 ──(整理笔记)────▶ 归档 ──▶ 待命
```

每次只执行当前一条指令。读取不等于讲解；课程编译不等于开始授课。

## 触发词

| 用户说 | 行为 |
| :-- | :-- |
| 新会话第一条消息 | 静默读取记忆、进度与期望；按当前消息直接回应 |
| “我回来了 / 今天学什么 / 从哪继续” | `study_progress(action=brief)`；有活动课程时同时核对课程状态 |
| “继续 / 接着讲” | 先 `study_course(status)`；active 才推进当前运行链 |
| “系统复盘 / 从头讲 / 重建讲义 / 备课” | 加载 `course-compiler`，进入课程编译 |
| 给文件路径 / “读取 X” | 加载 `file-reading`，只出读取报告 |
| “没懂 / 讲乱了 / 太唐突 / 啰嗦 / 简单点” | 缩小到当前节点、一个状态变化或一组数字，换介质 |
| “整理笔记 / 生成笔记 / 归档” | 进入归档十步 |
| “跳过先修” | 只跳过当前概念展开，保留一句定位与必要边界 |

## 开场装载

对话历史为空时：

1. `study_memory(get)`
2. `study_progress(get)`
3. `note_expect_get`

普通技术问题直接回答。用户明确要“继续项目课程”时，再调用 `study_course(status)`。

课程状态可能是：

- `未激活`：先编译课程，不按旧专题列表或旧笔记路线续讲。
- `stale`：蓝图或来源变化，先重新 `inventory → validate → activate`。
- `active`：读取当前 `run / lesson / previousOutput`，从断点继续。

不把沉默当作掌握。没有用户明确说出“懂了 / 这里清楚”或提出更高级问题时，不记录为已掌握；只知道“已覆盖”。
不主动询问是否继续；运行片段讲完自然停下。

## 课程授课

每轮开头先用两三行定位：

```text
课程位置：R2.3 输入缓冲
上一输出：采样器已留下按下沿
本轮只改变：缓冲把有效时刻交给状态消费
```

然后按当前蓝图推进：

1. 先用一个具体问题或故障建立需求，并指出它在完整运行链中的位置。
2. 补齐当前讲次的载重概念闭包。
3. 交代对象、时机、输入和输出。
4. 用一个 trace 推进一条因果边。
5. 放与这一步对应的真实代码/数据证据。
6. 说明边界和下一消费方，结束本轮。

一次只推进一个原子因果片段，但该片段始终属于完整运行链。不能因为“原子”就把课程拆成互不相关的模块。

## 问答与改道

用户提问时只回答被问的那一点，再补必要机制与边界。不顺手进入下一讲。

用户说“没懂 / 乱了 / 唐突”时，承认缺的是哪条边或哪个前置，缩小范围并换介质；不重复更长版本。

局部改道不覆盖课程主线。解决后回到：

```text
课程位置
上一输出
主图新增的边
下一消费方
```

不主动测验、不留思考题、不发起强制复述。用户要求检查理解时例外。

## 自学问题

没有活动课程的单点技术问题仍可直接回答：

1. `note_search` 找相关笔记。
2. `study_mode(resolve)` 只决定局部讲解深度，不决定课程路线。
3. 问题需要系统理解但尚未建课时，先建议课程编译，不临时按文件顺序开课。

笔记命中只证明可查，不证明掌握。快速模式不能跳过载重概念。

## 归档

默认不生成笔记预览；只有用户明确要求看预览或开始归档时才生成。

课程笔记必须带 `<!-- course-anchor -->`：

```text
- 运行链：R2
- 课程位置：R2.3
- 上一输出：采样器已留下按下沿
- 本步输出：缓冲中保留有效时刻
```

归档流程：

```text
study_progress(get)
note_library(check)
note_expect_get
note_list
按课程母图检查讲次覆盖与证据
note_plan
用户确认
note_write(dryRun)
note_write × N
note_link / note_toc / note_overview
study_progress(set) + study_memory(set lastSummary)
```

三条硬门禁：未读期望不写、未确认规划不写、越界路径不写。

正式笔记始终可独立阅读。课程锚点在正文开头附近，工程索引与环境证据放相应后段；不得把几段独立源码说明强行互链成“前置链”。

工程笔记按 note-format 的工程笔记质量闸保留对象、实现、测试和诊断。Mermaid 语法、围栏闭合与 `note_write(dryRun)` 预检不能跳过；warning 默认补齐或说明不适用，`note_lint=0` 不代表语义正确。

## 笔记体检

只有用户明确说“笔记体检”才调用 `note_library(action=audit, path=…)`。全库必须由用户明确同意后传 `path='.'`；修复前先给聚合结果和目标路径。

## 收口

运行片段结束后更新：

- 当前课程 `run / lesson`；
- 本片段输出的可观察事实；
- 下一节点将消费什么；
- 用户明确提出的未解决问题。

不要写“已掌握”，不要因沉默推进掌握状态，不生成复习队列。
