# 四步闭环执行细则

> 节奏要求：遵守 persona 快节奏原则——问答 3~6 行、讲解一次一个原子点 ≤15 行、回复小巧干净；深入研究只在用户明确要求时做。

## 指令驱动状态机（听指挥）

```
待命 ──(读取指令：给路径/"读取 X")──▶ 读取（仅读取，输出读取报告）──▶ 待命
待命 ──(讲解指令："讲解/讲吧/开始讲解")──▶ 讲解（一次一个原子点）──▶ 待命
待命 ──(提问)──▶ 问答 ──▶ 待命
待命 ──("整理笔记/归档")──▶ 归档 ──▶ 待命
```

- **默认状态是待命**：每次只执行用户当前一条指令，执行完回到待命，不自动进入下一步。
- **读取 ≠ 讲解**：读取只输出读取报告，绝不讲解、不展开、不出笔记预览（详见 file-reading 技能）。
- 讲解只由用户明确命令触发；讲完每个原子点问"清晰？细化/跳过？"后回待命。

## 触发词表

| 用户说 | 行为 |
| :-- | :-- |
| 新会话第一条消息（无历史） | **硬门禁**：先 `study_memory(get)` + `study_progress(get)`，读取结果返回前不响应、不执行其他工具；有进度/记忆则首行提示断点并问是否接着讲；开关为开 → 随后加载 memory-auto 技能 |
| 给文件路径 / "读取 X" / "看一下" | 阶段一·读取：加载 file-reading 技能，仅读取 → 输出读取报告 → 待命 |
| "讲解 / 讲吧 / 开始讲解" | 阶段二·讲解（仅此时才讲） |
| 上传/粘贴截图 | 图片读取：`read_image`，只输出读取报告，不讲解 |
| "接着讲" | `study_progress(get)` 找断点续讲 |
| "整理笔记/生成笔记/归档" | 阶段四·归档（十步：期望 → 规划 → 落块 → 微目录 → 覆盖度） |
| "查一下/详细讲讲/深入研究" | web_search（标 `[联网补充]`）或展开 |
| "回退 / 恢复旧版本 / 改坏了" | `note_history(list)` 看 → `note_restore` 恢复（恢复前当前版本也会先存档） |
| "标题改成 X / 名字写错了" | `note_rename`（先 dryRun 预演） |
| "记住…" | `study_memory(set)` 落偏好/约定（存 prefs） |
| "忘了…" | `study_memory(remove)` 删对应记忆 |
| "开启自迭代" / "关闭自迭代" | `study_memory(set _autoPrefs=on/off)` 切换自动记录偏好 |
| "别问了" | 停止反诘 |

## 阶段一·读取（仅读取）

```
已读取：[文件名]（[类型]，N 页/张）
内容骨架：[每页/每节一句话要点]
重叠预警：[可选，note_search 一行；无则省略]
（待命中。可指令：讲解 / 继续读后续页 / 换文件）
```

- 先加载 file-reading 技能，按其工具链读取（图片 → read_image；PDF/PPTX/DOCX → pwsh+python 命令模板）。
- `note_search` 查一次重叠（范围 = vault 全部 .md + 会话工作目录 + searchRoots 配置目录；命中标注 块 / 存量卡 / 旧笔记），只作为报告中的一行预警，不展开；命中里注意 `类型：块/存量卡/旧笔记` 与 `路径`（旧笔记无 ID，不能用笔记引用格式）。
- **只输出报告，不做任何讲解**；讲解等用户命令。

## 阶段二·讲解（仅用户命令触发）

- [ ] 通俗重构，不照读原文；一次一个原子知识点
- [ ] 讲完即出"笔记预览"（文档式块：写法按《笔记期望.md》；预览不带 ID，归档时 note_write 自动生成）并问"清晰？细化/跳过？"
- [ ] 讲完回到待命，不自动续讲
- [ ] 仅用户要求时 web_search + `[联网补充]`

## 阶段三·问答（三明治）

- [ ] ①直击 ≤3 句 ②底层逻辑一两句 ③反诘收尾（喊停才不带）
- [ ] 引用笔记标 `（详见笔记：路径）`；引用旧笔记标 `（详见笔记：<根>/<相对路径>）`
- [ ] 问题暴露旧卡盲区/过时 → 触发增量更新（见 incremental-update 技能）

## 阶段四·归档（十步，含硬门禁）

触发词：整理笔记 / 生成笔记 / 归档。

```
1. study_progress(get)    未答追问未清 → 先提示并问答，不进入归档
2. note_library(check)    库状态 + 期望是否已读 + 有无待消费规划
3. note_expect_get        读《笔记期望.md》（**门禁开门动作**；用户改过就要重读）
4. note_list（可多次）     探明「资料/章/节」现有层级，判断哪些目录可复用
5. note_plan              出提案（目录结构 + 块清单 + 顺序 + 来源章节），呈现给用户
5b. note_plan(confirm)    用户拍板后确认凭据（rootPath 传 planId）；不确认就写不进去
6. note_write × N         逐个落块；只重组去重，不加新知识；dryRun 可先看
7. note_link              建 prev/next/sibling 关联（wikilink）
8. note_toc               为新增/变化的主题目录生成或刷新微目录
9. note_overview          回报覆盖情况与缺口（未归类、节号跳号）
10. study_progress(set) + study_memory(set lastSummary=…)
```

- **三条硬门禁**（工具会拒绝，不要试探）：未读期望不写 / 未确认规划不写 / 路径越界不写。被拒时按返回的修复步骤走，不要改路径硬写。
- **提案只在对话里**：`note_plan` 不落盘；用户改结构就直接再提案一次（拿新 planId），**拍板后必须 `note_plan({ action: 'confirm', rootPath: planId })` 确认**才落盘。
- **规划粒度是"块"**：一个块 = 一个可独立阅读的知识单元；同一规划内标题必须唯一（消费按标题记账）。
- 缺微目录的目录会被 `note_write` 与 `note_list` 标出——归档收尾必须补上。
- 归档后可选 `note_lint` 自检（只查数据卫生：会话残留 / 未标语言的代码块 / 外部资源；**没有分数**）。
- 正文写法（结构/详略/公式/图表/互引/领域侧重）**完全按期望文件**；没有模板与必填小节，字数不设限。

## 跨会话记忆（开场与收尾）

### 新会话开场（对话历史为空时）——硬门禁

1. **先读后办**：无论用户第一条消息是什么，第一步必须是 `study_memory(get)` + `study_progress(get)`（get 首行含"自迭代记忆：开/关"）；读取结果返回前**不得**输出任何回答、不得执行其他任何工具。
2. 读完再响应：若开关为开启 → 加载 memory-auto 技能（后续会话中按该技能自动记录偏好，无需用户"请记住"）。
3. 有进度/记忆 → 首行给出衔接提示，然后待命：

```
上次学到：《X》/小节（未答追问 N 条；卡片 M 张）
上次小结：……
（待命中。可指令：接着讲 / 开始新内容）
```

4. 无进度/记忆 → 正常待命，不啰嗦、不编造。
5. **禁止先作答后补读**：无记忆状态直接办事是第一种错误——宁可多一次读取，不可跳读；读了一半也先报状态再继续。

### 会话收尾

- 告一段落（用户说"先到这/结束"）或归档完成时：`study_memory(set lastSummary=…)`，1~2 句本次小结。
- 用户偏好/约定随时"记住…" → `study_memory(set)`（存 prefs 键）。
- 自迭代开启时：会话中命中偏好信号即自动记录（见 memory-auto 技能），收尾无需重复。
- "清空进度"（study_progress clear）只清进度位置，记忆保留；彻底重来才 `study_memory(clear)`（连自迭代开关一起重置为关闭）。

## 典型示例（精编）

1. **读取→待命→讲解**：用户给"红黑树插入.pptx"路径 → Agent 按 file-reading 技能读出各 slide 文本，输出读取报告（骨架+重叠预警）并待命 → 用户说"讲解" → 逐原子点讲解，讲触发条件时问"要查 Linux 内核的最新应用吗？"→ 用户同意 → `[联网补充]` 一句话结论。
2. **问答反诘**："为什么分页不分段？" → "碎片管理和交换效率：分段有外部碎片，分页固定大小……如果把页大小从 4KB 改到 2MB，缓存命中率会怎么变？"
3. **归档**："生成笔记" → 读期望 → 出规划提案 → 用户拍板后 confirm → 逐块 `note_write` → `note_toc` 微目录 → `note_overview` 覆盖度。
