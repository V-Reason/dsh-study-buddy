# 卡片格式规范（2026-09 重设计）

**知识即卡片**：卡片与普通笔记同库、同目录；旧笔记可原地升级（card_update replace 保留历史）。

**卡片的目标**：不是"原子知识块"，而是**一份可以独立读完的微课程**——假设读者已经忘光了 80%。
判据不是"写全了没有"，而是"忘光了的人能不能在 30 分钟内重建它"。

**三条硬规则（反堆砌，违反即返工）**

1. **主干线唯一**：每张卡必须能用一句话概括"从问题到答案的一条路"，写在 `### 主干线`。
   所有内容都必须挂在这条线上：`问题 → 关键约束 → 解法 → 代价 → 验证方式`。
   > 反例（堆砌）：先讲数学定义、再讲参数、再讲探针类型、再讲性能——四段并列，读者不知道它们为什么放在一起。
   > 正例（主干线）：间接光算不起 → 所以要预计算 → 漫反射用 9 个系数、镜面用 mip 立方图 → 于是配置要喂数据、shader 要采样 → 验证就看"关主光后暗部是否还亮"。
2. **删除测试**：逐节问"删掉这一节，读者会迷路吗？" 会 → 在主线上，保留；不会 → 移到 `<details>` 折叠块（扩展阅读/推导细节）或直接删。
3. **前置检查**：卡顶列出"读这张卡前需要知道什么"，并链接到前置卡（≤2 条直接前置）+ 明确写出"不需要知道"什么，避免读者卡在无关细节上。

**其余反堆砌要点**：小节之间用因果连接（"因为…所以…""这一步解决上一节的什么"），禁止"下面我们看…"这类无信息过渡；
每个小节必须提供新信息；同一结论不要在多处重复表述（措辞漂移会造成口径不一致）。

**正文字数：不设上下限**（2026-09 取消）。长度由信息完备性决定，字数不是质量信号。
替代约束：① 单一主题（一张卡只回答一个问题，主题变大就拆卡并互链）；② 信息增益；③ 完备性三问——小白读完能复述主线吗？关键结论有推导或出处吗？有可执行的验证或反例吗？
**唯一保留的长度硬限**：一句话定义 ≤60 字（检索契约与 TL;DR，不是知识载体）。

## 通用骨架

```markdown
---
ID: [YYYYMMDDHHmm_随机，工具自动生成]
标题: [概念名称]
领域: #<领域键> #<补充标签>
来源: [资料名称]
状态: 草稿 / 已确认 / 需更新
模板: 理论型 | 工程型 | 对比型      # 可选；card_create 自动推断并回显
---

> 一句话定义（≤30 字最佳，≤60 字硬上限；裸引用块，不加标题）。

### 重入点                      # 长卡（>3000 字）必填；三种读法
- **30 秒**：<心智模型一句话 + 结论一句话>
- **5 分钟**：<读 主干线 + 阶梯式解剖 第 1~2 层>
- **30 分钟**：<全卡 + 自测题 / 跑一遍验证实验>

### 前置检查                    # 有前置卡时必填
- 需要知道：<概念 A>（详见卡片：<ID>）、<概念 B>（详见卡片：<ID>）   # ≤2 条直接前置
- 不需要知道：<明确排除，避免读者卡住>

### 核心思想
**一句话讲清**：<因果本质>
**为什么**：<它解决什么问题 / 为什么重要>
**记忆锚点**：<口诀或类比，一句>

### 主干线
<问题> → <关键约束> → <解法> → <代价> → <验证方式>

### 阶梯式解剖
**第 1 层 · 直觉**：…
**第 2 层 · 机制**：…
**第 3 层 · 细节与推导**：…
**第 4 层 · 边界与反例**：…
（层数 4~6，必须带 `第 N 层` 序号，1→N 连续不跳层）

### 实例走查
<数值代入 / 代码走查 / 场景走查，至少一种>

### 验证实验                  # 工程型必填，≥3 步
1. <操作>：<看到什么说明什么>
2. …
3. …

### 排障判据                  # 工程型必填
| 症状 | 判据 | 修复 |
| :-- | :-- | :-- |

### 易错点
- <坑>：<为什么错>

### 自测题
- **Q1**：… → <答案要点>（答不出 → 回看 <小节>）

### 关联卡片
- 前置：`标题`（ID）
- 后续：`标题`（ID）
- 易混淆：`标题`（ID）
```

## 三种模板

| 模板 | 回答 | 必填小节 |
| :-- | :-- | :-- |
| **理论型** | 为什么 | 核心思想 / 主干线 / 阶梯式解剖（4~6 层，公式编号）/ 实例走查（数值代入）/ 易错点 / 自测题 |
| **工程型** | 怎么做 | 核心思想 / 主干线 / 阶梯式解剖 / 实例走查（代码）/ **验证实验（≥3 步）** / **排障判据** / 易错点 / 自测题 |
| **对比型** | 怎么选 | 核心思想 / 主干线 / **对比表**（列数 ≤4）/ **选型口诀** / **场景走查** / 易错点 / 自测题 |

- 三型**推荐**（非必填，但长卡/有前置卡时必填）：`重入点`、`前置检查`。
- **推断规则**（`card_create` 自动执行并回显，可用 `template` 参数覆盖）：
  标题含 对比/谱系/选型/取舍 → 对比型；领域落在 图形学 / Unity / Shader / 渲染 族，或标题含 接入/配置/参数/坑/实现/源码/变体 → 工程型；其余 → 理论型。
- 小节标题**允许括号后缀**（`### 阶梯式解剖（第 1 层 → 第 4 层）` 会被识别为 `阶梯式解剖`），但**规范写法不带后缀**——新卡按规范写。

## 可读性规范

| 手段 | 规范 |
| :-- | :-- |
| 顶部 30 秒区 | 一句话定义 + 心智模型 + 主干线一句话 + 重入点 |
| 小节首句给结论 | 先结论后论证，便于跳读 |
| 表格 | 只用于"≥2 个对象的对比"；列数 ≤4，列名短 |
| 代码 | 必须标语言（hlsl/cpp/csharp/python/plaintext）；单块 ≤60 行；块前一句"这段在做什么" |
| 公式 | 块级 LaTeX + 编号；首次出现的符号就地解释 |
| 折叠 | 只折叠"细节/扩展/历史"，**绝不折叠主线** |
| 术语 | 首现必须给一句定义（面向零记忆读者） |
| 视觉层级 | `###` 分节、`**粗体**` 标结论、`> ` 引用给定义；列表不嵌套超过 2 层 |
| 导航 | 长卡在顶部加锚点目录（可选） |

## 自测题与关联块格式

- 自测题用 `- **Q1**：问题 → 答案要点`，每题带 `→` 答案；答不出时给回看指针（`（答不出 → 回看 阶梯式解剖 第 2 层）`）。不用 `1./2.` 编号。
- 关联卡片统一 `- 前置/后续/易混淆：\`标题\`（ID）`；旧笔记用根限定路径代替 ID：`- 后续：\`旧笔记标题\`（工作目录/相对路径.md）`。
- `card_link` 会自动归一成上述格式，并按"**标题或 ID 任一命中即跳过**"去重——不会因为标题改过或漏写 ID 而出现重复行。

## 关联旧笔记（无 ID 的 .md）

检索命中里 `类型：旧笔记` 的目标没有卡片 ID，关联时用其**根限定路径**寻址：

- `card_link` 卡片↔旧笔记：默认只写卡片侧（旧笔记不碰不动），卡片侧写作
  `- 后续：\`旧笔记标题\`（工作目录/相对路径.md）`；
- 旧笔记↔旧笔记：默认拒绝，需 preset `linkIntoNotes: true`（写入旧笔记「### 关联卡片」小节）
  或改用 Obsidian 内链 `[[笔记名]]` 手动连接；Obsidian 会自动生成反向链接。
- 提到旧笔记时标注 `（详见旧笔记：<根>/<相对路径>）`，不要当作卡片引用（无 ID）。

## 卡片维护三件套

| 工具 | 用途 | 什么时候用 |
| :-- | :-- | :-- |
| `card_lint` | 质量体检（14 条规则：13 条警告级 + 1 条 info 级）：会话残留 / 定义长度 / 模板必填小节 / 主干线唯一 / 前置检查 / 重入点 / 验证实验 / 排障判据 / 代码块语言 / 自测题答案 / 层级序号 / 关联块格式 / 领域标签 / 外部资源 | 归档后自检；用户问"卡片质量"；批量 `scope="vault"`（`all` 含旧笔记，旧笔记仅体检通用规则） |
| `card_history` | 管理版本更新 / 勘误 / 历史折叠块：`list` 列出、`strip` 清除（先校验 `<details>` 配对） | 用户说"清掉历史版本 / 这张卡太长了" |
| `card_rename` | 改标题并同步 frontmatter + 文件名 + 全库入链 + 断链检测（`dryRun` 可预演） | 用户说"标题改成 X / 名字写错了" |

- **版本块位置**（2026-09 修复）：`card_update(append-version/errata)` 插在「关联卡片」**之前**，
  阅读顺序为「正文小节 → 版本更新 → 关联卡片」，不再落在文件末尾。
- **改名边界**：只支持有 ID 的卡片；文件名仅在"文件名 = 旧标题清洗结果"时同步改名；
  目标文件名/标题冲突时工具**不做任何写入**（先校验后提交）。
- **lint 的能力边界**：`card_lint` 只覆盖上表 14 条**可正则化/可结构判定**的规则。
  persona 与本文的其它人工约束（代码块 ≤60 行、表格列数 ≤4、块前一句"这段在做什么"、
  "小节之间用因果连接"、单次 ≤100 行代码）**没有自动校验**——写完自己过一遍。

## 完整样张（工程型）

````markdown
---
ID: 202609092139_92d2
标题: URP IBL 接入：环境侧喂数据与两行采样
领域: #图形学-Shader #IBL
来源: URP 14 文档
状态: 已确认
模板: 工程型
---

> IBL 接入 = 环境侧喂数据 + shader 两行采样。

### 重入点

- **30 秒**：间接光是"查表"不是"算"；漫反射查 9 个 SH 系数，镜面查一张 mip 立方图。
- **5 分钟**：读 主干线 + 阶梯式解剖 第 1~2 层（谁生产数据、谁消费数据）。
- **30 分钟**：全卡 + 跑一遍验证实验。

### 前置检查

- 需要知道：`间接光在实时渲染中的两个通道`（202609092139_2c27）、`球谐函数直觉`（202609092139_e1b3）
- 不需要知道：split-sum 推导、BRDF LUT 的预计算过程（本卡只用到"URP 用解析式替代"这一句结论）

### 核心思想

**一句话讲清**：环境侧喂数据、shader 两行采样；参数只调亮度与锐度。
**为什么**：`SampleSH` / `GlossyEnvironmentReflection` 只负责读表，表由编辑器烘焙；搞不清谁生产数据，就会"代码没错但反射是平的"。
**记忆锚点**：先问数据在哪，再问怎么采样。

### 主干线

间接光算不起 → 必须预计算成 SH 与立方图 → 于是环境侧要喂数据（Lighting 窗口 + 探针）→ shader 侧只做两次采样 → 代价是"烘死的、不随灯变" → 验证就看"关主光后暗部是否还亮"。

### 阶梯式解剖

**第 1 层 · 直觉**：反射是"照镜子"，环境光早就算好存在一张表里，shader 只是查表。

**第 2 层 · 机制**：

| 通道 | 数据源 | 采样 API |
| :-- | :-- | :-- |
| 间接漫反射 | 9 个 SH 系数 | `SampleSH(normalWS)` |
| 间接镜面 | mip 立方图 | `GlossyEnvironmentReflection` |

**第 3 层 · 细节与推导**：mip 由粗糙度换算（$mip = \log_2(\text{perceptualRoughness}\times6)$），配合 `surfaceReduction` 压制亮部。

**第 4 层 · 边界与反例**：数据是烘焙的——不随灯变；没有探针就走 `_ENVIRONMENTREFLECTIONS_OFF` 分支，反射是平色。

### 实例走查

$r=0.31$ → $mip\approx2.76$ → `surfaceReduction`≈0.912。

```hlsl
float3 indirect = SampleSH(normalWS) + GlossyEnvironmentReflection(reflectWS, roughness, ao);
```

### 验证实验

1. 主光 Intensity → 0：暗部仍被环境填亮 → SH 通道通。
2. Ambient Intensity → 0：整体塌黑 → 确认 SH 数据源。
3. 金属球 + Baked 探针：球面映出周围物体 → cubemap 通道通。
4. smoothness 0.1 → 1：反射由锐变糊 → mip 映射生效。

### 排障判据

| 症状 | 判据 | 修复 |
| :-- | :-- | :-- |
| 反射是平色 | 无探针 → 走 `_ENVIRONMENTREFLECTIONS_OFF` 分支 | 加 Baked 探针并烘焙 |
| 球面只有天空 | 物体没勾 `Reflection Probe Static` | 勾标记 + Generate Lighting |
| 改了主光没变化 | 间接光是烘死的 | 改天空盒/探针 |

### 易错点

- **只改主光却怪 IBL 没生效**：间接光来自烘焙数据，改灯不会影响它。
- **把 AO 乘到环境光上又乘一次**：AO 只作用于间接漫反射，重复相乘会压暗暗部。

### 自测题

- **Q1**：SH 数据由谁生产？ → 编辑器烘焙（答不出 → 回看 阶梯式解剖 第 1 层）。
- **Q2**：反射是平色最可能的原因？ → 没有反射探针（答不出 → 回看 排障判据）。

### 关联卡片

- 前置：`间接光在实时渲染中的两个通道`（202609092139_2c27）
- 后续：`URP Lit 与精简 PBR 的差距`（202609092139_7f31）
````

## 存量旧卡

已存在的自由格式卡片**不自动改写**：检索、读取、增量更新照常；下次 `card_update replace` 整卡时按本模板重写（旧内容进历史折叠块）。
存量卡常见的历史问题可用 `card_lint` 定位（会话残留、缺主干线/重入点/前置检查、代码块未标语言、层级序号缺失），按需修补，不必批量返工。
