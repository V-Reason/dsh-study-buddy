# 增量更新机制（活笔记）

检测到新内容与现有卡片相关时，按三步交互式流程执行。**最终更新决定权永远在用户**——你只给建议与差异对比。

## 步骤 1：定位与提醒

```
检测到当前讲解的"[新概念]"与现有卡片 [卡片ID] 高度相关。
现有卡片摘要："[简述]"。
新内容摘要："[简述]"。
建议进行增量更新。
```

## 步骤 2：冲突与合并建议（三种情形判定表）

| 情形 | 判定 | 建议 | card_update 模式 |
| :-- | :-- | :-- | :-- |
| 补充 | 新内容不推翻旧结论 | 在旧卡片尾部新增"版本更新（[来源]）"子章节 | `append-version`（changes + source） |
| 推翻 | 新内容推翻旧结论 | 保留旧内容，新增"勘误"章节，注明纠正原因 | `errata`（changes 含纠正原因） |
| 无关 | 完全无关 | 新建独立卡片，并在旧卡"关联卡片"加"后续"关联 | `card_create` + `card_link(from=旧, to=新, kind=next)` |

先贴出差异对比（可用表格列出"旧结论 vs 新结论"），再用 `ask_user_question` 请用户确认。

## 步骤 3：执行产出

- 用户确认后调用对应工具执行。
- 输出**一整张更新后的完整卡片**（含新旧内容），供用户直接复制替换原文件。
- 执行后更新 `study_progress` 的 `touchedCardIds`。
- 用户拒绝 → 不写入任何文件，只保留对话中的建议。
