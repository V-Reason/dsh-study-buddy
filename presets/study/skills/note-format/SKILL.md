# 文档式笔记规范（2026-10 重构）

**笔记就是文档块**：一个块 = 一个**可独立阅读的知识单元**，落成 vault 里一篇普通 `.md`（带 frontmatter 与 ID），与旧笔记同库同目录。

**写法没有模板**：结构、详略、文风、公式与图表偏好、领域侧重，全部由用户 vault 根的 **《笔记期望.md》** 决定。代码里没有内建模板，技能里也不定义小节清单——**你要做的是读期望并照着写**。

**三条硬门禁（工具会拒绝，别试探）**

1. **未读期望不写**：归档前必须 `note_expect_get`；用户中途改了期望 → 签名变化 → 必须重读。
2. **未确认规划不写**：先 `note_plan` 出提案（**只在对话里，不落盘**），用户拍板后才 `note_write`。
3. **越界路径不写**：落盘路径必须在规划根之下、标题在规划清单内、同一规划内一个标题只能写一次。

## 块的定义与拆分口径

- **一个块 = 一个能独立读懂的知识点/决策/结论**。判据不是字数，而是"单独拿出来读，读者是否需要先看别的块才懂"。
- **拒绝伪拆分**：不要把一个连贯推导机械切成多个文件；也不要让一个块塞进三个互不相关的主题。
- 篇幅由信息完备性决定：**尽细尽全，不设上下限**。简短不是美德，"简陋"是本轮重构要消灭的问题。
- 主题变大就拆块，并用 wikilink 互链（`note_link`）。
- 术语首现给一句定义（`> ` 引用块）；重要公式与定理保留推导步骤；抽象概念配简例；易混概念用表格。

## 归档流程（触发词：整理笔记 / 生成笔记 / 归档）

```
1. study_progress(get)                    未答追问未清 → 先提示，不进入归档
2. note_library(check)                    看库状态与期望是否已读
3. note_expect_get                        读《笔记期望.md》（门禁开门；改了就要重读）
4. note_list（可多次）                     勘探现有目录层级，判断哪些目录可复用
5. note_plan                              出提案（目录结构 + 块清单 + 顺序），呈现给用户
   └─ 用户改结构 → 直接再提案一次
   └─ 用户拍板   → 直接进入落盘（planId 已随提案返回）
6. note_write × N                         逐个落块（dryRun 可先看将写入什么）
7. note_link                              建块间或跨主题关联
8. note_toc                               为每个新增/变化的主题目录生成或刷新微目录
9. note_overview                          回报覆盖情况与缺口
10. study_progress(set) + study_memory(set lastSummary=…)
```

**只重组去重，不加新知识**：归档是把讲过的内容写成笔记，不是临时补充新内容。

## 目录层级与命名

- 层级：`资料 / 章 / 节 / 块`（课程笔记四层）。项目类笔记可以少一层（`主题 / 块`）。
- **章可以是目录，也可以是一个 `第N章 …` 文件**——按用户 vault 的既有习惯来，`note_list` 先看清楚。
- **文件名不加序号前缀**：阅读顺序由 frontmatter `顺序` 键与微目录承担。
- 每个主题目录都应有 `微目录.md`：`note_toc` 只重写 `<!-- note_toc:begin -->` 与 `<!-- note_toc:end -->` 之间的生成段，用户手写的导读原样保留。
- 改名用 `note_rename`（同步 frontmatter 标题 + 文件名 + 全库 wikilink + 断链检测）；不要手动搬文件，那会留下断链。

## 关联（wikilink）

- `note_link`：`kind=prev`（前置）/ `next`（后续）/ `sibling`（同主题兄弟），两侧都写，落盘为 Obsidian wikilink。
- 落盘形态：`### 关联` 小节里 `- 前置：[[目标标题]]`；已存在的关联不重复添加。
- 旧笔记（无 ID 的 `.md`）默认只写笔记侧；旧笔记 ↔ 旧笔记默认拒绝，改用 Obsidian `[[]]` 内链。
- 提到旧笔记时标 `（详见笔记：<根>/<相对路径>）`。

## 增量更新（正文不留历史块）

| 情形 | 动作 | 结果 |
| :-- | :-- | :-- |
| 补充，不推翻旧结论 | `note_update(append)`（可 `section` 指定小节） | 追加进正文，**不产生版本块** |
| 推翻 / 大改 | `note_update(replace)` | **旧正文先存入 `.study/archive/`**，正文只留新版 |
| 只改一句话定位 | `note_update(definition)` | 字段级微调，不算知识更新 |
| 挪目录 | `note_update(move)` | 迁到 targetPath（同改名要重跑 `note_toc`） |
| 回退 | `note_history(list/read)` → `note_restore` | 恢复前当前版本也会先存档，可来回 |

**决定权在用户**：先说清"旧 vs 新"，用户确认后再动手。

## 存量资产

- **存量卡**（有 ID、缺 `来源章节`）：可检索、可读取；补上 `来源章节` 即升级为块（`note_update(replace)` 时带上即可），会被 `note_overview` 计入覆盖度。
- **旧笔记**（无 ID）：默认只读，不自动改写。用户明确说"把这篇升级成笔记"时才 `note_update(replace)` 原地重写。
- 已存在的自由格式笔记**不批量返工**：`note_lint` 只报数据卫生问题（会话残留 / 未标语言的代码块 / 外部资源），不再有模板与分数。

## 覆盖度口径（note_overview）

- 按 `来源章节` 聚合成「资料 → 章 → 节」。语法：`《资料名》第N章 章标题 / N.N节`（无节号也合法；全角数字与多余空格会被归一）。
- **不虚构章节**：完整性只由笔记里真实出现过的章节号构成；缺口只给"未归类"与"节号跳号"提示。
- 解析不出 `来源章节` 的条目进"未归类"，补齐后即计入。

## 落盘位置

领域 → 目录映射（`presets/study/agent.cordis.yml` 的 `domainFolders`）在本轮之后**只是快捷方式**：正常路径下目录来自用户确认的文件夹规划（`note_plan` 的 `path`）；未给 path 时才回退到领域键，仍未映射则落 `未分类/<领域>/`。

## frontmatter 契约

```yaml
---
ID: 202610241230_ab12cd          # note_write 自动生成，手改会被视为新对象
标题: 高斯消元法
领域: #计算方法-线性方程组        # 首个标签 = 领域键（可选）
来源: 《计算方法》                # 资料名（必填）
状态: 已确认                      # 草稿 / 已确认 / 需更新
来源章节: 《计算方法》第2章 线性方程组数值解法 / 2.1节
顺序: 3                           # 同目录阅读顺序（微目录排序用）
简介: 用初等行变换把系数矩阵化为上三角，再回代求解。
---
```

只认这几个键；`简介` 无长度限制（可从正文首个引用块自动提取），`定义` 作为它的旧别名仍可读。
