## 2. 执行不顺利 / 设计不合理

### 2.1 card_moc 日期前缀双写（新增，P1）

- 现象：旧 MOC 文件名惯例为 `2026-08-27_图形学 MOC 目录（…）`，我据此把完整日期写进 title → card_moc 自动再加一次日期 → 文件名 `2026-09-02_2026-09-02_图形学 MOC 目录（…）.md`，需 pwsh Rename-Item 修正一次。
- 根因：工具侧自动加日期前缀的行为**没有任何描述**；唯一样例（docs 下已有 MOC）与工具实现混淆（样例本身可能是旧版手写）。
- 建议：card_moc 工具描述/文档显式写明"**title 只传主题名，日期前缀由工具自动生成**"，并给出正确调用示例。

### 2.2 定义 ≤30 字软提示 → replace 全量返工 + 历史折叠嵌套（复现升级，P1，**建议本次落地**）

- 现象：3 张卡（caab 33 字 / 6b89 43→36→29 字 / e2c6 32→29 字）触发软提示；修正手段 card_update(replace) 需**全量重传正文**（每卡 600+ 字），6b89 修了两次 → 生成两层嵌套 `<details>`，卡身膨胀且阅读负担重。上份报告 2.1 建议二选一（硬拒绝/放宽），**第三次复现仍未落地**。
- 新增观察：replace 模式没有"只改 definition"的轻量通道，修一个字段 ≈ 重写整卡。**修定义 ≠ 知识更新**，混用 replace 语义会让"历史版本"里塞满无意义的定义微调。
- 建议（合并上份）：① >30 字硬拒绝并回显改写建议，或放宽至 50~60 字+等级化；② card_update 增加字段级 patch（如 mode=definition/append-links），不改正文、不产生新折叠；③ 历史折叠只对知识性变更（append/errata/replace）生效。

### 2.3 进度信息多键复制 → 过期不一致（新增，P1）

- 现象：本会话把 study_progress、prefs.学习锚点、prefs.学习计划、lastSummary 四处全部更新为"GAMES101 全书闭环"，但 **prefs.用户画像与 prefs.知识存量里的进度句仍写"现学 GAMES101 L19 / L1-18 学完"**——开场 get 的记忆输出里同时存在"已完结"与"现学 L19"两种说法。本次未误用（靠语义判断），但属数据卫生隐患：**位置信息被复制进 5+ 个键，任何一次漏更都会产生矛盾**。
- 建议：进度单一来源（study_progress），prefs.* 只存偏好/惯例（当前 prefs.学习锚点、prefs.知识存量中的进度句迁移或标注"历史快照"）；memory get 输出对"疑似过期进度句"做一行提示。

### 2.4 card_id 与 card_create 的 ID 不互通（复现，P1 降级观察）

- 现象：上份报告记为"未触发"，本次触发：我先 card_id(5) 预取 ID（想确认日期/预留引用），card_create 随后生成**完全不同的 ID**（预取 9a03… 与实建 3a70/f54f… 无任何映射）→ 预取结果零用途，浪费一次调用。
- 判断：card_id 仅适合"想先看看 ID 长什么样"的轻量场景，**不能用于预留引用**；工具描述没有说明这一约束。
- 建议：工具描述注明"card_create 自动生成 ID，不消费 card_id 预取值；需要引用请以 create 返回为准"，或让 card_create 支持可选 ID 参数。

### 2.5 记忆中的领域键示例与真实键名不一致 → grep 配置绕路（部分复现，P2）

- 现象：上份报告记"domainFolders 键名绕路消失"，本次**部分复现**：prefs.图形学子目录只给了"图形学-后处理→后处理与图像"示例，而动画键真实写法是"**图形学-动画特效**"（无"与"）；记忆旧文与搜索结果中"图形学-动画与特效/动画-特效"写法混杂，我最终 grep agent.cordis.yml 才敢落盘。
- 建议：把**完整键名表**（含容易写错的三字差异：后处理/动画特效/光照模型…）内嵌进 card-format 技能，或干脆让 card_create 在键名近似匹配时回显"已映射到 X 目录"。

### 2.6 标题含 "/" → 文件名 sanitize 不透明（新增，P2）

- 现象：标题"PBD/Verlet 积分与约束投影的实现"落盘为"PBD Verlet 积分与约束投影的实现.md"（/ 被替换为空格），MOC 输出 `[[PBD Verlet…]]· PBD/Verlet…`，别名与标题不一致。按标题搜索文件会落空。
- 建议：card_create 检测标题中的非法字符（/ \ : * ? " < > |），警告并回显实际文件名，避免"标题↔文件名"对不上。

### 2.7 技能加载偏重（观察，P2）

- 现象：讲解"ODE 复习"前按系统提示加载了 study-loop + domain-adaptation；domain-adaptation 速查表**无数学/数值分析条目**（仅数据结构/OS/AI/引擎/美术/图形学），对本次纯数学复习零指导，白付上下文。
- 建议：① domain-adaptation 补"数学/数值"条目（或注明数学属"未覆盖→通用模式"无需加载）；② 系统提示的"task matches skill → 必加载"对边缘场景放权（纯复述/复习可不加载 domain-adaptation）。

### 2.8 小项（P3）

- fitz 每次运行打 deprecation warning（`import pymupdf` 建议）；模板改用 pymupdf 或抑制即可。
- 上份 2.2"edit 先读判定"本次未复现（未用 edit 触卡片文件，改用 card_update），但"建卡→微调"场景仍在（只是换成了更贵的 replace）——建议仍落地。

## 4. 开发者侧下一步建议（按优先级）

1. **（P1）定义长度终局**：>30 字硬拒绝+改写建议，或放宽 50~60 字+等级化；同时新增 **card_update 字段级 patch**（只改 definition/links，不重传正文、不生成折叠）。三次复现，本次成本最高，建议关闭此议题。
2. **（P1）日期源统一**：card_moc 与 card_create/card_id 取同一时间源；MOC 落盘前回显"文件名+标题+日期"；工具描述注明"title 只传主题，日期自动加"（双前缀直接根因）。
3. **（P1）进度单一来源**：位置只存 study_progress；清理 prefs.用户画像/prefs.知识存量中的旧进度句（迁移或标注快照）；get 输出对过期进度句加提示。
4. **（P1）card_id 用途文档化**：注明"预取 ID 不被 card_create 消费"；或 create 支持可选 ID。
5. **（P2）键名表内嵌 card-format**：全量精确写法（含"动画特效"无"与"），杜绝 grep 绕路。
6. **（P2）domain-adaptation 补数学/数值条目**；系统提示对边缘场景放权加载。
7. **（P2）标题非法字符检测**：sanitize 规则警告+回显实际文件名。
8. **（P3）模板 pymupdf 化**；消除 deprecation warning。
9. **（回归测试项）** incremental-update 的 append-version/errata 分支、card_update 知识更新语义——连续五次会话零实测；下次可刻意制造一次（如对 L21 卡挂一条"联网补充"走 append-version）。
