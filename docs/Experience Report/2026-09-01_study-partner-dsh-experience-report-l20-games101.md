## 2. 执行不顺利 / 返工记录

### 2.1 domainFolders 配置修改不热生效 → 8 张卡落"未分类"（返工，P0，**新增**）

- 现象：为新建「颜色与感知」子目录，向 `agent.cordis.yml` 的 domainFolders 追加 `图形学-颜色` 映射（该文件为 preset 级配置，位于 `.dsh/.agent-presets/study/`）；随后 card_create(domain=图形学-颜色) 的 8 张卡**全部落 `未分类/图形学-颜色/`**——插件仍按启动时加载的旧映射运行。补救：手动 Move-Item ×8 + 新建目标目录。
- 根因：
  1. **配置无热加载**：domainFolders 在插件进程启动时读取，会话中途修改不生效，且**无任何提示**（"配置已变更，需重启生效"）。
  2. **落"未分类"无告警**（首份报告 §2.2 已建议"未映射领域键时回传可用键列表"，本次验证：该建议**未实现**——但本次根因不是"键不存在"而是"键存在、映射过期"，即使有键列表提示也救不了）。
  3. 配置文件在**工作区外**（用户级 .dsh），修改需走沙箱提升；修复路径长。
- 建议：
  1. **domainFolders 支持热重载**（读取配置时校验 mtime，或提供 reload 通道）；无法热重载时，card_create 检测"配置 mtime 晚于插件启动时间/或映射与当前配置不一致"并回显警告。
  2. card_create 落 fallback（未分类）时返回：`领域键未映射，可用键：<列表>` + `当前配置路径：<路径>`（首份报告 P0 项仍未落实，优先级再上调）。
  3. 有映射但目录不存在时，**自动创建目标目录**（本次"颜色与感知"目录是手动建的；若插件自动建目录，2.1 的补救可少一步）。

### 2.2 card_id 预生成 ID 与 card_create 脱节（返工/困惑，P1，**新增**）

- 现象：归档前调用 `card_id(count=10)` 预取 10 个 ID（计划用于后续关联引用），实际 `card_create` **不接受外部 ID、自行生成**，且生成结果与预取 ID 完全不同 → 预取 ID 全部作废，关联阶段改用 create 返回的 ID。
- 根因：工具描述称"自动生成唯一 ID"，但未说明 `card_id` 的真实用途；流程上"先取 ID 再建卡"是自然动作，缺少文档拦截。
- 建议：
  1. `card_create` 增加可选 `id` 参数（支持"预分配 ID 建卡"）；或
  2. `card_id` 工具描述明确用途（如"仅用于预览/批量占位"），并把"最终 ID 以 card_create 返回为准"写进 card-format 技能；或
  3. 直接移除 `card_id` 工具（减少 API 面）。

### 2.3 文件名清洗：中文引号→空格（复现，P1）

- 现象：标题 `SPD 谱功率密度与"颜色是感知"` → 文件名 `SPD 谱功率密度与 颜色是感知.md`；`CMYK 减色空间与"为何还要黑版 K"` 同理。MOC wikilink 显示空格版文件名（有「· 真实标题」补偿行，但文件名本身仍与标题脱节）。**与首份报告 §2.3 完全同族**。
- 建议：slug 清洗规则显式化——去除 Windows 非法字符 `<>:"/\|?*` 与控制字符；全角/ASCII 引号替换为 `「」`（Windows 文件名允许全角引号）或直接删除且**不残留空格**；连续空格折叠为单个。首份报告建议"MOC 用标题展示"已部分实现（补偿行），文件名侧仍未修。

### 2.4 定义长度提示 10/10 命中（复现，P2）

- 现象：10 张卡全部触发"定义 X 字，超过 30 字建议精简"（本次实测 37–50 字）。纯噪音，无阻断。**首份报告 §2.5 已提，未修**。
- 建议（同首份）：阈值放宽至 ~45 字；或提示时附"30 字对齐示例"；或降级为 info。

### 2.5 personna/skill 规则自相矛盾："1~3 张卡" vs "尽可能全"（不一致，P2，**新增**）

- 现象：study-loop 技能与 persona 均写"归档出 1~3 张卡 card_create"，而 prefs.落卡口径（用户记忆键）要求"尽可能全、原子粒度优先，引子级也可成薄卡"。本次实际落 10 张（首轮 10 张）。执行时以用户 prefs 为准，但**按文档字面即违规**——外部审查者或新模型实例可能按"1~3 张"收缩，导致漏卡。
- 根因：规则文本过时（早期"1~3 张"先于用户偏好出现，未联动修订）。
- 建议：把归档规则统一为"**一张卡 = 一个原子知识点，数量不限；只重组去重、不加新知识**"；同步修改 persona 与 study-loop、card-format 三处文本，消除歧义。

### 2.6 建卡 links 参数与 card_link 双路径（观察，P3，同首份报告 §3.2）

- 现象：content 内写「关联卡片」小节 + links 参数预写 + 随后 card_link 双向写入——同一条关联两条维护路径。本次未出现重复条目，但职责边界仍模糊。
- 建议：明确 links 参数=建卡时单向预写，关联收口统一走 card_link；或在工具描述中注明"links 与 card_link 会自动去重"。
