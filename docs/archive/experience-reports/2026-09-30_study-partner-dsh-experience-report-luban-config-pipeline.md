## 2. 执行不顺利 / 设计不合理

### 2.1 【P0】没有"编码安全写入"通道，脚本类交付物两次写坏

- 现象：本次交付物包含 3 个 `.bat` 与 1 个 `.ps1`。其中：
  - 用 UTF-8 写中文 `.bat` → 用户双击后报一堆 `'M'/'nul'/'ho'/'o.' 不是内部或外部命令`（UTF-8 字节被 cmd 按 GBK 解码，**行结构被切碎**）；
  - 把脚本命名为 `tools\比较数据差异.ps1` → bat 里的中文字节被替换成 `?`，调用变成 `tools\??????.ps1`；
  - 把 `.bat` 内容"ASCII 化"时，连**文件名**一起写成了 `?`。
- 证据：用户原话"这个 bat 有问题"两次；报错里 `'鏄庤〃鏍煎彲鑳借繕寮€鐫€锛?'` 是 UTF-8→GBK 二次解码的典型痕迹。
- 根因：`write` 工具统一按 UTF-8 落盘，而 Windows 批处理与 cmd 的解析依赖系统 ANSI（中文系统 = 936）。**模型必须自己知道这条环境契约**，工具没有任何提示。
- 影响：3 次交付物返工、2 轮用户复测，且期间模型一度把责任误判为"路径写错"。
- 建议（三选一）：
  1. `write` 增加 `encoding` 入参（`utf8` / `utf8-bom` / `gbk` / `auto`），并在目标扩展名为 `.bat` / `.cmd` 时**默认告警或自动选 GBK**。
  2. 增加"编码预检"：写入时扫描内容里是否存在非 ASCII 且扩展名属于批处理/脚本类，返回一条提醒（"Windows 批处理按 ANSI 解析，建议 GBK 或纯 ASCII"）。
  3. 最低成本：在 skill 或工具描述里写明这条环境契约 + 两条对策（`.bat` 用 GBK；**文件名一律 ASCII**，中文只放注释/文档）。

### 2.2 【P0】`note_lint`「会话残留（本机路径）」误报率高到失去信号（上次 P1，本次升级为 P0）

- 现象：单篇 15 条告警，全部指向**工程相对路径与文件名词**：`Gen\Tables.cs`、`Gen\demo\TbWeapon.cs`、`## 二、Weapon.cs：一行数据`、`Runtime\BeanBase.cs`。全库有大量笔记命中该规则。
- 影响：这些路径是技术内容的必要组成部分（写笔记就是为了记"哪个文件负责什么"）。高误报直接后果是**用户与模型都学会忽略 lint**——本次即按"这类不用改"处理，真正的 4 处残留（第二人称"你的表"、时间词"本次"）混在同一条规则里，需要人工逐条分辨。
- 根因：规则把"含 `\` 或文件扩展名的文本"当作路径，未区分**本机绝对路径**与**工程内相对路径/文件名**。
- 建议：
  1. 规则精确化：只匹配 `^[A-Za-z]:[\\/]`、`\\\\`（UNC）、`/Users/`、`file:///`、以及**出现盘符且层级 ≥3**的串；`Gen\Tables.cs` 这类相对路径放行。
  2. 拆分规则：把"本机绝对路径"与"第二人称/会话时间词"拆成两条独立规则——它们的可信度完全不同，混在一条里会互相拖累。
  3. 单篇报告里按规则分组，并标注"该规则历史误报率"，让调用方知道哪些可以忽略。

### 2.3 【P0】`note_lint`「代码块语言」不给行号，且修补无通道

- 现象：8 篇里 6 篇命中"代码块未标语言（第 1、2、4、5、6、7、8 块，共 9 块）"。**没有行号，也没有围栏序号**——"第 7 块"到底指第几个围栏，无法直接定位。
- 实际处理：只能自写 pwsh 扫描器统计"孤立的 ``` 行号"，才定位到 18 处未标围栏。
- 叠加问题：定位之后**没有插件内修补通道**（`note_update` 是整篇替换，`edit` 直改 vault 文件会触发 fs-observation 策略，记忆里记的推荐路径正是"绕出插件用 pwsh"）——一次小修又要付出外部脚本 + 全文重传的代价。
- 建议：
  1. lint 报告里给**行号**（`L55, L73, L158` 这样可直接跳转的形式），而非"第 N 块"。
  2. 或新增 `note_fix`（或 `note_update` 的 `patch` 模式）：按行号/锚点做小范围替换，覆盖"补语言标注、修断链、改一句话"三类高频小修。
  3. 参考：本次 18 处修补全部通过 pwsh 完成，说明调用方有真实且高频的需求。

### 2.4 【P0】脚本类交付物缺"模型侧自检"通道，验收只能靠用户手工跑

- 现象：本次交付 2 个 bat（校验用 / 导出用）。模型在终端"代跑"了 5 个场景、结论是通过，但用户实际双击后又暴露了编码与调用上下文问题（用户两次反馈"有问题"）；反过来，模型也**无法可靠自跑**——批处理里的 `pause` 会让代跑挂住，`Start-Process` + 重定向捕获又会二次损坏中文输出（`[失锟斤拷]`），一度让模型追了一个不存在的 bug。
- 证据：整场会话里"验证"占了约 1/4 轮次；真正定位靠的是用户原话 + 用户自己的终端输出。
- 根因：这是"环境相关产物"的固有属性（编码、控制台代码页、工作目录、文件锁），模型在非交互环境下拿不到用户双击时的真实上下文。
- 建议：
  1. 给"包脚本/工具"类会话一个**固定验收清单模板**：正常运行 / 拦错路径 / 成功路径 / 失败路径 / 边界（文件被占用），每条给"预期输出 + 看哪个文件的时间戳"，让用户一次跑完回报。
  2. 在预设或 skill 里写明：**执行类成品一律由用户实操验收，模型代跑只作冒烟测试**（本次已写入 `prefs.分步契约`）。
  3. 提供"无 pause 冒烟运行"的约定（如 bat 支持 `--smoke` 跳过 pause），降低模型自检成本。

### 2.5 【P1】vault 内小修仍缺少插件内通道（上次 P0 的变体，本次以别的方式踩到）

- 现象：本次 4 处会话残留 + 18 处语言标注 + 1 处断链，全部用 `pwsh` 直改文件完成。过程中还**反复触发 fs-observation 策略**：`note_write` 刚返回全文也不算"读过"，`edit` 报 `file has not been read`；一次 `edit` 因换行/空格不匹配静默失败，只能改走 pwsh 字符串替换。
- 影响：小修的成本被放大成一个完整的外部脚本调用；且直改文件绕过了工具的一致性保障（frontmatter、存档、关联都不参与）。
- 建议：
  1. 把 `note_update` 的 `append` 泛化为"**按锚点替换**"（`anchor` + `newText`），一次调用完成小修，同时保留存档与元数据。
  2. 或提供 `note_raw_patch`（vault 内文本的定向替换），把 2.3 的修补需求一并收回插件体系。
  3. 在工具描述中显式声明"`note_write` 之后同轮 `edit` 会被拒绝，请用 `note_update`"，减少一次无效调用。

### 2.6 【P1】正文手写 wikilink 无人校验，断链只能靠自发比对

- 现象：归档时块 5 引用了块 4，写的是规划期的旧标题（`Tables / TbXxx / Bean 三层`），而块 4 实际标题是 `Tables 与 TbXxx 与 Bean 三层`——**断链**。它是模型自己写 pwsh 比对全目录链接时才发现的。
- 处理时又碰到一处不对称：`note_unlink` 对这条"只存在于正文、非工具写入"的链接返回"无改动"（它只处理 `### 关联` 小节里工具建的关联），最终仍靠 pwsh 改文本。
- 影响：断链是归档类会话的高频故障，且**静默**（Obsidian 里显示为未解析链接，工具侧无任何提示）。
- 建议：
  1. `note_write` / `note_update` 落盘后增加**轻量链接校验**：正文里出现的 `[[目标]]` 若在当前 vault 内不存在同名笔记，返回一条提示（不阻断写入）。
  2. `note_lint` 增一条独立规则"断链检测"（本次 lint 报告里没有这一项）。
  3. `note_unlink` 的语义说明里补一句"只处理关联小节的入链；正文手写链接不在管辖内"，避免调用方误解。

### 2.7 【P1】`note_lint` 的报告粒度与"给 AI 消费"不匹配

- 现象：整库报告只给"命中 N 条 + 每篇条数排行"，单篇报告里路径类问题**逐行罗列**（同一规则刷 15 行），而语言类问题**一行汇总**（无行号）。两类问题的信息量正好与需求相反。
- 影响：模型要花额外轮次把汇总型问题展开成行号（见 2.3），又要花精力把刷屏型问题合并理解。
- 建议：
  1. 同类问题合并展示（`会话残留 ×15：涉及 Gen\… 等相对路径（疑似误报）`），附"是否建议忽略"的判断提示。
  2. 需要细粒度的问题（围栏语言、断链）给行号或可跳转锚点。
  3. 报告尾部给一句"本次建议动作清单"（改哪几条、忽略哪几条），把判定成本降到最低。

### 2.8 【P2】`note_search` 的计数与范围口径容易误读

- 现象：在 `游戏开发/Luban配表` 目录内检索 "Luban" 返回目录内命中数，同时附带全库总量（来源：vault / 工作目录），实际范围是该目录内的笔记与 `微目录.md`。此外 `微目录.md` 被列为"类型：旧笔记"。
- 影响：判断"是否重复主题"时，计数口径不清会让人把全库总量误认为检索范围。
- 建议：检索结果里给出"本次命中 N 篇 / 其中块 x、存量卡 y、旧笔记 z"，`微目录.md` 单独归类为"导航文件"而非"旧笔记"。

### 2.9 【P2】`note_update(replace)` 的 `newContent` 是必填但描述不显式

- 现象：想用 `dryRun` 预演一次替换，未传 `newContent` 直接报 `replace 需要 newContent`。而 `dryRun` 的语义本应是"先看会发生什么"，缺参时可以先回显"将要替换的现有正文"。
- 建议：`dryRun` 模式下允许省略 `newContent`（只回显现状与将被存档的信息）；或在工具描述里写明"`dryRun` 仍需 `newContent`"。

### 2.10 【P2】跨工具 `ref` 解析口径不一致

- 现象：用路径调 `note_lint(ref="游戏开发/Luban配表/从 Excel 到 Unity：最小链路与工程搭建")` 返回 `找不到卡片`，改传 ID（`202609300045_a5c77e`）才生效。同一路径在 `note_write` 的返回里是正常回显的。
- 影响：一次无效调用；且"标题/路径/ID 三者哪个能用"在不同 note 工具间不一致，需要试错。
- 建议：统一为一个"先 ID → 再标题 → 再路径 → 再文件名"的解析链，并在失败信息里列出**近似命中**（本次目录下只有 8 篇，近似命中可直接给出）。

### 2.11 【环境类，P1】PowerShell 输出捕获会二次损坏中文，是本场最大的"假 bug"来源

- 现象：用 `Start-Process -RedirectStandardOutput` 捕获 cmd 的输出，中文变 `[失锟斤拷]`、`锟斤拷锟斤拷未通`。模型据此追了两轮，最后确认**bat 的中文输出实际是正确的，损坏发生在我自己的捕获层**（GBK 字节按 UTF-8 解码）。
- 影响：不仅浪费轮次，还得出过错误结论（一度判断"echo 中文不可靠"），并因此把 bat 的提示文案整体改成 ASCII。
- 建议（面向 harness 使用习惯，非插件）：
  1. 捕获 Windows 子进程输出时固定配套 `chcp` 与解码设置，或在文档里写明"捕获层会二次解码，中文输出不要作为判据"。
  2. 判据改用**不依赖中文的内容**（退出码、文件时间戳、ASCII 标记 `[OK]`/`[FAIL]`）——本次最终正是靠"json 文件时间戳变了"确认拷贝成功。

### 2.12 【P2】规划期标题与实际标题不一致时会静默留下断链（流程类）

- 现象：`note_plan` 提案里的标题是 `生成代码的运行结构：Tables / TbXxx / Bean 三层`，落盘时因为"标题不能含 `/`"改成了 `…：Tables 与 TbXxx 与 Bean 三层`；但**归档过程中引用的仍是规划期标题**（见 2.6）。
- 建议：`note_plan(confirm)` 的返回里回显"最终标题清单"，或 `note_write` 在"标题与规划项不完全一致但合法化后等价"时提示一次。

## 5. 附：本场会话的"环境契约"小结（建议收进预设或 Skill）

这几条不是插件的 bug，而是**Windows + 中文环境下的固定契约**，本次全部踩到，建议直接写进预设，避免下次重复试错：

| 契约 | 对策 |
| :-- | :-- |
| Windows 批处理按系统 ANSI 解析，UTF-8 中文 bat 会被切碎 | `.bat` 存 GBK，或内容全 ASCII（中文提示挪进 Markdown） |
| 脚本文件名不能含中文（会被替换成 `?`） | 文件名一律 ASCII，中文只放注释与文档 |
| `%date%` / `%time%` 随区域变化且含冒号 | 时间戳用 `powershell -NoProfile -Command "Get-Date -Format yyyyMMdd_HHmmss"` |
| `set RC=%ERRORLEVEL%` 必须紧跟被捕获的命令 | 中间插一句 `echo`/`type` 就会拿到错的值 |
| Excel 打开 xlsx 时持有独占锁，连读都不允许 | 保存 → 关表 → 再导表；`~$` 文件存在≠一定开着，也不应被脚本自动删除 |
| 重定向捕获 Windows 子进程输出会二次解码中文 | 验收判据用退出码 / 文件时间戳 / ASCII 标记，不用中文输出 |
| `cd /d "%~dp0"` 缺一行，双击运行时相对路径全错 | 批处理开头固定加这一句 |
