## 1. 这是什么

`dsh-study-buddy` 是给 DeepSeek Harness（DSH）的**「通用学习 Agent」模式**，由两部分组成：

| 组成 | 是什么 | 装在哪 |
| :-- | :-- | :-- |
| 插件 | 注册 12 个 `card_*` / `study_*` 工具，用 `node:fs` 直写用户 Obsidian vault | DSH profile 的 `node_modules` |
| 预设 | 「学习伙伴」Agent：persona + 6 个技能 + 插件挂载行 | `%DSH_HOME%\.agent-presets\study\` |

一句话定位：**快节奏、听指挥、把知识沉淀成可独立复读的卡片，直接写进你的 Obsidian vault**。

三条不变量（任何改动都不得破坏）：

1. **磁盘是唯一真相**——卡片就是普通 `.md`，用户在 Obsidian 里手改、git 回滚永远有效；插件按 mtime/ctime/size 签名重扫索引，不与用户编辑打架。
2. **决定权在用户**——讲不讲、讲多深、写不写卡、改不改旧卡，都由用户下命令；Agent 只给建议与对比。
3. **fail-loud**——配置错误、JSON 损坏、注册失败一律抛错，不静默降级（曾因静默失败让"工具全无"潜伏数天）。

## 2. 设计转向：从「原子知识块」到「可复读的微课程」

### 2.1 为什么要转

旧定位：卡片 = 一个原子知识点，用于检索与复习。
问题：半年后忘光了再看，卡里全是结论，没有"为什么需要它""从哪开始读"，读不动。

新定位：卡片 = **一份可以独立读完的微课程**，假设读者已经忘光 80%。
判据从"写全了没有"改成"**忘光了的人能不能在 30 分钟内重建它**"。

### 2.2 三类读者与三种读法（决定卡的物理结构）

| 读者状态 | 想干什么 | 卡内应提供 |
| :-- | :-- | :-- |
| 完全遗忘（小白） | 从头学一遍 | 前置检查 → 主干线 → 分层解剖 → 数值/代码走查 |
| 半遗忘（记得名字） | 快速捡起 | 30 秒区：一句话定义 + 心智模型 + 主干线一句话 |
| 未遗忘（在干活） | 查一个细节 | 表格 / 代码片段 / 排障判据（能跳读定位） |

于是卡的物理结构固定为：**顶部 30 秒区 → 中部主干线与分层 → 底部查表区**，三种读法互不干扰。

### 2.3 取消字数限制与替代约束

正文字数**不设上下限**——长度由信息完备性决定，字数不是质量信号。
唯一保留的长度硬限是**一句话定义 ≤60 字**（它是检索契约与 TL;DR，不是知识载体）。

替代约束（防止"取消字数"变成"无限膨胀"）：

- **单一主题**：一张卡只回答一个问题；主题变大就拆卡并互链。
- **信息增益**：每个小节必须提供新信息。
- **完备性三问**：小白读完能复述主线吗？关键结论有推导或出处吗？有可执行的验证或反例吗？

### 2.4 反堆砌三规则（设计核心）

| 规则 | 内容 | 落地方式 |
| :-- | :-- | :-- |
| **主干线唯一** | 每张卡用一句话写"问题 → 关键约束 → 解法 → 代价 → 验证"，所有内容挂在这条线上 | `### 主干线` 小节 + lint `mainline` 规则（缺失或多条都报） |
| **删除测试** | 逐节问"删掉这一节读者会迷路吗"：不会 → 移入 `<details>` 或删 | 写入 persona 与 card-format 技能（人工判据，不设规则） |
| **前置检查** | 卡顶列 ≤2 条直接前置（带卡片 ID）与"不需要知道" | `### 前置检查` 小节 + lint `prereq-check`（有前置关联却缺该节即报） |

## 3. 卡片模型：三型模板

一套模板硬套两类卡，必然一边臃肿一边空洞（15 张样本实证）。因此模板分型：

| 模板 | 回答 | 必填小节 | 自动推断触发 |
| :-- | :-- | :-- | :-- |
| **理论型** | 为什么 | 核心思想 / 主干线 / 阶梯式解剖（4~6 层）/ 实例走查 / 易错点 / 自测题 | 默认 |
| **工程型** | 怎么做 | 上述 + 验证实验（≥3 步）+ 排障判据（症状\|判据\|修复） | 领域落在 图形学/Unity/Shader/渲染 族，或标题含 接入/配置/参数/坑/实现/源码/变体 |
| **对比型** | 怎么选 | 核心思想 / 主干线 / 对比表（列 ≤4）/ 选型口诀 / 场景走查 / 易错点 / 自测题 | 标题含 对比/谱系/选型/取舍/差异/之争 |

- 三型**推荐**（非必填，但长卡 >3000 字或有前置卡时必填）：`重入点`、`前置检查`。
- 推断结果写入 frontmatter `模板`（可选字段，旧卡无此键不影响），并在 `card_create` 返回里回显；显式传 `template` 优先。
- **小节标题匹配口径**（兼容存量卡格式漂移）：精确相等，**或**以规范标题开头且紧跟括号/冒号/破折号。
  例：`### 阶梯式解剖（第 1 层 → 第 4 层）`、`### 核心思想（直击）` 都识别为对应小节，不会被误判缺节。

### 3.1 通用骨架

```markdown
> 一句话定义（≤30 字最佳，≤60 字硬限）

### 重入点      # 长卡必填：30 秒 / 5 分钟 / 30 分钟三种读法
### 前置检查    # 有前置卡必填：需要知道（≤2 条 + ID）+ 不需要知道
### 核心思想    一句话讲清 / 为什么 / 记忆锚点
### 主干线      问题 → 关键约束 → 解法 → 代价 → 验证方式
### 阶梯式解剖  第 1 层直觉 → 第 2 层机制 → 第 3 层细节推导 → 第 4 层边界（4~6 层带序号）
### 实例走查    数值代入 / 代码走查 / 场景走查（≥1）
### 验证实验    # 工程型必填：≥3 步，每步"看到什么说明什么"
### 排障判据    # 工程型必填：表格
### 易错点      坑：为什么错
### 自测题      **Q1**：问题 → 答案要点（答不出 → 回看 X）
### 关联卡片    - 前置：`标题`（ID）
```

## 4. 架构

### 4.1 分层与数据流

```
Obsidian vault（磁盘 = 唯一真相）
        │  node:fs 扫描（vault + searchRoots + 会话工作目录）
        ▼
   vault.ts  ──►  search.ts        索引与加权召回（mtime/ctime/size 签名缓存）
        │             │
        │             ▼
        │        IndexedCard ──► frontmatter.ts（五键 + 模板）
        │             │
        ▼             ▼
   cardmodel.ts（段落模型：小节序列）──┬──► template.ts（三型注册表 + 推断 + 校验）
                                      ├──► lintrules.ts + lint.ts（规则判定 + 打分）
                                      ├──► history.ts（版本块/历史折叠）
                                      ├──► rename.ts（改名与入链重写）
                                      └──► insight.ts（跨卡一致性/趋势/可执行性）
                                      │
                                      ▼
                         index.ts（VaultStore 业务 + apply）──► tools.ts（12 个工具）
```

### 4.2 模块边界

| 模块 | 职责 | 依赖 |
| :-- | :-- | :-- |
| `vault.ts` | 扫描/跳过清单/路径安全/原子写/落盘目录解析 | node:fs |
| `search.ts` | CJK 双字组 + 英文分词、字段加权、多根索引 | frontmatter, vault |
| `frontmatter.ts` | 极简 YAML 五键 + 可选 `模板`、定义提取 | — |
| `card.ts` | ID/校验/渲染/增量更新/关联/MOC 组装 | frontmatter, history, template |
| `cardmodel.ts` | 段落模型（切分/渲染/标题匹配/块插入/块抹除） | — |
| `template.ts` | 三型模板注册表、推断、齐备度校验 | cardmodel |
| `lintrules.ts` | 规则判定（纯函数，接收已切好的小节）+ 共享正则常量 | cardmodel |
| `lint.ts` | `RULES` 规则注册表、打分、单卡报告、批量汇总 | lintrules, template, cardmodel |
| `history.ts` | 版本更新/勘误/`<details>`：定位、插入、list、strip、配对校验 | cardmodel |
| `rename.ts` | 标题替换、关联行重写、wikilink 重写、断链检测、文件名计划 | frontmatter, cardmodel, vault |
| `insight.ts` | 跨卡一致性、质量趋势、可执行性评级 | cardmodel, lint |
| `state.ts` / `memory.ts` | `.study/progress.json` / `.study/memory.json` | vault |
| `opener.ts` | 开场门禁（系统提示段 + 预步提醒，双形状特性探测） | — |
| `tools.ts` | 12 个工具定义（schema 即文档；描述由规则表/模板表生成） | card, lint, template, history |
| `index.ts` | `VaultStore`（业务编排）+ `apply`（注册与生命周期） | 全部 |

**设计约束**：除 `vault/state/memory` 外，所有模块都是**纯文本变换、零 IO、零宿主依赖**，因此可独立单测；
`@deepseek-ai/*` 保持构建 external，宿主侧零运行时导入（平台重构不会让插件挂载失败）。

### 4.3 一次工具调用的生命周期

```
工具 execute(args, exec)
  → VaultStore.<method>()
      → assertVault()（fail-loud：vault 不可读立即报错）
      → ensureIndex(sessionCwd)（TTL 内且 cwd 未变则复用缓存索引；否则按签名重建）
      → 业务：解析 ref → 纯函数变换 → 写前校验（assertWritable / 冲突）→ atomicWrite（临时文件 + rename）
      → invalidate()（写后失效缓存，下次重扫）
  → 返回文本（含"已写入/已更新/已清除"等回显行；有跳过文件时追加 ⚠ 行）
```

## 5. 关键设计决策（含取舍）

| # | 决策 | 取舍与理由 |
| :-- | :-- | :-- |
| D1 | 卡片即普通 `.md`，不建独立数据库 | 与旧笔记同库同目录，Obsidian/git 直接可用；代价是索引要按签名重扫（mtime+ctime+size 互补，覆盖"同毫秒同大小"场景） |
| D2 | 模板注册表 + 段落模型，而非字符串拼装 | 加规则只改一处；代价是多一层抽象，用"阶段 0 行为零变化"的回归保证其安全 |
| D3 | lint 以警告级为主，不阻塞落盘 | 避免"为过检而写"删掉有价值内容；只有定义 >60 字保持硬拒绝（检索契约）。`external-resource` 是唯一的 info 级（权重 0），只提示不扣分 |
| D4 | 规则精度优先于召回 | 规则由**真实 vault 只读抽样**校准（223 张卡），白名单先于正则；宁可漏报，不可误伤——误伤会让用户不再信任工具 |
| D5 | 版本块插在「关联卡片」之前 | 修复"知识 → 关联 → 新知识"的错误阅读顺序；实现上按小节定位而非文件末尾追加 |
| D6 | 关联行归一 `` - 标签：`标题`（ID） `` + 标题/ID 双向去重，**判重范围限「关联卡片」小节** | 同时覆盖"标题改了 ID 未变"与"标题相同漏写 ID"；全正文判重会把「前置检查」里的 `- 前置：甲` 误当已关联，静默跳过真实关联 |
| D7 | 改名只写 vault 内文件 | `searchRoots`/工作目录是用户旧笔记库（只读，除非 `linkIntoNotes: true`）；命中时在报告里标注"只读根未写入"，不静默跳过 |
| D8 | 改名同步文件名**仅当**文件名 = 旧标题清洗结果 | 避免"改标题顺带搬文件"的意外；历史遗留命名保留原名并说明 |
| D9 | 断链检测排除"新标题包含旧标题" | `A → A 与探针` 场景下 `includes` 恒真，必须先排除新值 |
| D10 | P2 分析（跨卡/趋势/评级）挂在 `card_lint` 同工具 | 不新增工具、不增加固定 schema 开销；三个开关默认关闭 |
| D11 | 不新增技能目录（保持 6 个技能） | 避免部署副本与 `skills.spec.ts` 结构性返工；模板规范并入 `card-format` |
| D12 | 存量卡不强迁 | 提案明确"下次整卡替换时按新模板重写"；本次未写入真实 vault |
| D13 | **数据安全优先于功能收敛** | 审查发现的两个 blocker（`strip` 删错内容、`rename` 半写盘）是新引入的数据破坏面，必须先修；修复顺序固定为「先只读复现 → 补回归用例 → 再改实现」 |
| D14 | **规则收敛为单一注册表 + 规格驱动，拒绝双口径** | `RULES` 是 id/权重/级别的唯一来源；小节存在性由 `templateSpec` 推导（`mainline` 字段首次生效）。重复规则合并删除（`walkthrough`），而不是让两套口径长期并存 |
| D15 | **不删已发布功能，改校准** | 100 分制与 `cross/trend/rating` 已进文档与 persona；本轮只修其校准（分档权重、去重复扣分、旧笔记不套模板），把"删功能"留到有使用数据之后再决定 |
| D16 | **写操作先校验后提交，失败可回滚** | `rename` 拆成"规划（全部冲突校验）+ 提交（写前缓存 + 逆序回滚）"；任何写路径先过 `assertWritable`。宁可报错不写，也不留半改名状态 |
| D17 | **渲染层转义是纵深防御，不替代校验** | 含换行的字段在入口被拒（fail-loud），渲染层再用 `inlineText` 兜底；两者都保留，因为漏一个就是静默的元数据丢失 |
| D18 | **报告必须与"实际处理了什么"一致** | 跳过项按**原因**分组回显（`⚠ 跳过 N 项未完整处理：目录深度超过 16 层（…）`），不静默吞掉、也不把原因一律写成"读取失败"——"共检索 223 篇"必须是真的 223 篇 |
| D19 | **缓存不能牺牲可见性** | TTL 只作用于**命中路径**；`search` 未命中、`resolveCard` 找不到卡片时强制重扫一次（`{ force: true }`）。用户"在 Obsidian 里刚写完就让 Agent 读"是核心用法，缓存窗口不能变成"搜不到" |
| D20 | **写路径不许为了提示付全库代价** | 建卡是最热写路径：同名提示改由 `titleHints`（索引重建时填充、写入后增量维护）提供 O(1) 查询，`create` 不再触发全库扫描。代价是进程内首次调用（从未建立索引）时提示缺席——提示不是门禁，可接受 |
| D21 | **安全阀拦异常根，不拒绝正常的大库** | 文件数超限从"抛错让六个工具全不可用"改为**截断 + 显式警告**，并暴露 `config.maxWalkFiles` 让用户自救；深度超限同样只跳过该子树并上报原因 |

## 7. 验收与质量门

| 门 | 标准 |
| :-- | :-- |
| 构建 | `pnpm run check` = typecheck + vitest + esbuild 全绿 |
| 工具面 | 12 个工具，名字集合由 `tests/tools.spec.ts` 钉住 |
| 规则精度 | 白名单反例单测（`L0/L1/L2`、`LOD`、`GAMES101 L15`、代码块与 `<details>` 内）必须绿 |
| 数据安全 | 每个 blocker 有**先红后绿**的回归用例（`strip` 行号漂移、`rename` 半写盘、字段注入） |
| 修复副作用 | 复审 N1~N4 各有一条回归用例：只读根 `card_link` 不半写盘、`card_create` 不触发索引重建、TTL 窗口内外建卡立即可见、`addLink` 无尾换行不粘行 |
| 一致性 | 文档/配置/技能三处口径由测试钉住（领域键表、规则描述、persona 无重复段落） |
| 兼容 | 存量卡括号后缀变体不被判缺节（单测钉住） |
| 产物 | `lib/index.js` 无 `@deepseek-ai` 运行时导入；冒烟加载输出 12 个工具 |
| 用户数据 | 涉及用户 vault 的操作：只写可写根、原子写、`dryRun` 可预演、失败不写半个文件、跳过文件必须回显 |

**遗忘测试**（人工，每轮迭代做一次）：随机抽 5 张卡只给标题，限时 5 分钟口述"在解决什么问题、主线是什么、关键结论、怎么验证"，按覆盖度/因果连贯/可操作各 0~5 分，目标均值 ≥10/15。

## 8. 边界与已知限制

- 检索是**关键词召回**（CJK 双字组 + 英文单词），无语义向量；近义改写可能漏检。
- 每个 `apply` 实例一个索引缓存，不跨挂载共享；索引 TTL 默认 2s（`indexTtlMs`），但**未命中/找不到卡片时强制重扫一次**，因此"刚写完立刻读"依然即时可见。
- 索引常驻全库正文（1000 卡 × 4KB ≈ 4MB）；10 万卡级需要改懒加载，当前规模不需要。
- 旧二进制 Office 格式（`.ppt/.doc/.xls`）不直接读。
- 跨卡一致性只报"同键多值"，不做语义判断（取值是否正确由人判断）。
- 可执行性评级只用于报告，尚未回写 MOC。
- `card_lint` 只覆盖 14 条可判定规则；persona 的"代码块 ≤60 行""表格列数 ≤4""小节间因果连接"等人工约束没有自动校验（见 `card-format` 技能「lint 的能力边界」）。
- 记忆/进度中的文本会随开场门禁进入上下文，插件只给"指令性语句"软提示，不做内容净化。
