### 2.1 `cardmodel.ts` — 段落模型（地基）

```ts
interface CardSection { level: number; title: string; body: string; start: number; end: number }

splitSections(body: string): { lead: string; sections: CardSection[] }   // matchAll，无共享正则状态
renderSections(lead: string, sections: CardSection[]): string
matchesTitle(heading: string, title: string): boolean      // 精确相等 或 规范标题 + 括号/冒号/破折号
findSection(sections, title) / hasSection(sections, title)
insertBlockBefore(body, block, beforeTitle = '关联卡片'): string      // 找不到则追加到末尾
inlineText(value): string                 // 换行折成空格 + 压缩空白（SEC-1 渲染兜底）
makeLineOf(text): (index) => number       // 下标 → 行号（1 基），二分查找（PERF-4）
codeFenceLanguages(body): string[]        // 逐行状态机，返回每个代码块的语言标注（'' = 未标）
layerNumbers(body): number[]              // `第 N 层` 去重升序
countListItems(body): number              // `1.` / `1)` / `- ` / `* ` / `+ `
blankOutBlocks(body): string              // 代码块与 <details> 内容替换为空行（保留行号）
```

> 关键实现细节：`codeFenceLanguages` 用 `inFence` 状态机逐行扫描，**不能用正则全局匹配**——否则闭栅栏会被当成开栅栏（见 `docs/经验文档.md` 坑 1）。
> `inlineText` 是**纵深防御**，不替代校验：`validateCard`/`validateDefinition` 会直接拒绝含换行的标题/定义。

### 2.2 `template.ts` — 模板注册表

```ts
type TemplateType = '理论型' | '工程型' | '对比型'
interface SectionSpec { title: string; hint: string; mainline?: boolean }
interface TemplateSpec { type: TemplateType; answers: string; required: SectionSpec[]; optional: SectionSpec[] }
interface TemplateHints { engineeringDomains?: string[]; engineeringTitles?: string[]; comparisonTitles?: string[] }

templateSpec(type?: string): TemplateSpec      // 未知类型回退「理论型」
allTemplates(): TemplateSpec[] / isTemplateType(v): boolean
inferTemplate({ title, domain, mappedFolder?, hints? }): TemplateType
checkTemplate(type, body): { type, present: string[], missing: SectionSpec[], missingOptional: SectionSpec[] }
sectionHints(specs) / templateTable(): string[]   // 工具描述由它们生成（EXT-1/EXT-2）
```

具名小节常量（lint 读标题，不再手抄字面量）：`VERIFY_EXPERIMENT_SECTION` / `TROUBLESHOOT_SECTION` /
`COMPARISON_TABLE_SECTION` / `CHOICE_RULE_SECTION` / `SCENARIO_WALKTHROUGH_SECTION` / `REENTRY_SECTION` / `PREREQ_SECTION`。

必填小节定义（权威来源，文档与技能必须与此一致）：

| 模板 | required |
| :-- | :-- |
| 理论型 | 核心思想 / 主干线 / 阶梯式解剖 / 实例走查 / 易错点 / 自测题 |
| 工程型 | 理论型 6 节 + 验证实验 + 排障判据 |
| 对比型 | 核心思想 / 主干线 / 对比表 / 选型口诀 / 场景走查 / 易错点 / 自测题 |
| optional（三型） | 重入点 / 前置检查 |

推断优先级：显式 `template` > 标题含对比类词（默认表：对比/谱系/选型/取舍/差异/之争/vs）→ 对比型 >
领域键**精确或以 `${键}-` 前缀**命中工程族（默认表：图形学/Unity/Shader/URP/渲染）**或**落盘目录的某个路径段精确等于该键，
**或**标题含工程类词（接入/配置/参数/坑/实现/源码/变体）→ 工程型 > 理论型。
`config.templateHints` 可逐字段覆盖三张默认表（EXT-3）；匹配不再用子串包含——「渲染数学」不会再被判工程型。

### 2.3 `lintrules.ts` — 规则判定

| 函数 | 返回 | 说明 |
| :-- | :-- | :-- |
| `scanResidue(body, { blanked? })` | `ResidueHit[]` | 会话残留；数据表驱动，只扫代码块与 `<details>` 之外 |
| `checkCodeFences(body)` | `{ total, unlabeled, unlabeledIndexes }` | 代码块语言标注 |
| `checkSelfTest(sections)` | `{ questions, answered, missing[], usesQn, usesNumbered }` | 自测题答案率与格式 |
| `checkLayers(sections, body?)` | `{ layers[], inRange, sequential, hasNumbers }` | 4~6 层且序号连续 |
| `checkDomainTags(tags, knownKeys)` | `{ tags, roots[], children[], mixed }` | 根域/子域混挂 |
| `checkLinksBlock(sections)` | `{ present, malformed[], lines[] }` | 关联行格式 |
| `checkExperiments(sections)` | `{ present, steps }` | 验证实验步数 |
| `countSection(sections, title)` | `number` | 小节出现次数（变体计入；`spec.mainline` 的唯一性检查） |
| `checkExternalResources(body)` | `{ line, excerpt }[]` | `<iframe>`/`<script>`/`<img src="http…">`（SEC-7，info 级） |
| `bodyLength(body, blanked?)` | `number` | 去空白后的正文字数（不含代码块与折叠块） |

> 结构类判定统一接收**已切好的小节**（`lintCard` 里只 `splitSections` 一次），`scanResidue`/`bodyLength`
> 复用同一份 `blankOutBlocks` 结果（PERF-3）。

共享正则常量（**代码与文档同源**）：

```ts
RESIDUE_PATH_RE    = /(?:[A-Za-z]:\\|Assets[\\/]|\.(?:shader|unity|mat|asset|hlsl|cs|cginc|compute)\b)/
RESIDUE_LINE_RE    = /\bL\d+(?:\s*[-–]\s*L?\d+)?\b/
RESIDUE_PERSON_RE  = /你|我们|咱们/
RESIDUE_TIME_RE    = /上次|本次|刚才|刚刚|昨天|前天|前几讲/
RESIDUE_PHASE_RE   = /\b(?:P[0-3]|W[1-9])\b/
RESIDUE_SESSION_RE = /本工程|本卡会话|排查顺序|先证据后结论|课上/     // 2026-09 移除 `实测`（误报率高）
LINE_WHITELIST_RE  = /\bL[0-2]\b(?!\s*[-–~]\s*L?\d)|LOD/      // 球谐带 / 正则化 / LOD
LECTURE_REF_RE     = /(?:[A-Za-z]+\s*)?L\d+\b[^。；\n]{0,12}(?:讲|课|课件)|第\s*\d+\s*讲|Lecture\s*\d+/i
```

### 2.4 `lint.ts` — 规则注册表与打分

```ts
interface Rule { id; title; weight; severity; scope?: 'card'; run(ctx: RuleCtx): LintFinding[] }
export const RULES: Rule[]                       // 唯一权威：加一条规则 = 加一个数组元素

lintCard({ title?, definition?, body, template?, tags? }, ctx?): LintReport
interface LintReport { title; template; kind: 'card'|'note'; score; chars; findings; passed }
interface LintFinding { rule; severity: 'error'|'warn'|'info'; title; message; line; excerpt?; suggestion?; weight }
interface LintContext { tags?; knownDomains?; residueLevel?: 'off'|'warn'|'error'; rulesOff?: string[]; kind?: 'card'|'note' }
interface RuleCtx { title; definition; body; sections; residueText; bodyChars; spec; tags; knownDomains; residueLevel; kind }

formatReport(report): string
summarizeLint(reports, titles): LintBatch          // total / noteCount / averageScore / distribution / rules / rows
formatBatch(batch, limit = 20): string
ruleIds(): string[] / ruleTitle(id): string / ruleCatalog(): { id, title, weight, severity, scope }[]
REENTRY_CHARS = 3000 / ERROR_SCORE_CAP = 59 / SCORE_BUCKET = 10
```

**规则与权重**（`RULES` 是唯一权威；`ruleIds()`、`ruleTitle()`、`card_lint` 的工具描述都由它派生）：

| rule id | 中文 | 权重 | 默认级别 | 适用范围 | 触发条件 |
| :-- | :-- | --: | :-- | :-- | :-- |
| `session-residue` | 会话残留 | 10/处（第二人称/会话口吻 3/处） | warn（可配 error/off） | 全部 | 6 类命中 |
| `definition-length` | 定义长度 | 8 | warn | 全部 | 定义 >60 字 |
| `template-sections` | 模板必填小节 | 5/节 | warn | 卡片 | 按 `spec.required` 缺节 |
| `mainline` | 主干线唯一 | 5 | warn | 卡片 | `spec.mainline` 小节出现 >1 次（缺节由 template-sections 负责） |
| `prereq-check` | 前置检查 | 3 | warn | 卡片 | 有关联「前置」但缺该小节 |
| `reentry-point` | 重入点 | 3 | warn | 卡片 | 正文 >3000 字且缺该小节 |
| `verify-experiment` | 验证实验 | 5 | warn | 卡片 | 工程型缺失或步数 <3 |
| `troubleshoot-criteria` | 排障判据 | 5 | warn | 卡片 | 工程型缺该小节 |
| `code-language` | 代码块语言 | 3 | warn | 全部 | 有未标语言的代码块 |
| `selftest-answer` | 自测题答案 | 3 | warn | 卡片 | 有题无 `→` 答案，或用了 `1./2.` 编号 |
| `layer-number` | 层级序号 | 3 | warn | 卡片 | 层数不在 4~6 / 序号不连续 / 无序号 |
| `links-format` | 关联块格式 | 3 | warn | 全部 | 关联行不符合 `- 标签：…` |
| `domain-tag` | 领域标签 | 3 | warn | 全部 | 同时挂根域与子域 |
| `external-resource` | 外部资源 | 0 | info | 全部 | 正文引用 `<iframe>`/`<script>`/`<img src="http…">` |

- `walkthrough`（实例走查）已于 2026-09 审查后**合并删除**：三种模板的必填小节已分别包含 `实例走查`（理论/工程型）
  或 `场景走查`（对比型），该规则与 `template-sections` 重复，且对对比型是误报。缺节仍会被 `template-sections` 报出。
- `scope: 'card'` 的规则在 `kind === 'note'`（旧笔记）时**跳过**且不写入 `passed`（BIZ-4）。
- 打分：`score = max(0, 100 - Σ权重)`；存在 `error` 级发现时 `score = min(score, 59)`。

### 2.5 `history.ts` — 版本块与历史折叠

```ts
type HistoryKind = 'version' | 'errata' | 'details'
extractHistory(body): HistoryBlock[]         // { kind, title, body, line, endLine }
checkDetails(body): { balanced, opens, closes, unclosed[] }
versionBlock(source, changes) / errataBlock(changes): string      // source 过 inlineText（单行）
insertHistoryBlock(body, block): string      // = insertBlockBefore(body, block, '关联卡片')
stripHistory(body, { kinds? }): { text, removed: HistoryBlock[], warnings: string[] }
formatHistory(blocks): string
```

- `extractHistory` 识别 `### 版本更新…`、`### 勘误…` 小节与配对完整的 `<details>…</details>`。
- `stripHistory` 先校验配对：**不配对只警告，未闭合块不会被删除**；`kinds` 可只清某类。
- **删除顺序（BIZ-1 修复）**：先在**原始坐标系**删 `<details>`（`dropDetailsBlocks` 用 `extractHistory` 的行号），
  再 `splitSections` 按标题过滤 `版本更新`/`勘误` 小节、`renderSections` 收尾。
  旧实现先重排文本再拿原始行号删除，行号前移会删掉无关正文（实测丢失整个「关联卡片」小节）。
  `removed` 的行号语义是**删除前的位置**，工具返回文本已标注。
- `append-version` / `errata` 均走 `insertHistoryBlock` → 阅读顺序为「正文小节 → 版本更新 → 关联卡片」。

### 2.6 `rename.ts` — 改名与入链重写

```ts
replaceCardTitle(raw, newTitle): string       // 只改 frontmatter 标题，其余原样；标题过 inlineText
cardTitleOf(raw): string                      // frontmatter 标题，回退正文一级标题
rewriteCardLinks(body, { oldTitle, newTitle, targetId? }): LinkRewrite   // 只动「关联卡片」小节内以 - 开头的行
rewriteWikilinks(body, oldBase, newBase): LinkRewrite                    // [[旧名]] / [[旧名|别名]] / [[旧名#锚点]]
detectBrokenLinks(body, { oldTitle, oldId?, newTitle?, checkFormat? }): BrokenLinkHit[]
planRename({ fileName, oldTitle, newTitle }): { renameFile, oldBase, newBase, reason }   // 复用 vault.sanitizeFilename
formatRenameReport({ id, oldTitle, newTitle, plan, filesChanged, broken, dryRun, notes? }): string
```

改名同步四件事：frontmatter 标题 → 文件名（仅当 `文件名 === 旧标题清洗结果`）→ 全库入链 → 断链检测。
编排在 `VaultStore.planRenameAction`（纯计算 + 冲突校验）+ `commitRename`（落盘 + 回滚）：
只写**可写根**（vault，或 `linkIntoNotes: true` 时的额外根），其余命中报告标注"只读根未写入"；
`detectBrokenLinks` 对每个候选文件都跑（`checkFormat: false`，只报"仍指向旧标题"，不报别人的历史格式噪声）。

| `card_update` | `id` `mode` | `changes`/`source`（append,errata）、`definition`（definition,replace）、replace 全字段 | `已更新：rel` + `ID：…` + 整卡；透传会话 cwd（引用解析与 `card_search` 回显路径一致） |

| `study_memory` | `action(get\|set\|append\|remove\|clear)` | `key` / `value` | 单键值或整份（`_autoPrefs` 状态行置顶、`lastSummary` 置顶）；`__proto__` 等保留键拒绝 |

### 3.1 `card_update` 四种模式

| mode | 行为 | 参数 |
| :-- | :-- | :-- |
| `append-version` | 插「### 版本更新（来源：X）」到关联卡片之前，旧内容保留 | `changes`（必）、`source`（默认"学习补充"） |
| `errata` | 插「### 勘误」到关联卡片之前，旧结论保留 | `changes`（必，含纠正原因） |
| `definition` | 只替换正文首行引用块（一句话定义），**不产生历史折叠** | `definition`（必，≤60 字，不含换行） |
| `replace` | 整卡替换，旧正文压入 `<details><summary>历史版本（日期）</summary>` | replace 全字段 + 可选 `links` |

## 4. 配置参考（`StudyConfig` → `VaultLayout`）

`StudyConfig` 是 `VaultLayout` 的"可省略默认值"视图（同一份定义，EXT-6）：类型定义只有 `src/vault.ts` 一处，
`normalizeConfig` 只做默认值填充。

| 键 | 默认 | 说明 |
| :-- | :-- | :-- |
| `vaultRoot` | 必填 | vault 绝对路径；为空或**文件系统根**（`parse(resolve(p)).root === resolve(p)`）→ 挂载失败（fail-loud） |
| `stateDir` | `.study` | 进度/记忆状态目录（相对 vaultRoot） |
| `fallbackDir` | `未分类` | 未映射领域落盘目录（实际写入 `未分类/<领域>/`） |
| `mocDir` | `目录` | MOC 落盘目录（文件名 `日期_标题.md`） |
| `domainFolders` | `{}` | 领域键 → vault 内相对目录；支持多键别名 |
| `skipDirs` | `[]` | 额外跳过扫描的顶层目录名（内置跳过 `.obsidian`/`.trash`/`.study`/`.git`/`node_modules`） |
| `includeSessionCwd` | `false` | 把会话工作目录纳入检索（与 vault 相同/嵌套自动去重；文件系统根被拒） |
| `searchRoots` | `[]` | 额外检索根（绝对或相对 vaultRoot）；不存在 → 挂载失败；默认只读 |
| `linkIntoNotes` | `false` | 是否允许写入无 ID 的旧笔记（同时决定额外根是否可写） |
| `lint.residueLevel` | `warn` | `off` / `warn` / `error`（error 时含残留的卡封顶 59 分）；`off` 时该规则**不进 `passed`**，报告单列 `⊘ 未执行` |
| `lint.rulesOff` | `[]` | 禁用的规则 id 列表；**未知 id 在 `normalizeConfig` 抛错**（列出 `ruleIds()` 可用集） |
| `indexTtlMs` | `2000` | 索引缓存 TTL（毫秒）；`0` = 每次调用都重扫全库。TTL 命中且**未命中/找不到卡片**时强制重扫一次（`ensureIndex(cwd, { force: true })`） |
| `maxWalkFiles` | `20000` | 每根扫描文件数上限（`walk(..., maxFiles)`）；超限**截断并 `onSkip` 上报**，不再抛错 |
| `templateHints.engineeringDomains` | 图形学/Unity/Shader/URP/渲染 | 工程型领域键（精确或 `${键}-` 前缀，或目录路径段精确等于） |
| `templateHints.engineeringTitles` | 接入/配置/参数/坑/实现/源码/变体 | 工程型标题特征词 |
| `templateHints.comparisonTitles` | 对比/谱系/选型/取舍/差异/之争/vs | 对比型标题特征词 |

配置在 preset 行 `agent.cordis.yml` 的 `study.config`；改完需重启 DSH。`templateHints` 逐字段覆盖默认表。

## 5. 数据与文件格式

### 5.1 卡片 frontmatter（五键 + 可选模板）

```yaml
---
ID: 202609092139_92d2ab      # card_create 自动生成（YYYYMMDDHHmm_6位hex），不可手改
标题: URP IBL 接入
领域: #图形学-Shader #IBL   # 首个标签 = 领域键；其余为补充标签
来源: URP 14 文档
状态: 已确认                # 草稿 / 已确认 / 需更新
模板: 工程型                # 可选：理论型 / 工程型 / 对比型
---
```

解析器只认这六个键，其它键忽略（不影响正文）。`模板` 缺失时按标题/领域推断。
渲染侧对每个值做 `inlineText` 收敛（**只折换行、不压空格**）；校验侧对 `title/domain/source/status/definition` **拒绝换行**，
`tags` 拒绝含空白（否则会被 frontmatter 的空格分隔拆成两个标签）。

### 5.2 状态文件

| 文件 | 结构 | 损坏行为 |
| :-- | :-- | :-- |
| `.study/progress.json` | `{ currentMaterial, currentSection, pendingQuestions[], touchedCardIds[], updatedAt }` | 抛错（含文件名与原因），可手动修或删除回空态 |
| `.study/memory.json` | `{ notes: Record<string,string>, updatedAt }`；保留键 `lastSummary`、`_autoPrefs`(on/off) | 同上 |

记忆键 ≤64 字符、值 ≤4000 字符；`_autoPrefs` 只接受 `set/remove`，不接受 `append`；
键名拒绝 `__proto__`/`prototype`/`constructor`（SEC-6）。进度队列上限 50 条、单条 200 字。

### 5.3 落盘与命名

- 卡片：`domainFolders[domain]` → 目录；未映射 → `fallbackDir/<领域>/`。
- 文件名：标题清洗（Windows 非法字符、引号、`[` `]`）后 ≤80 字符；设备名（`nul`/`con`/`com1`…）加 `_` 前缀；
  冲突依次加 `_ID末6位` → `_完整ID` → 报错。清洗只有 `vault.sanitizeFilename` 一份实现（`rename.ts` 复用它）。
- 写入：`atomicWrite` = 临时文件 + `rename`（失败清理临时文件，不留半成品）。
- 路径安全：所有落盘路径经 `withinRoot` 校验，越界即抛错；写操作前 `assertWritable(card)` 复核根的可写性。

## 6. 错误语义（fail-loud）

| 场景 | 行为 |
| :-- | :-- |
| `vaultRoot` 缺失/为文件系统根 | 挂载抛错 → `agent-preset-invalid`（原因立即可见） |
| `searchRoots` 目录不存在 | **构造 store 时**抛错，不等首次搜索 |
| `ctx.tools.register` 不可用 | 抛错，不静默 return |
| 工具注册半途失败 | 先 dispose 已注册的工具再抛 |
| 卡片校验失败（缺字段/非法 status/定义 >60 字/字段含换行） | 抛错，**不落盘** |
| `.study/*.json` 损坏 | 抛错（含文件名与原因），不静默降级 |
| `card_history strip` 遇未闭合 `<details>` | 警告 + 跳过该块，其余照常 |
| `card_history` 的 `kinds` 含非法值 | 抛错（不静默变成"无块可清除"） |
| `card_rename` 目标同名/旧笔记 | **写入前**抛错并提示"未做任何写入" |
| `card_rename` 落盘中途失败 | 按写前缓存逆序回滚，抛 `改名失败并已回滚：…` |
| 写入只读根（`searchRoots`/工作目录） | 抛错；`card_link` 在**写入前**校验两侧（不留半写盘）；`rename` 只报告"只读根未写入" |
| 扫描超过安全阀（`maxWalkFiles` / 16 层） | **不抛错**：截断扫描并通过 `⚠` 上报（深度超限同理，按原因分组回显） |
| 读取失败的文件 | **不静默**：计数并在 `search`/`lint`/`rename`/`moc` 返回文本追加 `⚠ 跳过 N 项未完整处理：<原因>（…）` |
| 名字是 `.md` 但读不成文件（断链符号链接 / stat 失败） | **不静默**：与上同一通道上报，原因写明 `符号链接目标不可达（ENOENT）` 或 `文件 stat 失败（…）`——旧实现用 `dirent.isFile()` 当门禁，这类条目既不在索引里、也不在跳过清单里，"共检索 N 篇"会少算而不自知 |

## 7. 性能与缓存

- 索引缓存键 = `sessionCwd` + 每个文件的 `root|rel|mtimeMs|ctimeMs|size`；签名不变直接复用。
- **TTL**（`config.indexTtlMs`，默认 2000ms）：TTL 内且会话 cwd 未变时跳过 `walk + stat` 全库；写操作显式失效。
  TTL 命中的索引在**未命中/找不到卡片**的失败路径上会被强制重扫一次（`servedFromCache` + `{ force: true }`），
  因此"Obsidian 刚保存 → 立刻 `card_search`/`card_get`"依然即时可见；只有命中路径走缓存。
- 多根去重：根级按规范化路径 + 包含关系裁剪（vault 优先），文件级按规范化路径去重。
- 检索召回：CJK 双字组 + 英文单词（长度 ≥2），字段权重 标题 4 / 定义 3 / 领域 2 / 正文 1；
  单字 token 权重 ×0.2（PERF-6）；**先排序取 top-N 再算 snippet**，同分按 卡片优先 → 路径字典序。
- 索引查询：`byId`/`byTitle` 走 Map（`rebuild` 时建），来源标签走 `rootSet`。
- `titleHints`（`Map<小写标题, {title, fullRel, id}>`）为 `card_create` 的同名提示提供 O(1) 查询：
  索引重建时整体填充，`create`/`replace`/`rename` 后增量维护。**写路径不再触发全库扫描**（N2）；
  代价是进程内从未建立过索引时该提示缺席（提示不是门禁）。
- 批量 lint 复用索引里的 `body`/`template`，**不再逐文件读盘**；每卡只 `splitSections` 一次、
  `blankOutBlocks` 一次（PERF-2/PERF-3）。
- `rename` 用索引正文预筛（含旧标题/旧文件名/ID 才读盘），只读根不读盘。
- 已知边界：索引常驻全库正文（1000 卡 × 4KB ≈ 4MB）。10 万卡级需改懒加载 + LRU（PERF-8，未做）。

## 9. 调试与排障

| 现象 | 排查 |
| :-- | :-- |
| 会话里没有任何 `card_*` 工具 | 插件未装进 profile / `file:` 依赖未刷新 / preset 配置被旧副本覆盖；核对 `<profileDir>/node_modules/dsh-study-buddy/lib/index.js` |
| 挂载报 `agent-preset-invalid` | `vaultRoot` 为空/文件系统根，或 `searchRoots` 目录不存在 |
| 配置改了不生效 | 配置在 `%DSH_HOME%\.agent-presets\study\agent.cordis.yml`，需重启 DSH |
| 搜索不到刚改的卡 | 索引有 2s TTL（`indexTtlMs`，设 0 关闭）；**未命中会强制重扫一次**，通常已即时可见 |
| 报告出现 `⚠ 跳过 N 项未完整处理` | 按括号里的原因处理：文件读取失败（同步盘/Obsidian 锁定）→ 解锁重跑；`符号链接目标不可达` → 修好或删掉断链；目录深度超限 → `skipDirs` 排除；`扫描文件数已达上限` → 调高 `config.maxWalkFiles` 或收窄 `searchRoots` |
| `card_get` 报"找不到卡片" | 用 ID 或根限定路径（`vault/…`、`工作目录/…`、`<标签>/…`） |
| `card_lint` 报会话残留但看起来没问题 | 用 `rule:'session-residue'` 单看命中行；必要时 `lint.residueLevel:'off'` 或 `lint.rulesOff:['session-residue']` |
| `card_lint rule=X` 报"未启用或不适用于此类文档" | 该规则在 `lint.rulesOff` 里被关闭，或它是结构类规则而目标是旧笔记 |
| 旧笔记在批量体检里分数很高/很低 | 旧笔记只跑 6 条通用规则，不与卡片同口径比较 |
| 改名后 Obsidian 里有断链 | 看 `card_rename` 报告的"断链检测"段；旧笔记侧不自动改写（按文件名寻址） |
