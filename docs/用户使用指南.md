## 1. 这是什么

`dsh-study-buddy` 是给 [DeepSeek Harness](https://github.com/deepseek-ai/DeepSeekHarness)（DSH）做的**「通用学习 Agent」模式**，由两部分组成：

| 组成 | 是什么 | 装在哪里 |
| :-- | :-- | :-- |
| **插件**（本仓库 `src/`，构建产物 `lib/index.js`） | 注册 12 个 `card_*` / `study_*` 工具，用 `node:fs` 直写你的 Obsidian vault | 你的 DSH profile 的 `node_modules` |
| **预设**（本仓库 `presets/study/`） | 「学习伙伴」Agent：persona（苏格拉底式学习伙伴）+ 6 个技能（`study-loop` / `card-format` / `incremental-update` / `domain-adaptation` / `file-reading` / `memory-auto`）+ 插件挂载行 | `%DSH_HOME%\.agent-presets\study\` |

一句话定位：**快节奏、听指挥（指令驱动）、把知识沉淀成原子卡片直接写进你的 Obsidian vault 的学习伙伴**。

核心理念：

- **知识即卡片，卡片即知识**：卡片不是数据库记录，就是 vault 里普通的 `.md` 文件（带 frontmatter）。与你的旧笔记同库、同目录，Obsidian 可直接打开/编辑，git 可管理。
- **磁盘是唯一真相**：插件读索引会按 mtime/ctime/大小签名自动重扫（默认 2s 缓存窗口），你在 Obsidian 里手改、git 回滚永远有效，插件不与你的编辑打架。
- **决定权在你**：讲不讲、讲多深、写不写卡、改不改旧卡、更新还是不更新——都由你下命令、做决定；插件与 Agent 只给建议和对比。
- **内容会出境**：vault 正文、路径、进度与记忆都会随工具结果进入会话日志并发给模型服务商；插件自身不联网。详见 README「隐私」。

| 功能 | 一句话 | 详见 |

## 3. 安装与部署

### 3.1 前提

- 一份**可运行的 DSH 部署（web profile）**。本仓库是插件 + 预设，**不含 DSH 本体**。
- Node.js ≥ 22、pnpm（仓库锁文件为 pnpm 11）。
- 一个 Obsidian vault 目录（绝对路径）。
- 若需读取 PDF/PPTX：本机 Python 环境，PDF 需要 `PyMuPDF`（新版本 `import pymupdf`；旧版 <1.24 为 `import fitz`），PPTX 需要 `python-pptx`；DOCX 用 Python 标准库即可，无需第三方库。

### 3.2 克隆并构建插件

```powershell
git clone https://github.com/V-Reason/dsh-study-buddy.git
cd dsh-study-buddy
pnpm install
pnpm run check        # typecheck + 248 项测试 + 构建 lib/index.js
```

### 3.3 把插件装进你的 DSH profile

`<profileDir>` 通常是 `%DSH_HOME%\profiles\web`。在 `<profileDir>\package.json` 的 `dependencies` 里加入：

```json
"dsh-study-buddy": "file:D:/path/to/dsh-study-buddy"
```

然后：

```powershell
cd <profileDir>
pnpm install
```

### 3.4 部署预设

```powershell
Copy-Item -Recurse presets/study "$env:DSH_HOME\.agent-presets\study"
```

### 3.5 必改配置（最重要的一步）

编辑 `$env:DSH_HOME\.agent-presets\study\agent.cordis.yml`，找到 `study` 插件行：

1. **`vaultRoot`**：换成你自己的 Obsidian vault 绝对路径（默认是占位符 `<你的vault绝对路径>`，不改则插件报错拒绝挂载）。
2. **`domainFolders`**：按你的 vault 分类调整「领域 → 目录」映射（仓库默认按作者习惯给了数据结构、操作系统、图形学、Unity、美术等映射；键是 `card_create` 传的领域键，值是 vault 内相对目录；多个键可指向同一目录，如 `数据结构与算法`/`数据结构`/`算法` → `计算机/编程/数据结构与算法`）。
3. **（可选）** `skipDirs`、`includeSessionCwd`、`searchRoots`、`linkIntoNotes`——默认值及含义见[第 4 章](#4-配置参考逐键详解)。

### 3.6 启动并选择预设

重启 DSH，新建会话，在预设列表中选择 **「学习伙伴」**（preset 显示名；部署目录名为 `study`）。

### 3.7 升级插件

`file:` 依赖**不会自动刷新**。升级后若 DSH 未加载新代码：

```powershell
Remove-Item -Recurse "<profileDir>\node_modules\dsh-study-buddy"
cd <profileDir>
pnpm install
# 重启 DSH
```

预设侧同理：删旧复制新（`Copy-Item -Recurse -Force`），并把配置文件里的 `vaultRoot`/`domainFolders` 再核对一遍（部署步骤 3.5 的编辑不会随复制丢失——**前提是直接编辑 `%DSH_HOME%` 下的副本**，不要每次重新复制覆盖它）。

> ⚠ 部署形态说明：若你的启动器**以 vault 目录作为 DSH 工作目录**启动（`vaultRoot` 与 `{{cwd}}` 相同），这是**受支持**的部署形态（配套 launcher 的默认行为）。插件只拒绝「文件系统根」这一真正危险的落盘目标。事故复盘见 `docs/archive/dev-experience/postmortem-2026-08-21-tools-not-registered.md`。

## 4. 配置参考（逐键详解）

配置位置：`presets/study/agent.cordis.yml` 的 `study` 插件行 `config`（部署后即 `%DSH_HOME%\.agent-presets\study\agent.cordis.yml`）。

| 键 | 插件默认 | 预设当前值 | 说明 |
| :-- | :-- | :-- | :-- |
| `vaultRoot` | 必填（无默认） | `<你的vault绝对路径>` | Obsidian vault 绝对路径。为空/文件系统根会**挂载失败**（fail-loud）。 |
| `stateDir` | `.study` | `.study` | 进度与记忆状态目录（相对 vaultRoot）。其中 `progress.json`、`memory.json` 见 [5.4](#54-磁盘上有什么)。 |
| `fallbackDir` | `未分类` | `未分类` | 未映射领域的落盘目录（相对 vaultRoot），实际写入 `未分类/<领域名>/`。 |
| `mocDir` | `目录` | `目录` | MOC 知识目录的落盘位置（相对 vaultRoot），文件名为 `日期_标题.md`。 |
| `domainFolders` | `{}` | 见预设 | 领域键 → vault 内相对目录。支持多键别名指向同一目录。未映射 → `fallbackDir/<领域名>/`。 |
| `skipDirs` | `[]` | `[资源]` | 额外跳过扫描的**顶层**目录名。内置已跳过：`.obsidian` / `.trash` / `.study` / `.git` / `node_modules`。媒体等大目录（如 `资源`）建议加入，避免索引膨胀。 |
| `includeSessionCwd` | `false` | `true` | 把「会话工作目录」（DSH 启动目录，即 persona 里的 `{{cwd}}`）的旧笔记纳入 `card_search`/`card_get`。与 vault 相同或嵌套时自动去重，不重复扫描。 |
| `searchRoots` | `[]` | `[]` | 额外检索根（绝对路径，或相对 vaultRoot 的路径）：固定旧笔记库，**只读**。目录不存在则**挂载失败**（fail-loud）。检索结果显示的标签 = 目录名（与 `vault`/`工作目录` 冲突时自动加序号 `名称(2)`）。 |
| `linkIntoNotes` | `false` | `false` | `card_link` 是否允许把关联写入**无 ID 的旧笔记本体**（默认只在卡片侧写，旧笔记零改动）；同时决定 `searchRoots`/工作目录是否可写（`true` 时 `card_rename` 也会同步改写这些根里的关联行）。 |
| `lint.residueLevel` | `warn` | 未设置 | 会话残留规则级别：`off` / `warn` / `error`（`error` 时含残留的卡总分封顶 59）。 |
| `lint.rulesOff` | `[]` | 未设置 | 禁用的规则 id 列表，如 `['domain-tag']`。禁用后 `card_lint rule=X` 会明确回显"未启用或不适用于此类文档"。 |
| `indexTtlMs` | `2000` | 未设置 | 索引缓存 TTL（毫秒）：TTL 内跳过全库 `stat`。设 `0` = 每次调用都重扫（Obsidian 外部编辑立即可见，代价是每次工具调用都扫全库）。 |
| `templateHints` | 内置表 | 未设置 | 模板推断提示词表，逐字段覆盖：`engineeringDomains`（工程型领域键）/`engineeringTitles`（工程型标题词）/`comparisonTitles`（对比型标题词）。新增领域族（如 Rust/数据科学）不必改源码。 |

> 配置是 YAML 行内的 `config:`，改完需重启 DSH 生效。

领域映射示例（片段）：

```yaml
domainFolders:
  图形学: 游戏开发/图形学
  图形学-后处理: 游戏开发/图形学/后处理与图像   # 子域键 → 子目录
  Unity: 游戏开发/Unity
  'C++': 计算机/编程/C++/基础C++
```

**调优思路**：目录是大规模整理过的（如 83 个笔记分到 8 个子文件夹），就为每个子文件夹加一对「子域键 → 子目录」，并保留原键作兜底；再用 `study_memory(set prefs.xxx=…)` 把新约定写进跨会话记忆，让下个会话的 Agent 知道该传哪个子域键。相关复盘见 `docs/archive/dev-experience/postmortem-2026-08-23-vault-subfolder-reorganization.md`。

## 5. 核心概念

### 5.1 四步学习闭环

每轮学习按四个阶段组织，阶段间由你的指令驱动：

```
阶段一·读取（摄入）   你给路径/说"读取 X" → 输出读取报告（只报告，不讲）
阶段二·讲解（拓展）   你说"讲解" → 一次一个原子点，讲完问"清晰？细化/跳过？"
阶段三·问答（反诘）   你提问 → 三明治回答：直击 ≤3 句 → 底层逻辑 → 反诘追问
阶段四·归档（笔记）   你说"整理笔记/生成笔记/归档" → 按原子知识点落盘（数量不限）+ MOC 目录
```

红线（persona 内建，违反即失职）：
- 不替用户写完整项目代码（引导拆解，单次 ≤100 行完整代码，超出必须拆片段并标注作用/依赖/输入输出）。
- 不假装理解图片（识别不了如实说，请补文字）。
- 读取后未经命令不讲解。
- 不跳过笔记格式：归档前若有未答追问，先提示、先问答。
- 无记忆不办事：对话历史为空的首条消息先 `study_memory(get)` + `study_progress(get)`，读取结果返回前不响应。

### 5.2 原子卡片

- 一张卡 = 一个原子知识点（Zettelkasten 风格），带 frontmatter（`ID`/`标题`/`领域`/`来源`/`状态`）。
- **ID**：`YYYYMMDDHHmm_随机6位hex`（如 `202608161430_ab12cd`），由 `card_create` 自动生成；`card_id` 工具只是**预生成占位符**，`card_create` **不会使用**预生成的 ID（常见坑，见 [7.2](#72-card_id生成占位-id)）。
- **三种状态**：`草稿` / `已确认` / `需更新`（工具 schema 用 enum 约束）。
- **文件名** = 标题清洗后（Windows 非法字符替换为空格、≤80 字符），同目录重名时自动加后缀 `_ID末4位`，再冲突用完整 ID，仍冲突则报错。
- 落盘目录由 `domainFolders` 映射决定；未映射 → `未分类/<领域名>/`。

### 5.3 检索根（卡片 ↔ 旧笔记的边界）

`card_search`/`card_get` 的检索范围是**多个根**的并集：

| 根 | 何时存在 | 标签 | 读写 |
| :-- | :-- | :-- | :-- |
| vault | 永远 | `vault` | 可读可写（写经 `card_*` 工具） |
| searchRoots | 配置了才存在 | 各目录名 | **只读** |
| 会话工作目录 | `includeSessionCwd: true` 且 cwd 非文件系统根 | `工作目录` | 只读 |

- 同一文件被多根扫到（如 vault ⊆ cwd）时按规范化路径去重，**vault 标签优先**。
- 有无 frontmatter `ID` 决定它是「卡片」还是「旧笔记」：`card_search` 命中会标注 `类型：卡片/旧笔记` 与 `路径`（多根时为 `根/相对路径`）。
- 卡片寻址可用：ID、标题、根限定路径（`工作目录/子目录/笔记.md`）、相对路径、纯文件名（多根同名会报歧义，见 [10.5](#105-歧义处理)）。

### 5.4 磁盘上有什么

```
vault/
├── <各分类目录>/卡片.md        # 卡片 = 普通 md，与旧笔记同库
├── 目录/日期_标题.md            # MOC 知识目录
├── 未分类/<领域名>/卡片.md     # 未映射领域兜底
├── .study/                     # 状态目录（内置跳过扫描）
│   ├── progress.json           # 学习进度：资料/小节/未答追问/触及卡片/updatedAt
│   └── memory.json             # 跨会话记忆：键值笔记 + lastSummary（上次小结）+ _autoPrefs（自迭代开关）
└── ...旧笔记.md                # 无 ID frontmatter = 旧笔记（只读侧）
```

- 进度与记忆**相互独立**：「清空进度」只清 `progress.json`，记忆保留；彻底重来才清记忆。
- 两个 JSON 损坏时工具**直接报错**（fail-loud，不静默降级）：报错含文件名与原因，可手动修复或删除该文件后继续（删除即回到空状态）。

### 5.5 指令驱动状态机

```
待命 ──(给路径/"读取 X")──▶ 读取（只出报告）──▶ 待命
待命 ──("讲解/讲吧/开始讲解")──▶ 讲解（一次一个原子点）──▶ 待命
待命 ──(提问)──▶ 问答 ──▶ 待命
待命 ──("整理笔记/归档")──▶ 归档 ──▶ 待命
待命 ──("接着讲")──▶ 从断点续讲 ──▶ 待命
```

- 默认状态是**待命**：Agent 每次只执行你当前一条指令，执行完回待命，**不自动进入下一步、不续讲**。
- **读取 ≠ 讲解**：说"读取 X"，Agent 走 `file-reading` 技能固定工具链读出内容，只输出读取报告（文件信息/内容骨架/一行重叠预警），绝不讲解、不展开、不出卡片预览。
- 讲解只在你明确说"讲解"后开始；每个原子点讲完会问"清晰？细化/跳过？"并回待命。
- 深入研究（联网/超纲）默认不做，你说"查一下/详细讲讲/深入研究"才做。

## 6. 日常使用指南（按场景）

### 6.1 新会话开场（自动衔接）

**新会话第一条消息**（对话历史为空时），Agent 执行**硬门禁**：先 `study_memory(get)` + `study_progress(get)`（get 首行含「自迭代记忆：开/关」；若为开，随后加载 `memory-auto` 技能），**读取结果返回前不响应用户指令、不执行其他工具**；读完再按指令办事：

- 有进度/记忆 → 首行给衔接提示（上次学到/未答追问/上次小结）并问"接着讲？"：

```
上次学到：《Unity Shader入门精要》6.1.2 / 光照模型（未答追问 2 条；卡片 12 张）
上次小结：完成了光照模型的讲解与归档。
（待命中。可指令：接着讲 / 开始新内容）
```

- 无进度/记忆 → 正常待命，不啰嗦、不编造。

### 6.2 读取资料（仅读取）

**触发**：给文件路径 / "读取 X" / "看一下" / 上传或粘贴截图。

**工具链**（由 `file-reading` 技能固定，Agent 不自己摸索工具）：

| 文件类型 | 工具链 | 说明 |
| :-- | :-- | :-- |
| `.png/.jpg/.jpeg/.webp/.gif` | `read_image`（绝对路径） | 唯一首选；失败如实说，请你补文字 |
| `.txt/.md/.json/.yml/.csv/.html/.xml` 及代码 | `read` | 直接读 |
| `.pdf` | ① `pwsh` + Python PyMuPDF 提取文本（默认前 10 页）② PyMuPDF 找含图页渲染 PNG → `read_image`（默认前 12 个含图页）③ 文本近空（扫描版）天然走② | 文本 + 内嵌图片都给模型；超长可续读 |
| `.pptx` | ① `pwsh` + python-pptx 按 slide 提取文本（含表格）② python-pptx 提取图片 shape（`PICTURE`，GROUP 递归）→ `read_image`；zipfile 解 `ppt/media/*` 兜底 | 幻灯片背景/母版图可能遗漏，提示另存 PDF 重读 |
| `.docx` | ① `pwsh` + Python 标准库（解 `word/document.xml` 取 `w:t`）② 解 `word/media/*` 提取图片 → `read_image` | 无需第三方库；绘图对象为 emf/wmf 时列入"需转换" |
| `.ppt/.doc/.xls`（旧二进制） | 不主动尝试 COM（易挂起） | 请你另存为 `.pptx/.pdf/.docx` 再读 |

**输出**（只输出这个，其余一概不做）：

```
已读取：红黑树插入.pptx（PPTX，24 页）
内容骨架：
- slide 1-5：红黑树定义与五条性质
- slide 6-12：插入修复的三种情形判断
...
图片：N 张（每张一行"图N（第 M 页）：所见结构"；超出 12 张注"已读前 12"；svg/emf 等列入"需转换"）
重叠预警：已存在卡片 《红黑树插入修复》[202608161430_ab12]，内容基本重合，建议讲解后增量更新。
（待命中。可指令：讲解 / 继续读后续页 / 换文件）
```

- 重叠预警来自一次 `card_search`（覆盖全部根），**只允许一行、不展开**。
- 失败兜底链：路径错 → 不猜路径，请你核对；命令报错 → 换备选库（pypdf/pdfplumber、PPTX 图片换 zipfile）；乱码 → 确认 `-X utf8` 后重试；沙箱拒绝 → 一次提升请求或你把文件放进工作区/vault，**绝不绕过**；图片提取为 0 但你说图里有内容 → 换兜底命令再试，仍无则请你提供截图/另存 PDF，如实说明"未提取到图片"，**不假装读图**。

### 6.3 讲解（仅你命令触发）

**触发**："讲解 / 讲吧 / 开始讲解"。

- 一次**一个原子点**，≤15 行，通俗重构，不照读原文。
- 讲完出「卡片预览」（按 card-format 分型模板的必填小节；不带 ID，归档时由 `card_create` 自动生成）并问"清晰？细化/跳过？"。
- 讲完回待命，**不自动续讲**；每个原子点由你逐次确认推进。
- 只有你要求时才联网：`web_search` 输出标注 `[联网补充]`。

### 6.4 提问（三明治回答）

- ① 直击 ≤3 句 → ② 底层逻辑一两句 → ③ 反诘收尾（"别问了"才不带）。
- 引用旧卡标 `（详见卡片：ID）`；引用旧笔记标 `（详见旧笔记：<根>/<相对路径>）`。
- 问题暴露旧卡盲区/过时 → Agent 会触发增量更新流程（[6.7](#67-增量更新活笔记)）。

**领域适配**：Agent 按资料/提问自动切换讲解侧重（数据结构/操作系统/AI/引擎/美术/图形学各有触发词与侧重，如图形学走高精度数学推导 + HLSL + LaTeX，美术讲"为什么这样做"而非"怎么点按钮"）；跨领域问题会联动多套知识（如"渲染管线缓存未命中"= 体系结构 + 图形学）。领域不明会先问你一句，不猜。

### 6.5 深入研究（按需开启）

**触发**："查一下 / 详细讲讲 / 深入研究"。

- 默认**不联网、不超纲**（快节奏优先）。
- 联网结果标注 `[联网补充]`；超纲推导在你要求时才展开。
- 适用于资料过时、未说明的依赖知识，或你想看最新进展的场景。

### 6.6 归档（整理笔记）

**触发**："整理笔记 / 生成笔记 / 归档"。

Agent 行为：
1. 先 `study_progress(get)` 检查未答追问——有未闭环先提示（红线：不跳过笔记格式）。
2. `card_create` 落盘**原子卡片**（一张卡 = 一个原子知识点，**数量不限**；只做结构化重组与去重，**不加新知识**）。
3. 新卡与检索命中的旧笔记相关 → `card_link`（默认只写卡片侧）。
4. `card_moc` 生成知识目录（只收录有 ID 的卡片，旧笔记自动跳过并提示）。
5. `study_progress(set)` 更新触及卡片、清已答追问；`study_memory(set lastSummary=…)` 写 1~2 句本次小结（本会话若已自动记录偏好则无需重复）。

**典型对话**：

```
你：生成笔记
Agent：已检查未答追问：0 条。
  → card_create ×2：《红黑树插入修复》《红黑树旋转操作与情形表》
  → card_link：插入修复 → 旋转（前置）
  → card_moc：知识目录_20260816（图形学组 2 张）
  → 已写入：游戏开发/算法/红黑树插入修复.md（ID：202608161430_ab12）……（整卡内容）
```

### 6.7 增量更新（活笔记）

新内容与旧卡相关时，Agent 走三步，**决定权永远在你**：

**步骤 1 · 定位提醒**

```
检测到"红黑树删除修复"与现有卡片 202608161430_ab12 相关。
旧卡摘要："插入修复三种情形"；新内容摘要："删除修复双黑节点"。
建议增量更新。
```

**步骤 2 · 判定与建议**（先给"旧 vs 新"对比表，再问询确认）：

| 情形 | 判定 | 建议 | `card_update` 模式 |
| :-- | :-- | :-- | :-- |
| 补充 | 不推翻旧结论 | 尾部加「版本更新（来源）」 | `append-version`（changes + source） |
| 推翻 | 推翻旧结论 | 保留旧内容加「勘误」（注明纠正原因） | `errata`（changes 含原因） |
| 无关 | 完全无关 | 新卡片 + 旧卡加"后续"关联 | `card_create` + `card_link(next)` |

**步骤 3 · 执行**：你确认后才调用，输出更新后整卡（含新旧内容）供复制替换；更新 `touchedCardIds`。**你拒绝 → 不写任何文件。**

### 6.8 进度与记忆（附指挥词速查）

| 你说 | 发生什么 | 底层 |
| :-- | :-- | :-- |
| "接着讲" | 从上次断点（资料/小节）继续 | `study_progress(get)` 找断点 |
| "清空进度" | 只清进度位置，记忆保留 | `study_progress(clear)` |
| "记住……" | 写跨会话记忆（偏好/约定） | `study_memory(set)`，惯例键 `prefs.*` |
| "忘了……" | 删对应记忆 | `study_memory(remove)`；键不存在时明确提示"无此键"且不写盘 |
| "开启自迭代" | 打开自迭代记忆：偏好/约定自动记录，无需"请记住" | `study_memory(set _autoPrefs=on)` |
| "关闭自迭代" | 关闭自迭代，回到"记住…"手动模式 | `study_memory(set _autoPrefs=off)` |
| "清空记忆" | 彻底重来（含开关，回到默认关闭） | `study_memory(clear)`（不动进度） |
| "别问了" | 停止反诘追问 | persona 行为 |
| "先到这 / 结束" | 收尾写小结 | `study_memory(set lastSummary=…)` |

- 进度四要素：当前资料、当前小节、未答追问队列、触及卡片 ID（数组，`set` 为**整体替换**）。
- 记忆键名 ≤64 字符、值 ≤4000 字符，超限报错；保留键 `lastSummary`（上次小结，`get` 置顶）与 `_autoPrefs`（自迭代开关，on/off，只接受 set/remove，不接受 append）。
- 自迭代开启后：Agent 按 `memory-auto` 技能自动把持久偏好/约定写入 `prefs.*`（每类一个键、覆盖更新、不追加），每次写入在回复末尾标注「（已自动记入偏好：prefs.xxx）」，同一键以用户最近一次表达为准；关闭后自动写停止，已写入的保留。
- 手改 `memory.json` 里 `_autoPrefs` 为非法值 → `get` 显示「异常值」行并提示重新设为 on/off（读不崩）；用 `set` 修复。
- 「清空进度」与「清空记忆」互不影响，语义分离。

### 7.1 card_search — 多根全库检索

- **范围**：vault 内全部 `.md`（卡片 + 旧笔记）+ `searchRoots` + （可选）会话工作目录；多根命中标注 `类型：卡片/旧笔记` 与 `路径`（根限定）。
- **命中行**：`### 标题 [ID]` → `类型` → `路径` → `领域/状态/来源` → `- 定义：…`（≤40 字截断）→ `- 片段：…`。
- **过滤**：`domain`（匹配 frontmatter 领域**或**旧笔记顶层目录推断领域）、`status`、`kind`（card=有 ID，note=无 ID）。
- **limit** 默认 5，上限 50。
- **用途**：摄入新资料前必查重叠；回答问题引用旧卡/旧笔记前定位；增量更新判断前对比。
- **无命中返回**：`未命中（共检索 N 篇，来源：…）。可换词再试；新概念直接进入讲解，归档时新建卡片。`——不编造。

### 7.2 card_id — 生成占位 ID

- 格式 `YYYYMMDDHHmm_xxxx`（hex 后缀）。`count` 上限 20。
- ⚠ **常见坑**：`card_create` 会**自己生成** ID，**不会使用** `card_id` 预生成的 ID。所以：**不要在卡正文里引用"本次预生成的 ID"**。正确姿势：先 `card_create` 拿返回的**实际 ID**，再 `card_link` 或补正文；或干脆等 create 完再写关联。工具描述已注明此约束（不再依赖文档提醒）。坑的来龙去脉见 `docs/archive/dev-experience/postmortem-2026-08-23-vault-subfolder-reorganization.md`。

### 7.3 card_create — 原子卡片落盘

- 必填：`title`/`domain`/`source`/`status`/`definition`/`content`。
- 校验失败直接报错（`卡片校验失败：…`），**不落盘**（fail-loud）。
- **定义长度（2026-09 定稿）**：>60 字**硬拒绝**（报错并提示精简到 ≤60 字、30 字左右最佳）；31~60 字只做等级化提示（"稍长/偏长，允许放行"），**不阻塞、不需要返工**。
- **标题清洗可见性**：标题含非法字符（`/ \ : * ? " < > |`）或引号时自动清洗（引号直接移除不留空格），返回文本会提示"已清洗为文件名「…」"，文件名以返回的 `已写入：rel` 为准。
- **领域映射可见性**：返回文本含 `领域映射：键 → 目录`；领域键未精确命中时提示 `未映射` + **可用键列表（前 12 个）** + **近似键建议**（如"图形学-动画与特效"→"图形学-动画特效"）+ "刚改过 preset 配置需重启 DSH 生效"；目标目录不存在会自动创建。
- `content` 必须含模板必填小节（理论型：核心思想/主干线/阶梯式解剖/实例走查/易错点/自测题；工程型另加验证实验/排障判据；对比型另加对比表/选型口诀/场景走查），缺节出警告（`提示：正文缺少…`）不阻止落盘——**是否补齐由 persona 归档清单强制**；格式见 [8.1](#81-模板定稿--阶梯式解剖)。`template` 参数可显式指定，缺省按领域目录族与标题自动推断并回显。
- `links` 预先写好「关联卡片」小节（纯文本标签，可带注释如 `\`漫反射模型\`（Lambert）`；后续与 `card_link` 按 ID 自动去重）。
- 返回整卡。文件名冲突自动加后缀（`标题.md` → `标题_末4位.md` → `标题_完整ID.md` → 报错）。

### 7.4 card_update — 增量更新

四种模式（由 persona 先给对比并确认后调用；definition 例外：字段级微调无需全卡对比）：

| 模式 | 行为 | 参数 |
| :-- | :-- | :-- |
| `append-version` | 尾部追加 `### 版本更新（来源：X）` + changes；**旧内容保留** | id、changes（必）、source（来源文本，默认"学习补充"） |
| `errata` | 底部追加 `### 勘误` + changes（含纠正原因）；旧结论保留 | id、changes（必） |
| `definition` | **只替换一句话定义**（正文首行引用块）；不重传正文、**不产生历史折叠**；不算知识更新 | id、definition（必，≤60 字硬上限） |
| `replace` | 整卡替换，**旧正文压入 `<details>历史版本（日期）</details>` 折叠块**；可传 `links` 重建关联（不传则新卡无关联小节，旧关联留在历史块） | id、mode + 新卡全字段 |

- 返回 `已更新：rel` + 整卡（含新旧内容，供复制替换/检查）。
- 更新后记得 `study_progress(set)` 更新 touchedCardIds。

### 7.5 card_link — 维护卡片关联

- `kind`：`prev`（toId 是 fromId 的**前置**）/ `next`（后续）/ `conflict`（易混淆）。
- **双向写入**：from 侧写 `前置：目标`，to 侧自动写反向 `后续：来源`（conflict 两侧同向）。已存在的关联**不重复添加**（按 `（ID）` 判重，标题改了也能识别；旧笔记无 ID 回退按标签文本判重）。
- **旧笔记保护**：卡片 ↔ 旧笔记默认**只写卡片侧**（旧笔记零改动），返回说明"（单侧写入；未修改旧笔记：…）"；旧笔记 ↔ 旧笔记默认**拒绝**，需开启 `linkIntoNotes: true` 或改用 Obsidian `[[ ]]` 内链手动连接（Obsidian 会自动生成反向链接）。
- 卡片侧关联行格式：`- 后续：旧笔记标题（工作目录/相对路径.md）`；卡片目标格式：`- 后续：目标标题（目标ID）`。
- ⚠ 与手写「关联卡片」小节择一使用，避免重复行（工具按 ID 去重，手写的错 ID 不会被去重）。
- 非法 `kind`（如 `sideways`）直接报错。

### 7.6 card_moc — 生成知识目录

- 输入本次涉及的卡片 ID/标题（数组），输出按**领域分组**的 MOC（Obsidian wikilink `[[文件名]]`），写入 `mocDir/日期_标题.md`。
- **title 只传主题名**（如 `图形学 MOC 目录`）：日期前缀由工具自动生成（文件名 = `日期_标题.md`）；**不要手写日期**——旧版把日期写进 title 会产生双前缀（`2026-09-02_2026-09-02_…`），现已被自动剥离并回显。
- 返回文本回显 `MOC 已写入：rel（标题：…，日期：…）`；日期与卡片 ID 同源（本地时间），不再出现"卡片 ID 是 09-02、MOC 落 09-01"的错位。
- **只收录有 ID 的卡片**；旧笔记自动跳过并在返回中提示（不算缺失）。
- `domain` 过滤：只收录该领域的卡片；`missing` 未解析到的引用会报错提示。
- 归档收尾时用。

### 7.7 card_lint — 卡片质量体检（2026-09 新增）

14 条规则逐项打分（**全部警告级，不阻塞落盘**；只有"定义 >60 字"仍是 `card_create` 的硬拒绝）：

| 规则 | 判据 | 扣分 |
| :-- | :-- | --: |
| 会话残留 | 本机路径 / 源码行号 / 会话时间词 / 阶段代号（10/处）；第二人称 / 会话口吻（3/处） | 10 或 3 |
| 定义长度 | >60 字（工具会先硬拒，lint 只回显） | 8 |
| 模板必填小节 | 按模板类型缺节（理论型 6 节 / 工程型 8 节 / 对比型 7 节） | 5/节 |
| 主干线 | 主线小节出现多个（缺失由"模板必填小节"负责，不再重复扣分） | 5 |
| 前置检查 | 卡内有"前置"关联但缺该小节 | 3 |
| 重入点 | 正文 >3000 字但缺该小节 | 3 |
| 验证实验 | 工程型缺失或步数 <3 | 5 |
| 排障判据 | 工程型缺失 | 5 |
| 代码块语言 | 有未标语言的代码块 | 3 |
| 自测题答案 | 有题目没 `→` 答案，或用了 `1./2.` 编号 | 3 |
| 层级序号 | 阶梯式解剖不是 4~6 层 / 序号不连续 / 无序号 | 3 |
| 关联块格式 | 关联行不是 `- 前置/后续/易混淆：…` | 3 |
| 领域标签 | 同时挂根域与子域（如 `#图形学` + `#图形学-光照模型`） | 3 |
| 外部资源 | 正文引用 `<iframe>` / `<script>` / `<img src="http…">`（Obsidian 打开会主动外联） | 0（info） |

- 分数 = `100 - Σ扣分`（下限 0）；`residueLevel: error` 时含残留的卡封顶 59。
- **旧笔记口径**：`scope='all'` 时旧笔记只跑 6 条通用规则（会话残留 / 定义长度 / 代码块语言 / 关联块格式 / 领域标签 / 外部资源），**不套模板**，报告里单列"其中旧笔记 N 篇"。不要拿旧笔记的分数与卡片比。
- **误伤控制**（实证校准）：只扫代码块与 `<details>` 折叠块**之外**；白名单 `L0/L1/L2`（球谐带）、`LOD`、`GAMES101 L15`/`第 15 讲`（讲义引用）；行号只在紧跟文件名或成 `L35-55` 区间时报；`M1/M2/M3` 默认不报（多为里程碑/数学记号），仅同行出现"工程/阶段/里程碑"时提示；`实测` 单独出现不再算残留（"实测帧率 60fps"是正常表述）。
- **能力边界**：这 14 条只覆盖可正则化/可结构判定的部分。persona 里的"代码块 ≤60 行""表格列数 ≤4""块前一句在做什么""小节之间因果连接"**没有自动校验**，需要你自己过一遍。
- **用法**：归档后自检 `card_lint({ref})`；批量体检 `card_lint({scope:'vault'})`（返回均分、分数分布、规则命中、最低分卡片）；只看某条规则 `card_lint({ref, rule:'session-residue'})`（规则被禁用或对旧笔记不适用时，明确回显"未启用或不适用于此类文档"）。
- **P2 三个分析开关**（同一个工具）：
  - `cross: true` 跨卡一致性——抽取表格首两列与行内公式赋值（`$mip = …$`），同键在多卡取值不一致时列出冲突组（如 π 标尺 3.14 vs 3.1416）；
  - `trend: true` 质量趋势——按卡片 ID 日期分周输出张数、均分、短板规则与整体趋势；
  - `rating: true` 可执行性分布——能跑（有代码 + 验证实验）/ 能查（有排障判据或对比表）/ 只能读；单卡报告默认附评级。
- **配置**：`lint.residueLevel`（off/warn/error，默认 warn）、`lint.rulesOff`（禁用规则 id 列表）。

### 7.8 card_history — 版本块与历史折叠管理（2026-09 新增）

- `action="list"`：列出全部历史块（类型/行号/摘要）——版本更新、勘误、`<details>` 历史折叠。
- `action="strip"`：清除历史块，**正文与关联卡片保留**；`kinds` 可只清某类（非法值会报错）；先校验 `<details>` 配对，不配对时只警告、不删未闭合块。删除按"整块"语义执行，报告里的行号是**删除前的位置**。
- `dryRun: true` 只报告将删除什么，不写盘。
- 典型场景：用户说"这张卡太长了 / 清掉历史版本 / 只留最新版"。

### 7.9 card_rename — 改标题并同步引用（2026-09 新增）

- 同步四件事：frontmatter 标题、文件名（**仅当文件名 = 旧标题清洗结果**时）、全库入链（`` `标题`（ID） `` 与 `[[wikilink]]`）、断链检测。
- **先校验后提交**：目标标题/文件名冲突时**不做任何写入**（报错里会写"未做任何写入"）；落盘中途失败会按写前缓存回滚，并报 `改名失败并已回滚：…`。
- 只写**可写根**的文件（vault；`linkIntoNotes: true` 时含额外检索根）；只读根命中时在报告里标注"只读根未写入"。
- `dryRun: true` 预演（断链检测与实写同一口径，不会再"恒报无断链"）；旧笔记（无 ID）明确拒绝。
- 典型场景：用户说"标题改成 X / 名字写错了 / 统一一下命名"。

### 7.10 study_progress / 7.11 study_memory

见 [6.8](#68-进度与记忆附指挥词速查)。补充细节：

- `study_progress(set)` 无任何字段时**不写盘**（不 bump updatedAt），直接返回当前状态；`pendingQuestions`/`touchedCardIds` 上限 **50 条、每条 200 字**（超限报错，避免 progress.json 膨胀）。
- `study_memory` 的 `append`：已存在键时**换行拼接**（`旧值\n新值`）；保留控制键 `_autoPrefs` 不接受 append（set 切换 on/off，remove 回到默认关闭）。
- 键名拒绝 `__proto__`/`prototype`/`constructor`（会被 JS 原型语义吞掉，写入无效）。
- `study_memory(get)` 带 key = 取单键（无则 `（无此键：key）`）；不带 key = 全量（`_autoPrefs` 状态行置顶，`lastSummary` 置顶为「上次小结」，其余按键名字典序）。
- `study_memory(get)` 全量输出会对含"现学/正在学"等**进度句**的键追加"⚠ 提示"——进度位置以 `study_progress` 为**单一来源**，偏好键中的进度句建议迁移或标注为「历史快照」。
- 记忆里以"忽略/指令/你现在是"开头的值会得到"记忆是用户数据、不会被当作指令执行"的软提示（**不拒绝写入**）。
- 未知 action 一律抛错（`study_progress 未知 action "xxx"（可用 get/set/clear）`），不静默；vault 不可读时也不会在错误路径静默创建 `.study/`。

### 7.12 模型在同一会话中还能用什么工具

「学习伙伴」预设还挂载了：文件读写/检索（`read`/`glob`/`grep`/`fs-search`，**仅限工作区**，vault 在沙箱外只能走 `card_*` 工具）、`pwsh`（Windows，演示验证用，遵守 100 行红线）、`skill`（按需加载 6 个技能）、`web_search`（仅你要求时用）、`ask_user_question`（拍板确认）、`todo_write`（任务清单）。**不挂载**：计划模式、子代理、工作流、目标工具、后台任务控制（学习是聊天驱动，不是工程任务；`/goal` 命令仍在宿主可用）。

## 8. 卡片格式规范

> 2026-09 重设计：卡片从"原子知识块"升级为**可独立复读的微课程**——假设读者已忘光 80%，判据是"30 分钟内能否重建它"。
> 完整规范与三型样张见 `presets/study/skills/card-format/SKILL.md`；本节给使用者视角的要点。

### 8.1 通用骨架（2026-09 定稿）

```markdown
---
ID: [YYYYMMDDHHmm_随机，card_create 自动生成]
标题: [概念名称]
领域: #图形学-光照模型 #PBR
来源: [资料名称]
状态: 草稿 / 已确认 / 需更新
模板: 理论型 | 工程型 | 对比型      # 可选，card_create 自动推断并回显
---

> 一句话定义（≤30 字最佳，≤60 字硬上限；裸引用块，不加标题）。

### 重入点                      # 长卡（>3000 字）必填
- **30 秒**：<心智模型 + 结论各一句>
- **5 分钟**：<主干线 + 阶梯式解剖 第 1~2 层>
- **30 分钟**：<全卡 + 自测题>

### 前置检查                    # 有前置卡时必填
- 需要知道：<概念 A>（详见卡片：<ID>）、<概念 B>（详见卡片：<ID>）
- 不需要知道：<明确排除>

### 核心思想
**一句话讲清**：… / **为什么**：… / **记忆锚点**：…

### 主干线
<问题> → <关键约束> → <解法> → <代价> → <验证方式>

### 阶梯式解剖
**第 1 层 · 直觉** → **第 2 层 · 机制** → **第 3 层 · 细节与推导** → **第 4 层 · 边界与反例**
（4~6 层，带"第 N 层"序号）

### 实例走查
数值代入 / 代码走查 / 场景走查（至少一种）

### 验证实验                  # 工程型必填，≥3 步
1. <操作>：<看到什么说明什么>

### 排障判据                  # 工程型必填
| 症状 | 判据 | 修复 |

### 易错点
- 坑：为什么错

### 自测题
- **Q1**：问题 → 答案要点（答不出 → 回看 X）

### 关联卡片
- 前置：`标题`（ID）
- 后续：`标题`（ID）
- 易混淆：`标题`（ID）
```

**规则要点**：

- **正文字数不设上下限**（2026-09 取消）。长度由信息完备性决定；替代约束是"单一主题 + 信息增益 + 三问自检"。
- **定义仍限 ≤60 字**（检索契约与 TL;DR；>60 硬拒绝，31~60 只提示"允许放行"）。
- **分型必填小节**：理论型 6 节 / 工程型 8 节 / 对比型 7 节；缺节出警告（不阻塞落盘，persona 归档清单强制补齐）。
- **反堆砌三规则**：主干线唯一（一句话写清因果链）、删除测试（删了会迷路才留在主线）、前置检查（≤2 条直接前置 + 明确排除）。
- **可读性**：顶部 30 秒区；小节首句给结论；表格列数 ≤4；代码标语言、单块 ≤60 行；折叠块只藏细节不藏主线；术语首现给一句定义。
- frontmatter 后空一行再写定义；**不加尾部标签行**；存量旧卡不强迁，下次 `card_update replace` 时按新模板重写。

### 8.2 三种模板

| 模板 | 回答 | 必填小节 | 自动推断触发 |
| :-- | :-- | :-- | :-- |
| 理论型 | 为什么 | 核心思想/主干线/阶梯式解剖/实例走查/易错点/自测题 | 默认 |
| 工程型 | 怎么做 | 上述 + 验证实验（≥3 步）+ 排障判据 | 领域在 图形学/Unity/Shader/渲染 族，或标题含 接入/配置/参数/坑/实现/源码/变体 |
| 对比型 | 怎么选 | 核心思想/主干线/对比表/选型口诀/场景走查/易错点/自测题 | 标题含 对比/谱系/选型/取舍/差异/之争 |

`card_create` 的返回里会回显 `模板：工程型（按领域/标题推断，可用 template 覆盖）`；想强制某型就传 `template`。

### 8.3 完整样张

工程型样张（IBL 接入）与理论型骨架见 `presets/study/skills/card-format/SKILL.md` 的「完整样张」小节——含重入点、前置检查、主干线、四层解剖、实例走查、验证实验、排障判据、易错点、自测题、关联卡片的完整写法。

### 8.4 更新后的形态（活笔记）

- `append-version` 后：原卡内容不变，`### 版本更新（来源：X）` 插在**「关联卡片」之前**（2026-09 修复：旧版追加到文件末尾，阅读顺序被破坏）。
- `errata` 后：原结论保留，`### 勘误`（含纠正原因）同样插在关联卡片之前。
- `replace` 后：新卡 + 尾部 `<details><summary>历史版本（日期）</summary>…旧正文…</details>`（Obsidian 显示为可折叠块）。
- 三者都**不丢旧内容**——这是活笔记的底线。
- 想清掉历史块：`card_history({ref, action:'strip'})`（可 `kinds` 只清某类、`dryRun` 预演）；先 `card_history({ref, action:'list'})` 看有什么。

### 8.5 关联旧笔记（无 ID 的 .md）

- 检索命中中 `类型：旧笔记` 的目标**没有卡片 ID**，用其**根限定路径**寻址（如 `工作目录/子目录/笔记.md`；vault 内纯相对路径）。
- `card_link` 卡片↔旧笔记：默认只写卡片侧，卡片侧写作 `- 后续：旧笔记标题（工作目录/相对路径.md）`。
- 旧笔记↔旧笔记：默认拒绝 → 开启 preset `linkIntoNotes: true`（写入旧笔记「### 关联卡片」小节）或 Obsidian 内链 `[[笔记名]]`。
- 回答中提到旧笔记时标注 `（详见旧笔记：<根>/<相对路径>）`，不作卡片引用。

## 9. 在 Obsidian 中的配合

- **直接编辑**：卡片就是 `.md`，用 Obsidian 打开、编辑、打标签、移动都行；插件索引按 mtime/ctime/大小签名变化自动重扫，下次 `card_search` 即可见（见 [11.8](#118-索引为什么滞后-或-为什么明明编辑了却搜不到))。
- **wikilink 全通**：MOC 用 `[[文件名]]` 生成，Obsidian 内链、反向链接、图谱视图都正常工作。
- **git 管理**：vault 可整体 git 管理；卡片改动可回滚。插件写入用「临时文件 + rename」原子写，不会写坏一半（不会留下半个文件）。
- **不要做的事**：
  - 不要手改 `ID`、`标题`、`领域`、`来源`、`状态` 的字段名（解析只认这五键；手改内容随意）。
  - 不要指望 `card_id` 预生成的 ID 会被 `card_create` 采用（见 [7.2](#72-card_id生成占位-id)）。
  - 不要把旧笔记的「关联卡片」与 `card_link` 混用（重复行；用 `card_link` 就全用，手写就全手写，正文引用 ID 要等 create 之后）。
  - 移动/重命名文件不影响 `card_search`/`card_get`（按内容/ID 检索）；但**新卡落盘位置由 `domainFolders` 决定**——vault 目录重组后，务必同步更新 `domainFolders`（见 [4](#4-配置参考逐键详解) 与复盘文档）。
- **旧笔记原地升级**：想让某篇旧笔记变成卡片，可直接说"把这篇改成卡片"——Agent 走 `card_update(replace)` 原地升级，旧版本进历史折叠块，不另建新文件。

## 10. 检索原理与技巧

### 10.1 分词

- 中文：**双字组**（如「投影矩阵」→ 投影/影矩/矩阵），查询侧对 ≤4 字的短中文串额外展开单字提升召回。
- 英文/数字：按单词切分，长度 ≥2（`urp`、`0xff` 可检索）。
- 大小写不敏感；`_` 属于单词字符。

### 10.2 加权打分

| 字段 | 权重 |
| :-- | --: |
| 标题 | 4 |
| 一句话定义 | 3 |
| 领域标签 | 2 |
| 正文 | 1 |

同分按 卡片优先（kind 排序）→ 路径字典序。召回由插件做，语义判断由模型完成——所以检索词建议用**核心术语/概念名**，而不是完整句子。

### 10.3 过滤与限制

- `domain`：frontmatter `领域` 标签 或 旧笔记顶层目录名（推断领域）。
- `status`：`草稿`/`已确认`/`需更新`。
- `kind`：`card` 只出卡片 / `note` 只出旧笔记。
- `limit`：默认 5，最大 50。

### 10.4 引用寻址顺序

`card_get`/`card_update`/`card_link` 的 `ref`/`id` 解析顺序：**ID 精确 → 标题精确 → 路径/文件名候选唯一**。

### 10.5 歧义处理

- 根限定路径是最可靠的寻址方式：`vault/游戏开发/图形学/xx.md`、`工作目录/子目录/笔记.md`、`<searchRoot标签>/rel`。
- 多根下同名文件报歧义：

```
路径歧义："引擎.md" 命中多篇（vault/游戏/引擎.md、工作目录/引擎.md），请用根限定路径（如 "vault/xxx.md"）
```

- 找不到时的提示：`找不到卡片 "xxx"（可传 ID、标题、根限定路径 如 "工作目录/子目录/笔记.md"、相对路径或文件名）`。

### 10.6 实用检索词示例

| 目的 | 说法（对 Agent 下指令） |
| :-- | :-- |
| 找概念 | "我笔记里有没有讲过 红黑树？" / "检索一下 投影矩阵 的卡片" |
| 找旧笔记 | "在旧笔记里搜 分页 的内存管理"（Agent 会加 `kind=note` 或按命中类型筛选） |
| 按领域 | "检索 图形学 的 光照 卡片"（domain=图形学） |
| 按状态 | "把 需更新 的卡片列一下"（status=需更新） |

## 11. 故障排查手册

### 11.1 现象与原因速查

| 现象 | 可能原因 | 处理 |
| :-- | :-- | :-- |
| 会话能建，但没有任何 `card_*` 工具 | 插件未装入 profile / `file:` 依赖未刷新 / preset 配置文件被旧副本覆盖 | 核对 [3.3](#33-把插件装进你的-dsh-profile)、[3.7](#37-升级插件)；确认 `<profileDir>/node_modules/dsh-study-buddy` 存在且为最新 |
| 挂载报 `agent-preset-invalid` | `vaultRoot` 缺失/为空/为文件系统根，或 `searchRoots` 目录不存在 | 检查 `agent.cordis.yml` 的 `study` 行 config；`vaultRoot` 填绝对路径；`searchRoots` 建目录或删配置 |
| 修复插件配置后仍不生效 | 配置在预设副本，不在仓库 | 改 `%DSH_HOME%\.agent-presets\study\agent.cordis.yml` 并重启 |
| `card_search` 搜不到刚写/刚改的卡 | 索引签名缓存 + TTL（默认 2s） | 等 2 秒再搜，或设 `indexTtlMs: 0` 每次重扫；确认 `skipDirs` 没把该目录跳过 |
| `card_search` 搜不到旧笔记 | 旧笔记不在检索范围 | 检查 `includeSessionCwd` / `searchRoots`；命中会标 `类型：旧笔记`，无 ID 是正常标记 |
| 返回文本出现「⚠ 跳过 N 个文件」 | 这些文件读取失败（同步盘/被杀软或 Obsidian 锁定、无权限） | 解锁后重跑；报告数字只统计真正处理成功的文件，不再假装"完整" |
| `card_get` 报「找不到卡片」 | ref 不唯一/不匹配/跨根歧义 | 用 ID 或根限定路径（`vault/…`、`工作目录/…`、`<标签>/…`） |
| 报「路径歧义」 | 多根同名 | 补根前缀（见 [10.5](#105-歧义处理)） |
| 报「卡片校验失败」 | 必填缺项/status 非法/定义超长/**字段含换行**/标签含空格 | 按报错补字段；status 只能 `草稿/已确认/需更新`；标题与定义请写成单行 |
| 报「……位于只读检索根」 | 想写 `searchRoots`/工作目录里的文件 | 这些根默认只读；卡片一律写 vault 内，或开 `linkIntoNotes: true` |
| 报「目标文件名已存在……未做任何写入」 | 改名后文件名与库里已有文件撞名 | 换标题或先处理同名文件；该报错保证**什么都没改** |
| 报「改名失败并已回滚」 | 写入过程中被占用/权限不足 | 检查文件占用后重试；已写文件已恢复原状 |
| card_create 提示「已存在同名卡片」 | 同一概念重复建卡 | 改用 `card_update` 增量更新；确实要两张同名卡也可以忽略此提示 |
| card_create 提示「正文缺少 ### X 小节」 | 阶梯式解剖模板小节不全（警告，不阻塞） | 归档规范是补齐后再落盘（persona 硬强制）；存量旧卡不强迁，下次 replace 整卡时按新模板重写 |
| 报「卡片文件名冲突」 | 三档命名全撞 | 换标题 |
| 报「进度文件损坏/记忆文件损坏」 | `.study/*.json` 手改坏/磁盘异常 | 报错含文件名与原因；手动修复或删除该文件（回到空状态）；不静默降级是设计 |
| get 显示「自迭代记忆：异常值」 | `memory.json` 里 `_autoPrefs` 被手改为非 on/off | 读不崩（宽容显示）；`study_memory(set _autoPrefs=on/off)` 修复，或直接改回 on/off |
| 报「……目录不存在或不可读」 | vault 路径错/searchRoots 错 | 核对路径；searchRoots 在**挂载时**就报（fail-loud，不等首次搜索） |
| 报「两侧都是旧笔记（无 ID）：默认不写入旧笔记」 | 想给两篇旧笔记建关联 | 开 `linkIntoNotes: true` 或 Obsidian `[[]]` 内链 |
| `card_create` 落错目录 | 领域键未映射 / 映射改了没同步记忆 | 用映射过的领域键；`未分类/<领域名>/` 是未映射的兜底；子域键约定写进 `study_memory` |
| 正文里关联 ID 引用全错 | 用了 `card_id` 预生成 ID 写正文 | 见 [7.2](#72-card_id生成占位-id)；以 `card_create` 返回的实际 ID 为准 |
| Obsidian 手改后搜不到新内容 | 索引未重扫 | 等文件 mtime 变化（编辑就会变）；或触发一次写操作使签名失效后重扫 |
| 卡与旧笔记重复 | 旧笔记原地升级 vs 新建 | 说"把这篇改成卡片"走 replace；或新建后用 `card_link` 建关联，避免双份 |
| 读取 PDF 失败 | 缺 PyMuPDF | `pip install pymupdf`；仍失败走渲染 PNG + `read_image` 兜底 |
| 报告"图片：0 张"但课件里有图 | PPTX 背景/母版图遗漏、docx 绘图对象为 emf/wmf、提取命令失败 | 按失败链换兜底命令（PPTX→zipfile `ppt/media`；PDF→渲染整页）；仍无 → 请你导出图片/另存 PDF 重读；svg/emf/wmf 列入"需转换"，不假装读图 |
| 读取 PPTX 失败 | 缺 python-pptx | `pip install python-pptx` |

### 11.2 部署三要素自查（工具缺失时）

1. **插件**：`<profileDir>/node_modules/dsh-study-buddy/lib/index.js` 与仓库构建产物一致。
2. **预设**：`%DSH_HOME%\.agent-presets\study\` 为最新复制，`agent.cordis.yml` 含 `study` 行且 config 正确。
3. **进程**：DSH 重启过（`file:` 依赖与预设均在启动时加载）。

### 11.3 会话工具清单怎么验证

新会话第一条消息问 Agent："你的工具清单里有没有 card_search/card_create/study_progress？"（它可自述；最硬的证据是会话 `request/header` 事件的 tools 数组）。参考 `docs/check/prompt-verify-all-features.md` 可做一次全功能验证（会产生少量 `【验证】` 测试卡，完成后有清理指引）。

### 11.4 fail-loud 说明

插件对配置错误、注册失败、JSON 损坏都**直接抛错**，不静默降级。这是设计决定（曾因静默失败让故障潜伏数天，见复盘文档）——看到报错按提示修复即可，它比"静默缺工具"好得多。

## 12. 性能与成本

- **每请求固定开销**（persona + 工具 schema）：学习伙伴 ~15.0 KB / 21 个工具；标准模式 ~21.3 KB / 26 个工具。
- **日常成本**（V4-Flash，约 60 轮/天、2 小时学习，2026-08 定价）：高峰约 **¥0.9/天**，低谷约 **¥0.45/天**；月开销约 ¥14–27，换 V4 Pro 约 ×3。
- 精简省的主要是**延迟**（每轮少处理 ~1.1k tokens）；成本大头始终是输出与新鲜输入。
- 会话早期自动压缩历史（阈值 30%、保留 15%、上限 4096 tokens；对应模型策略 flash/pro 均配置），配合 `study_progress` 持久化，「接着讲」不依赖历史。

## 13. 已知限制与路线图

**当前限制**

- 检索为**关键词召回**（CJK 双字组 + 英文单词），无语义向量；近义/同义改写可能漏检（换词可缓解）。
- 每 apply 实例一个索引缓存（不跨挂载共享）；索引 TTL 默认 2s，因此**外部编辑最多 2 秒后才可见**（设 `indexTtlMs: 0` 可关闭缓存，代价是每次工具调用都扫全库）。
- 索引常驻全库正文（1000 卡 × 4KB ≈ 4MB）；十万卡级需要改懒加载（当前规模不需要）。
- `card_lint` 只覆盖 14 条可判定规则；persona 的"代码块 ≤60 行""表格列数 ≤4""小节间因果连接"等人工约束**没有自动校验**（见 7.7 的「能力边界」）。
- **内容会出境**：vault 正文、路径、进度与记忆都会随工具结果进入会话日志并发送给模型服务商（见 README「隐私」）。
- 卡片 ID 仅用于（跨文件）引用；Obsidian 里按文件名建链即可，无需关注 ID。
- 未挂载会话历史检索工具（`dsh-tool-session-query` 未随应用安装）；跨会话靠 `study_progress`/`study_memory`。
- 旧二进制 Office 格式（.ppt/.doc/.xls）不直接读，需转存。
- 多语言：仅支持 YAML 标量 frontmatter（五键）；其他字段会被忽略（不影响正文）。
- 记忆/进度中的指令性文本只给软提示，插件不做内容净化（安全边界是"你自己决定放什么进 vault"）。

**路线图**（README）

- 复习测验子模式（基于卡片库抽卡出题）
- 语义检索（嵌入向量）替代纯关键词召回
- 卡片浏览面板（客户端 Slot UI）
- `/整理笔记`、`/接着讲` 斜杠命令
- 多 vault 支持
- 复习元数据（`lastReviewed` / `recallScore`，支撑遗忘曲线——提案明确"先不做，避免过度设计"）
- `card_lint` 增两条低成本规则：代码块行数 >60、表格列数 >4（当前靠人工约束）
