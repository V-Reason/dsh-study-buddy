# 需求分析：计划感知与智能学习

> 版本基线：v1.4.0 ｜ 状态：已确认 ｜ 读者：需求方、插件维护者

## 一、目标

让「学习伙伴」理解当前计划、真实进度和当轮意图，在不增加第 20 个工具的前提下，改善以下三类日常问题：

1. 用户询问“今天学什么/从哪继续”时，给出一个可执行的主线下一步，而不是复述计划或泛泛建议。
2. 自动讲解深度由意图、问题范围、计划情境和笔记证据综合判断，模式默认不展示。
3. 用户主动要求时可审计笔记可发现性，并在确认后只修元数据，不改变正文。

## 二、优先级与明确边界

- 优先级：计划衔接 > 优化现有能力 > 增加新功能。
- 不做定时、主动或后台复习提醒，不做遗忘曲线、出题或白板考官。
- 新会话静默读取记忆、进度和《笔记期望.md》；普通问题直接回答，只有明确继续意图才展示学习简报。
- 完成一个完整知识单元或明确项目动作后自动更新进度；追问、临时分支和未完成工作不推进正式阶段。
- 自动模式默认不展示快速/详细标签；证据不足时使用详细讲解。
- 笔记维护第一版只聚焦可发现性：来源章节、微目录、孤立笔记和断链。
- 修复前展示目标与字段；确认后只改 frontmatter、微目录和明确 wikilink，正文逐字不变。
- 不批量重写旧原子卡；无 ID 旧笔记默认只读，不要求迁移。

## 三、计划入口

用户明确询问“今天学什么/从哪继续/我回来了”时，插件结合计划引用、当前阶段、实际位置、下一动作、完成判据、最近结果和并行线给出简短入口。

默认只突出一个主线动作；八股、算法和投递作为简短并行进度，不展开为任务管理系统。用户当轮明确请求优先于历史计划；计划负责路线，进度负责位置，用户最新陈述可纠正两者。

## 四、模式判断

保留 `快速 / 详细 / 自动` 三个用户入口，并增加以下内部意图信号：

- `direct`：单点直答。
- `refresh`：明确回顾，允许结合近期笔记走快速。
- `learn`、`apply`、`debug`、`compare`：从零学习、落地、排错或系统比较，默认详细。
- `single`、`concept`、`system`：问题范围；系统范围默认详细。

显式快速/详细覆盖始终优先。没有相关笔记、没有接触证据或无法判断时一律详细。

## 五、笔记维护

用户主动要求“笔记体检”时，审计指定目录；全库体检必须显式传 `path='.'`。审计只报告：

- 有 ID 但缺来源章节；
- 来源章节无法参与覆盖度聚合；
- 主题目录缺微目录；
- 没有入链的孤立笔记；
- 断链或歧义 wikilink；
- 同范围重复标题。

修复必须由用户确认。允许修改 `来源章节`、`状态`、微目录和明确 wikilink；不允许借维护之名重写正文。

## 六、验收

1. 普通新会话问题不出现断点提示、复习提醒或“接着讲？”。
2. “今天从哪开始”只给一个主线动作、完成判据和简短并行线。
3. 完成单元后自动收口，中途追问不推进。
4. 自动模式证据不足时详细；手动模式正常覆盖。
5. 模式默认隐身。
6. 指定目录审计能发现缺来源章节、缺微目录、孤立和断链。
7. 元数据修复后正文逐字一致，未知 frontmatter 键保留。
8. 工具总数保持 19，旧 `.study` 数据可继续读取。
