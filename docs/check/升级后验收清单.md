# 升级后验收清单（DSH 本体 / 插件 / 预设）

> 读者：本机部署者。用途：**DSH 升级、插件升级或重铺预设之后**，用 5 分钟确认"跑起来的那份代码
> 真的是我刚改的那份"，而不是等到下次归档才发现工具不见了。
>
> 两条只读命令能判的，就别靠肉眼：判读口径见 [`../../tools/README.md`](../../tools/README.md)。

---

## 0. 命令层（先跑，10 秒）

```powershell
cd <插件仓库>
pnpm run verify:contract                       # 交付形态 + 插件 ↔ 本机 DSH 的契约（应 22 条断言全绿）
pnpm run verify:deploy -- -Profile web         # 产物哈希 / bundle 选中 / 预设 patch / legacy 目录 / 技能 / 《笔记期望.md》
```

- [ ] 两条都返回 0（`verify:deploy` 的每一节都 `OK`，无 `FAIL`）
- [ ] 若 `verify:deploy` 报产物哈希或预设 patch 不一致 → 先刷新安装副本（用户指南 §3.7），再回到本节重跑
- [ ] 若报"`dsh.profile.bundles` 没有本包" → 预设不会被声明：`plugin_manager set_bundle target=dsh-study-buddy enabled=true`
- [ ] 若报"legacy 预设目录还在" → 按用户指南 §3.4 删掉 `%DSH_HOME%\.agent-presets\study\`（它没有读者）

## 0.1 挂载层（DSH 侧，只读两步）

- [ ] `plugin_manager list_bundles`：本包在列且 `enabled`
- [ ] `plugin_manager list_plugins`：出现 `include:preset-study` 且 `fiberPhase: active`
      （`failed` 时它的 diagnostic 就是根因；**行不存在 = 声明没进 profile**）

## 1. 会话层（重启 DSH 后新建一个「学习伙伴」会话）

- [ ] 工具列表里是 **18 个** `note_*` / `study_*`，且**没有任何 `card_*`**
      （`card_*` 还在 = 预设没换成功，或会话在使用旧的 standing mount）
- [ ] 首条消息的硬门禁生效：先 `study_memory(get)` + `study_progress(get)`，读完才回应
      （这一条同时验证 `systemPrompt.section` 与 `agent/pre-step` 两条接线在真机活着）
- [ ] `note_library(check)` 输出库状态：块/存量卡/旧笔记计数、`笔记期望：已读`、待消费规划

## 2. 归档链路（本清单的核心：三条硬门禁 + 一次真实落盘）

- [ ] `note_expect_get` 成功（vault 根有《笔记期望.md》；没有会明确报"请先复制模板"）
- [ ] `note_plan` 出提案，**只在对话里**（不落盘），等你拍板
- [ ] `note_write` 落一个块：先 `note_expect_get` → 再 `note_plan` → 才允许写
- [ ] 故意跳过一步再试（例如不读期望直接写、或路径写到规划根之外）：**必须被拒且磁盘零改动**
- [ ] `note_toc` 生成/刷新该目录的 `微目录.md`；你手写的导读段仍在
- [ ] `note_overview` 的覆盖度按 `来源章节` 聚合，不虚构章节

## 3. 数据与迁移（只确认，不改动）

- [ ] `.study/progress.json` 里的旧卡片 ID 不影响使用（`note_get` 找不到是正常的，不是缺陷）
- [ ] 卡片时代的 `目录/`（历史 MOC）**不再被工具读取**；要不要归档由你决定（v1.0 的导航改由各级 `微目录.md` 承担）
- [ ] 《笔记期望.md》按你的写法改过之后，Agent 会重新读取（签名变即失效，不需重启）

## 4. 出问题时的定位顺序

1. **全都没有**（无工具、无门禁提醒）→ 先看**行是否存在**：`plugin_manager list_plugins` 有
   `include:preset-study` 吗？没有 = 交付形态问题（bundle 没装/没选中、patch 路径错、还被 legacy 目录误导），
   用 `pnpm run verify:deploy` 逐节定位；有但 `failed` = 看它的 diagnostic（多半是 `vaultRoot`，见用户指南 §3.5）。
2. **工具在但行为不对**（模型调不存在的工具、归档被拒）→ 预设或 vault 侧：`verify:deploy` 的交付形态与 vault 两节。
3. **契约类报错**（`no create() factory`、`does not provide an export named`、`pending (waiting for services)`）
   → 平台契约变了：`pnpm run verify:contract` 会指到具体的平台 `文件:行号`，照它去 DSH 工作树 HEAD 读现行定义，
   改 `src/host.ts` 的探测与 `HOST_CONTRACTS` 表。
4. 以上都不中 → 用户指南 [§11 故障排查手册](../用户使用指南.md#11-故障排查手册)。
