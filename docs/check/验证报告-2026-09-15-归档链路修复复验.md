## 二、逐条修复证据（源码级）

### 2.1 P0 — `notePlan` 补 `confirm` 分支

上游报告的根因链是：`buildPlanRecord` 写死 `confirmed: false` → 全仓库没有置位点 → `gate.checkPlan` 与
`planstore.consumePlanItem` 两道校验先后拦下 → 报错文案里的 `note_plan(action=confirm)` 是空头支票。

现在：

- `notePlan` 的 `action` 支持 `create` / `confirm` / `abandon`；`confirm` 与 `abandon` 都从 `rootPath` 取 planId，
  因此 `src/tools.ts` 的 `required: ['rootPath', 'items']` **不需要随动作漂移**（模型也只需照抄提案里的 planId）。
- `confirm` 置位 `confirmed: true` + `confirmedAt`，并把 `createdAt` 重置为确认时刻（有效期从凭据生效时刻起算；
  搁置超过 `planTtlHours` 的提案仍要求重新提案，且**拒绝时磁盘零改动**）。
- 两道门禁的拒绝文案改为**就本次 planId 给出可直接执行的调用式**：
  `请让用户拍板后用 note_plan({ action: "confirm", rootPath: "<planId>" }) 确认`。
- `note_plan` 出提案后的尾注也改成"拍板后先 confirm，再逐个 note_write"。

**测试不再绕过那一步**：`tests/noteflow.spec.ts` 的 `planAndConfirm` 删掉了"手改 `.study/plans/<id>.json` 置位 `confirmed`"
的写法（上游报告 §3.1「测试为什么没抓到」的正是它），改走真实 `confirm`；16 个既有用例因此全部获得真实确认路径覆盖。

### 2.2 P0′ — 新查出：`generatePlanId` 补零死锁

修复 confirm 的过程中撞到第二条同源缺陷（上游报告未覆盖）：

```
planId：202609152306_xxxxxx        ← 23:06 生成，12 位，正常
planId：202609150907_xxxxxx        ← 09:07（或 00:00~09:59 任意时刻）生成 → 只有 11 位
```

原实现的 `pad(now.getHours())` 是 `String(h).padStart(2,'0')`，而 `String(9)` 长度为 1、`padStart(2)` **补不满两位**，
所以 00:00~09:59（以及每月 1~9 日的日期位同类风险）生成的 id 只有 11 位，而 `planFileFor` 的校验式要求恰好 12 位：

> 同一个 planId 传回 `confirm` / `note_write` 时被**自己的合法性校验**拒绝——"凭据刚发出去就读不回来"，
> 正是门禁最该避免的死锁形态（与 P0 同类：门禁可写不可开）。

修法：`planstore.ts` 统一 `pad2()`，四个两位字段（月/日/时/分）都补零；
`tests/gate.spec.ts` 增一条不变量断言：**刚生成的 id 必须能立刻换回路径**，并用 `new Date(2026, 0, 5, 9, 7)`、
`00:00`、`23:59` 三个边界钉住。

### 2.3 P1 — 批量体检去掉均分

`LintBatch.average` 字段与 `formatBatch` 的"平均问题数：N 条"一并删除，首行改为
`- 有问题的文档：N 篇（共 M 篇）`；问题数分布、规则命中、问题最多的文档保持不变。
理由与上游报告 §3.4 一致：100 分制已随模板退场（架构选型 A9），"平均问题数"同属把问题当分数的残留口径。
`tests/lint.spec.ts` 改为断言 `'average' in batch === false` 与输出不含"平均"。

### 2.4 P2 — 简介与正文首句去重

`renderNote` 原本用 `doc.summary?.trim() || extractDefinition(doc.content)` 同时决定 frontmatter `简介` 与正文前置引用块，
于是"正文自带 `> …` 定位"（《笔记期望.md》要求的术语首现写法）会**同时**出现在 `简介:` 与正文首行。

现在只有**显式传 `summary`** 才前置引用块；缺省时由正文那一行充当定位（`简介` 仍从它提取）。
兼容口径：`> 概念: …` 这类旧形态仍优先取概念行，正文自带引用块保留（不回归），测试有对应用例。

### 2.5 P1/P2 — 验证清单订正

`docs/check/prompt-verify-all-features.md`：

- 第 12 项：明确"门禁按序短路，一次只说一个问题"，判定标准改为**被拒 + 磁盘零改动**，并给出新会话复现方式（新增会话首条即 `note_write`）。
- 第 14 项：补"报错里的修复动作必须真的可用"。
- 新增 18b：`note_plan(action=confirm)` 步骤与幂等核对。
- 第 20 项：改用"把同一标题写到**规划内的另一个路径**"才能命中消费记账（原写法先撞"目标已存在"，见上游 §3.5）。
- 第 29 项：`note_restore` 是**独立工具**（原写成 `note_update({action:'restore'})`）。
- 第 34/35 项：参数名是 `title`（原写成 `newTitle`）。
- 新增 36b：正文首行 `> …` 只出现一次的核对。
- 第 37 项：补"也不出现'平均'字样"。
- 收尾：清理项补 `.study/plans/<planId>.json`。
