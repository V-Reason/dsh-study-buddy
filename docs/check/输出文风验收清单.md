# 输出文风与自适应讲解验收清单

> 版本基线：v1.8.0 ｜ 适用：真实 DSH「学习伙伴」会话
>
> 自动化测试负责模式判断、状态持久化和提示词契约；本清单负责人工检查实际生成文本是否存在机械感、重复和信息泔水。

## 检查口径

- 先看内容是否有用，再看结构是否克制。
- 单一问题不出现多余标题；列表只承载真正的并列或步骤；表格只承载二维对照。
- 依赖、层级、状态、时序、数据流和复杂失败链优先用图；简单事实不为了图文感硬画图。
- 图示必须承载结构信息，图旁只解释关键边、触发条件和失效点，不逐节点复述。
- 讲解与笔记均可使用 Mermaid；渲染失败或用户表示看不到时，回退为紧凑文本图。
- 第一屏先用具体故障、数字或真实运行建立问题，再给一句话结论；之后才进入对象关系、状态变化和适用边界。
- 项目课程先有已批准的课程母图；每轮带当前地图位置、上一输出、本轮改变与下一消费方，不按源码目录临时拼课。
- 载重概念必须在依赖它的源码之前出现；历史笔记、近期接触和快速模式只能压缩深度，不能跳过概念本身。
- 代码机制按“问题锚点 → 载重概念先修 → 对象与时机 → 一个因果轨迹 → 真实代码证据 → 检查与边界”推进；单轮只保留一个主机制、一个原子因果片段和最多两个直接后果。
- 一轮给出足以复述当前一步的证据后即停；用户提问只答被问的一点，用户说“继续”才进入下一段。
- 用户说“没懂 / 讲乱了 / 太唐突 / 啰嗦 / 回答简单一点”后，下一轮必须缩小范围并换介质，不能继续加长。
- 不主动测验、不留思考题；只有用户明确要求检验理解时才提问。
- 对话讲解与自研项目正式笔记分开验收：对话保持最小证据；工程复用档笔记必须让读者不重读源码就能定位对象、入口、契约、实现、测试与诊断。
- 一段只承载一个观点；同一段出现两条以上并行因果链时，改为图、差异表或编号步骤。
- 包含生命周期、多方交互或跨时刻状态变化的笔记至少有一张主图；每篇只设一张主图。
- 每张图必须替代至少三四句本来要写的话，或揭示文字不易看出的边界；只做装饰的图删掉。
- 笔记正文从唯一 H1 开始，H1 后接普通导语；引用块只放外部原文，不放在 H1 前充当重复摘要。
- 同一结论不在正文、列表、表格和结尾总结里反复出现。
- 正文不默认出现“90 秒口径”、面试问答或下一步邀请；用户明确要求时才单独生成。
- 读取报告与普通回复自然结束，不机械追加“待命中/可指令”。
- 自动模式默认不展示快速/详细标签；只有用户询问依据或判断存在歧义时解释一行。
- 不做主动复习提醒，不生成待复习队列。

## 反例与目标写法

反例：

> 真正值钱的是这条：引用不传递。这条坑值得讲三遍，因为报错和真因完全对不上。一句话收口：asmdef 是配置源，csproj 是执行清单，dotnet 是驱动 MSBuild 的手。

目标写法：

> Unity 的 asmdef 引用不传递。测试程序集只引用 Presentation 时，看不到 Foundation 中定义的 `Singleton<T>`，因此会同时报 `CS0012` 和 `CS0117`。asmdef 声明 Unity 的程序集边界，Unity 据此生成 csproj，dotnet 再通过 MSBuild 编译。

反例的问题是按“值得强调”组织内容，先评价再解释，最后用金句重复。目标写法直接给出条件、结果和因果链。

图型反例：把装配依赖、跨组件调用、暂停状态和同帧执行顺序全部画成 `flowchart`。读者仍不知道每一步发生在哪个时刻，也无法区分调用、状态和顺序。

图型好例：装配依赖用 `flowchart`，跨组件调用用 `sequenceDiagram`，暂停状态用 `stateDiagram-v2`，同帧推进顺序用 `timeline`。删除主图后，读者会失去该篇最关键的时序或边界。

工程笔记反例：

> 只写“这里有三条硬边”和几段结论，代码位置、字段接线、失败日志、相关测试和诊断入口全部留给读者回项目里找。

工程笔记好例：

> 给出完整源码地图和符号入口，保留关键代码切片，列出接口/状态契约、失败现象、现有测试与证据级别；读者能仅凭本篇复现机制并判断改动后果。仍不逐行抄录整个类。

源码定位使用仓库相对路径加符号名，不用本机绝对路径或易漂移的行号。关键结论分别标“源码已核对、测试已覆盖、运行已观察、待验证”，未执行的验证只写步骤，不冒充观察结果。

工程笔记由 `lint.engineeringPaths` 显式启用；`lint.sourceRoots` 提供源码项目根。坏 Mermaid、未闭合围栏、已知根下不存在的源码路径会在 `note_write` / `note_update` 写盘前阻断；缺源码地图或证据级只告警。`note_lint` 与 `note_write` 必须给出一致判断。

`note-format` 是工程笔记最低质量要求的唯一执行来源。“没有固定模板”不等于允许用摘要代替可复用实现。工程机制笔记正式落盘前先走 `note_write(dryRun)`；硬 error 必须修，源码地图、证据级、主图预算等 warning 默认补齐或写明不适用。

`note_lint=0` 只表示数据卫生和结构信号通过，不证明概念顺序正确。人工语义检查至少确认：根问题可观察、载重概念先于源码、H2 形成因果链、存在真实状态 trace、验证和失效边界可执行。

结构关系优先使用下列形式：

| 关系 | 优先形式 |
| :-- | :-- |
| 线性因果、短调用链 | `A → B → C`、编号步骤或 Mermaid `timeline` |
| 层级、依赖方向、分支 | Mermaid `flowchart`，复杂时配合缩进树 |
| 类、接口、继承与实现 | Mermaid `classDiagram` + 关键代码 |
| 表、字段、主外键 | Mermaid `erDiagram` + 字段表 |
| 多方交互时序 | Mermaid `sequenceDiagram` |
| 状态迁移 | Mermaid `stateDiagram-v2` |
| 版本、里程碑和时间线 | Mermaid `timeline` |
| 多对象共同维度 | Markdown 表格 |

## 场景矩阵

| # | 输入 | 预期 |
| :-- | :-- | :-- |
| 1 | 对一个从未讲解、笔记库无相关主题的概念说“讲解” | 进入详细模式；问题锚点和载重概念先建立；一个原子因果片段后停下；无强迫确认问题；无自动预览 |
| 2 | 对近期已学习且有相关笔记的障碍烘焙主题再问 | 可进入快速模式，但仍先补齐距离场/SDF 的一句话定位；随后进入当前实现 |
| 3 | 把最近接触改成 31 天前后再问 | 回退详细；不自动弹出复习提醒，用户追问时能解释依据 |
| 4 | 说“快速”后连续追问 | 本会话持续快速；不逐轮重复模式标签 |
| 5 | 说“详细”后问一个简单定义 | 本会话保持详细；仍不堆砌无关背景 |
| 6 | 说“自动” | 清除会话覆盖；下一主题重新按证据判断 |
| 7 | 输入“模式” | 显示当前会话模式、最近主题和最近判断 |
| 8 | 普通答疑 | 直接回答；机制与边界按需；最多一个追问 |
| 9 | 说“别问了”后继续提问 | 后续不再主动追问 |
| 10 | 讲解结束后不额外发令 | 默认没有笔记预览 |
| 11 | 说“看笔记预览” | 才生成预览，内容不重复讲解全文 |
| 12 | 读取一个文件 | 只出文件信息、骨架、图片事实和可选重叠预警；无机械待命尾注 |
| 13 | 在快速模式执行归档 | 正式笔记仍按《笔记期望.md》完整可读 |
| 14 | 两个相同 cwd 的新会话分别切换模式 | 手动覆盖互不影响；新会话默认自动 |
| 15 | 新会话直接问普通技术问题 | 不展示断点、不询问“接着讲”、不出现复习提醒 |
| 16 | 说“今天从哪继续” | 一个主线下一步、完成判据、简短并行线 |
| 17 | 问一个单点事实题 | 直接回答，不扩写成完整课程 |
| 18 | 说“从零讲清一个系统设计” | 即使近期有笔记也使用详细讲解 |
| 19 | 讲解依赖图、状态机或导表流程 | 选用最轻且准确的图；图旁只解释关键边、条件和失效点 |
| 20 | 重写一篇项目复盘 | H1 后接普通导语；主次由 H2/H3 表达；无重复摘要与默认 90 秒收尾 |
| 21 | 讲一个包含表项结构、构造和执行的方法 | 先用问题说明它为何存在，再定义载重概念、交代对象与时机和状态 trace；不先丢类型名让用户猜 |
| 22 | 在同一轮追问三个以上机制 | 拆成可独立验收的回答；未展开项不造成当前主机制不可理解 |
| 23 | 讲完一个机制后不额外发令 | 自然结束，没有 `Next:`、下一站、下一步预告或自动邀请 |
| 24 | 打开一篇包含生命周期或跨时刻状态变化的笔记 | 有一张承担关键关系的主图；图型与关系匹配，不是全篇 `flowchart` |
| 25 | 阅读一篇很长但噪声很低的技术讲解 | 能沿问题、载重概念、对象与时机、状态 trace、代码和失效边界复述主线；删除图后会丢失关键顺序或边界 |
| 26 | 对比朴素写法与当前实现 | 优先用并排代码、diff 或共同维度矩阵；差异落到调用点、状态变化或可观测现象 |
| 27 | 讲解一道算法题 | 有不变量、一个小输入的 trace/图、正确性、复杂度、边界和代码，不先堆题面复述 |
| 28 | 讲解一次排障 | 从可见症状和最小复现出发，证据先于根因，并给回归验证 |
| 29 | 用户在 Mermaid 渲染失败后反馈看不清 | 切换为紧凑 ASCII 或文本步骤，不重复原图全部节点 |
| 30 | 要求把自研项目复盘做成“以后不用回源码”的工程百科 | 覆盖所有权、源码地图、接口/状态契约、实现切片、取舍、失败恢复、测试与诊断；关键结论有证据级别 |
| 31 | 检查一篇源码机制笔记的离线复用性 | 能从笔记定位核心类型、入口方法、相关测试和诊断命令；删除源码地图后会明显增加重新定位成本 |
| 32 | 工程笔记写入坏 Mermaid 或未闭合围栏 | 写前预检报 error，目标文件不存在，规划项不被消费 |
| 33 | 工程笔记引用已知根下不存在的 `Assets/.../Type.cs` | `source-reference` 报 error；没有项目根可查时只报 info 待验证 |
| 34 | 工程笔记缺源码地图或证据级 | 写入成功但回显 warning，不把质量缺口伪装成硬失败或静默通过 |
| 35 | 工程机制笔记只有三条结论、没有源码入口或失效边界 | 不进入正式写入；先按质量闸回读源码并补齐覆盖清单 |
| 36 | 工程笔记很长但重复、没有验证路径 | 删除重复，补齐可执行验证；篇幅不作为完成判据 |
| 37 | 纯决策或复盘总览没有核心代码切片 | 允许，但必须在正文说明范围、判断依据、证据状态以及源码地图为何不适用 |
| 38 | dryRun 返回源码地图或证据 warning | 默认补齐或说明不适用，再正式 `note_write`；不能把已返回 warning 当作通过 |
| 39 | 首次讲解“障碍烘焙” | 先说清运行时查询压力与距离场，再区分 SDF 和截断无符号距离场；源码不得先于概念出现 |
| 40 | 用户回答“没懂这里的 Δ 不等式” | 只保留两个采样点、一堵墙和一组具体数字，换 trace 展示；不扩讲整条物理查询链 |
| 41 | 用户说“还是没懂，怎么这么唐突” | 承认缺少流程位置并补一个最小总流程，再回到刚才那一步；不能用篇幅掩盖顺序错误 |
| 42 | 用户问一个单点问题后没有说“继续” | 只回答该问题并结束，不自动进入下一子目标 |
| 43 | 用户说“跳过先修” | 当前主题不再展开概念推导，但仍保留一句概念定位和必要边界 |
| 44 | 检查 `note_lint=0` 的工程笔记 | 继续人工检查根问题、概念顺序、因果链、状态 trace、源码地图和失效边界是否真实存在 |
| 45 | 首次要求系统复盘整个项目 | 先进入课程编译，建立全文件清单和完整运行链；不得直接按目录开讲 |
| 46 | 课程母图未验证或来源已变化 | `study_course(status)` 明确 stale，拒绝 `position` 和沿旧路线续讲 |
| 47 | 用户尚未批准课程母图 | 不调用 `activate`；沉默、“继续看看”都由用户另行确认 |
| 48 | 已激活课程开始一轮 | 先给当前地图位置、上一输出、本轮改变和下一消费方，再推进一个因果片段 |
| 49 | 用户只发“继续” | 推进下一节点，不改写为“已掌握”，不主动测验或追问 |
| 50 | 课程笔记缺课程锚点字段 | `course-anchor` lint 报 error，不能把缺上下游的正文称为完整课程笔记 |

## 自动验证

```bash
pnpm run check
pnpm run verify:contract
```

另确认 `.study/learning.json` 能跨会话保留主题足迹，且损坏时会明确报错而不是静默清零。
