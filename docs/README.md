## 2. 可执行验收

`check/` 保留能直接指导真机验证的材料：

- [`prompt-verify-all-features.md`](check/prompt-verify-all-features.md)：新会话全功能验证。
- [`升级后验收清单.md`](check/升级后验收清单.md)：DSH、插件或 profile 升级后的部署验收。
- [`输出文风验收清单.md`](check/输出文风验收清单.md)：自适应讲解与自然正文检查。
- [`计划感知与智能学习验收清单.md`](check/计划感知与智能学习验收清单.md)：计划入口、模式隐身与审计。
- [`教学文风V2样稿.md`](check/教学文风V2样稿.md)：代码机制与算法讲解的目标样稿。

两条例行只读校验来自仓库根 [`tools/`](../tools/README.md)：

```powershell
pnpm run verify:contract
pnpm run verify:deploy -- -Profile desktop
```

## 3. 改代码时的同步关系

| 改动 | 必须同步 |
| :-- | :-- |
| 用户可见行为、配置键、报错文案 | `用户使用指南.md`，必要时更新验收清单 |
| 新工具或 schema | `技术文档.md`、`用户使用指南.md`、工具集合测试 |
| 门禁、存档、替换或改名语义 | `设计文档.md`、`技术文档.md`、端到端测试 |
| lint 规则 | `src/lint.ts`、`技术文档.md`、`用户使用指南.md`、lint 测试 |
| 构建、peer、bundle 或部署形态 | `技术文档.md`、`开发维护与回归.md`、`tools/README.md` |
| 版本号 | 两个 manifest、`更新记录.md`、现行文档基线、构建产物 |
| 模块数、测试文件数或测试项数 | 只改 `技术文档.md`，由 `tests/docs.spec.ts` 现算校验 |

版本号是最后一刀：代码、测试和文档全部完成后同时更新 `package.json` 与
`dsh.plugin.json`，重新构建并跑完整检查。

## 4. 维护约定

1. 同一事实只在最接近实现的位置定义，其它文档做投影并链接过去。
2. 能被测试校验的文档事实就写成守卫，包括链接、锚点、版本和数字。
3. 历史快照不改写结论；移动后只修相对路径。
4. 已完成的实施计划从现行目录移入 `archive/refactor/`。
5. 真机报告按日期归档；需要复验时新建报告，不回改旧报告。
6. 完整缺陷调查归档，现行维护文档只保留状态、根因摘要与回归入口。
7. 发布前必须通过类型检查、全部测试、构建、契约校验和部署校验。
