# 卡片格式与质量重设计建议（2026-09-09）

> 状态：提案，待拍板
> 输入：① 15 张卡片的抽样调研（跨时间、跨类型）② 用户新增期望（取消字数限制、优化可读性、目标是"遗忘后能快速捡起"、面向"忘掉大部分内容的小白"也能读懂）
> 关联代码：`src/card.ts`（模板与校验）、`src/index.ts`（工具注册）、`presets/study/agent.cordis.yml`（persona 口径）、`docs/用户使用指南.md`

## 0. TL;DR

1. **卡片的目标要换**：从"原子知识块"改成"**可独立复读的微课程**"——判据不是"写全了没有"，而是"忘光了的人能不能在 30 分钟里重建它"。
2. **正文取消字数限制**（上下限都取消）。代码里本来就没有正文长度校验，需要改的是 skill/persona 文档里的"≥400 字""目标 600~1500 字"这类暗示性约束。
3. **定义字段仍保留短约束**（≤30 字最佳、≤60 字硬限）：它是检索契约与 TL;DR，不是知识载体，变长会让检索与扫读一起失效。
4. **长度不是问题，"无逻辑堆砌"才是**。用三条规则替代字数：**主干线唯一**、**删除测试**、**前置检查**。
5. **新增四个小节**：`重入点`（30 秒 / 5 分钟 / 30 分钟三种读法）、`前置检查`（读它前需要知道什么）、`验证实验`（工程型必填）、`排障判据`（工程型必填）。
6. **模板分型**：理论型 / 工程型 / 对比型。一套模板硬套两类卡，必然一边臃肿一边空洞（调研实证）。
7. **版本更新块位置是 bug**：`append-version`/`errata` 现在追加到文件末尾，落在「关联卡片」之后，阅读顺序被破坏。
8. **质量可以量化**：9 项可自动检测的指标（会话残留、代码块语言、验证步骤数、自测题答案率…），落成 `card_lint` 工具。
9. **今天的 8 张新卡不是终点**：它们解决了"去会话化"，但还没解决"重入点/前置检查/主干线显式化"。
10. **验收方式**：遗忘测试——只给标题，限时 5 分钟复述，按覆盖度与因果连贯度打分；用现有 215 张卡跑基线。

## 1. 背景

### 1.1 用户期望（本次新增）

> 取消卡片笔记的字数限制；格式优化便于阅读；目的是**内容详尽，使得经过遗忘后能通过翻看笔记快速捡起来**，而不是让知识无逻辑地堆砌，使得一个遗忘了大部分内容的"小白"无法阅读学习。

拆成四条可执行的要求：

| # | 要求 | 落到设计上的含义 |
| :-- | :-- | :-- |
| R1 | 取消字数限制 | 正文长度由信息完备性决定；字数不再作为质量信号 |
| R2 | 格式便于阅读 | 有扫读层、有视觉层级、有导航、术语可解释 |
| R3 | 遗忘后快速捡起 | 卡内有"重入点"，读者能从任意起点重建 |
| R4 | 不堆砌、小白可读 | 唯一主干线、因果连接、前置可查 |

### 1.2 调研结论（15 张样本）

样本覆盖：2026-08-16（教科书型）→ 08-25（深推导型）→ 08-27（算法型 / 对比型 / 理论+工程口径）→ 09-09（工程型 / 思想型）→ 09-09 晚（二次加工后的 8 张新卡）。

**核心发现**：卡片的差距几乎全部落在**可检测的结构特征**上，而不是"写得好不好"这种主观判断。这直接支撑了"把质量指标化、把 lint 工具化"的路线。

### 2.2 七个反复出现的质量问题

按"可自动化程度"排序：

1. **会话残留**：文件路径、源码行号、第二人称、"本工程 / W2 / P0"这类阶段代号。让卡片半年后不可读。
2. **验证实验缺失**：7 张旧卡里只有 1 张有可执行验证——这是"读完仍不会用"的直接原因。
3. **版本更新块位置错误**：`src/card.ts:169/174` 把 `append-version`/`errata` 追加到文件末尾，于是阅读顺序变成"知识 → 关联卡片 → 新知识"。
4. **关联卡片块三种写法混用**：`标题`（ID）／裸标题／标题（章节注释）。与 `addLink` 的判重逻辑同源——`src/card.ts:236` 只在有 ID 时按 `（ID）` 判重，格式不统一就会追加出重复行。
5. **自测题格式漂移**：`Q1/Q2` 与 `1./2./3.` 并存，且存在"只有问题没有答案"的卡。
6. **阶梯式解剖层数无约束**：4 层 / 5 层 / 6 层并存，有的还丢了"第 N 层"序号。
7. **领域标签分裂**：`#图形学`（根域）与 `#图形学-光照模型`（子域）混用，同一主题散落在根目录与子目录。

### 2.3 三个根因

| 根因 | 表现 | 对应设计动作 |
| :-- | :-- | :-- |
| 模板只有一套，但卡片有两类需求 | 工程卡缺代码、理论卡被迫塞工程细节 | 模板分型（§4.2） |
| 质量靠人自觉，没有可检测信号 | 会话残留、缺验证、格式漂移反复出现 | 指标化 + lint（§5） |
| 卡片假设读者"刚学完" | 遗忘后读不懂、缺前置、无重入点 | 重入点 + 前置检查 + 主干线（§3） |

## 3. 设计转向

### 3.1 从"原子知识块"到"可复读的微课程"

旧定位：卡片 = 一个原子知识点，用于检索与复习。
新定位：卡片 = **一个可以独立读完的微课程**，假设读者已经忘光了 80%。

这个转向带来三个必然结论：

- **长度必须放开**：要重建理解，就得有足够铺垫（前置概念、为什么需要它、失败会怎样）。
- **必须有主线**：内容越多，越需要一条明确的因果链，否则就是堆砌。
- **必须面向"零记忆读者"**：术语首现解释、前置卡链接、重入点提示。

### 3.2 三类读者与三种读法

| 读者状态 | 想干什么 | 卡内应该提供 |
| :-- | :-- | :-- |
| 完全遗忘（小白） | 从头学一遍 | 前置检查 → 主干线 → 分层解剖 → 数值/代码走查 |
| 半遗忘（记得名字） | 快速捡起 | 30 秒区：一句话定义 + 心智模型 + 主干线一句话 |
| 未遗忘（在干活） | 查一个细节 | 表格 / 代码片段 / 排障判据（能跳读定位） |

**这决定了卡的物理结构**：顶部 30 秒区（给半遗忘者）→ 中部主干线与分层（给小白）→ 底部查表区（给干活的人）。三种读法互不干扰。

### 3.3 取消字数限制：依据与替代约束

**现状**：`src/card.ts` 对正文**没有任何长度校验**；"≥400 字""目标 600~1500 字"只写在 skill 文档里。所以 R1 主要是**文档口径调整**，不是代码改动。

**建议**：

| 项 | 现状 | 建议 |
| :-- | :-- | :-- |
| 正文字数 | skill 写"≥400 字，目标 600~1500" | **取消上下限**，改为"信息完备性"自检 |
| 定义字数 | ≤30 最佳，≤60 硬限（代码硬拒绝） | **保留**（检索契约与 TL;DR，不属于知识载体） |
| 单卡主题数 | 隐含"一个知识点" | **显式要求单一主题**；主题变大时拆卡，而不是把卡写长 |

**替代约束**（防止"取消字数"变成"无限膨胀"）：

- **单一主题**：一张卡只回答一个问题。若需要两个问题，拆成两张并互相链接。
- **信息增益**：每个小节必须提供新信息；重复表述删掉。
- **完备性自检**（三问）：① 小白读完能复述主线吗？② 关键结论有推导或出处吗？③ 有可执行的验证或反例吗？

### 3.4 反堆砌：主干线 + 删除测试 + 前置检查

这是本次设计的核心，直接对应 R4。

**规则 1 · 主干线唯一**
每张卡必须能用**一句话**概括"从问题到答案的一条路"，写在卡顶的「主干线」小节。所有内容都必须挂在这条线上。

> 反例（堆砌）：先讲 SH 的数学定义、再讲 URP 参数、再讲探针类型、再讲性能——四段并列，读者不知道它们为什么放在一起。
> 正例（主干线）：间接光算不起 → 所以要预计算 → 漫反射用 9 个系数（SH）、镜面用 mip 立方图 → 于是配置要喂数据、shader 要采样 → 验证就看"关主光后暗部是否还亮"。

**规则 2 · 删除测试**
逐节问：删掉这一节，读者会迷路吗？

- 会 → 它在主线上，保留。
- 不会 → 它是补充材料，移到 `<details>` 折叠块（扩展阅读 / 推导细节），或直接删。

**规则 3 · 前置检查**
卡顶列出"读这张卡前需要知道什么"，并链接到前置卡。这解决了"小白不知道从哪开始"的问题——他可以被明确告知"先看哪张"。

**规则 4 · 因果连接**
小节之间用因果/依赖连接（"因为…所以…""这一步解决上一节的什么"），禁止"下面我们看…"这类无信息的过渡。

### 3.5 可读性：渐进披露与视觉规范

| 手段 | 规范 |
| :-- | :-- |
| 顶部 30 秒区 | 一句话定义 + 心智模型（一句类比）+ 主干线一句话 + 重入点 |
| 小节首句给结论 | 先结论后论证，便于跳读 |
| 表格 | 用于"≥2 个对象的对比"；列数 ≤4；列名短 |
| 代码 | 必须标语言；单块 ≤60 行；块前一句"这段在做什么" |
| 公式 | 块级 LaTeX + 编号；首次出现的符号就地解释 |
| 折叠 | 只折叠"细节/扩展/历史"，**绝不折叠主线** |
| 术语 | 首现必须给一句定义（面向零记忆读者） |
| 视觉层级 | 用 `###` 分节、`**粗体**`标结论、`> ` 引用给定义；不嵌套超过 2 层列表 |
| 导航 | 长卡（>3000 字）在顶部加锚点目录 |

### 4.2 三种模板

| 模板 | 回答 | 必填小节 | 可选 |
| :-- | :-- | :-- | :-- |
| **理论型** | 为什么 | 核心思想 / 主干线 / 阶梯式解剖（4~6 层，公式编号）/ 实例走查（数值代入）/ 易错点 / 自测题 | 前置检查、重入点 |
| **工程型** | 怎么做 | 核心思想 / 主干线 / 阶梯式解剖（配置与 API 层）/ 实例走查（代码）/ **验证实验** / **排障判据** / 易错点 / 自测题 | 重入点、前置检查 |
| **对比型** | 怎么选 | 核心思想 / 主干线 / 对比表 / 选型口诀 / 场景走查 / 易错点 / 自测题 | 重入点 |

推断规则（默认自动，可显式覆盖）：领域为 `图形学-Shader`/`Unity`/含"接入/配置/参数/坑"→ 工程型；标题含"对比/谱系/选型/取舍"→ 对比型；其余 → 理论型。

## 5. 质量指标与 lint 规则

### 5.1 指标表（可自动检测）

| # | 指标 | 目标 | 检测方式 | 级别 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | 会话残留 | 0 | 正则集（见 5.2） | 警告 |
| 2 | 定义长度 | ≤30（硬 60） | 字符计数 | 错误（>60） |
| 3 | 主干线 | 存在且 ≤1 条 | 检查 `### 主干线` 与行数 | 警告 |
| 4 | 前置检查 | 存在（有前置卡时） | 检查小节 + 链接有效性 | 警告 |
| 5 | 重入点 | 存在（长卡） | 检查小节；>3000 字必填 | 警告 |
| 6 | 验证实验 | 工程型 ≥3 步 | 数编号列表项 | 警告 |
| 7 | 排障判据 | 工程型存在 | 检查小节 | 警告 |
| 8 | 代码块语言 | 100% 标注 | 扫 ``` 后是否有语言 | 警告 |
| 9 | 自测题答案率 | 100%（含 `→`） | 正则 | 警告 |
| 10 | 层级序号 | 4~6 层且带序号 | 正则 `第 \d 层` | 警告 |
| 11 | 关联块格式 | 统一 `- 前置：\`标题\`（ID）` | 逐行解析 | 警告 |
| 12 | 领域标签 | 无根域/子域混用 | 与 `domainFolders` 比对 | 警告 |
| 13 | 数值/代码走查 | ≥1 | 检测数字或代码块 | 警告 |
| 14 | 删除测试自检 | 人工 | — | — |

> 注：**没有"字数"指标**。字数不再是质量信号；但 lint 会输出字数供参考（不做判定）。

### 5.2 会话残留正则集（P0 规则）

```
路径      : [A-Za-z]:\\ | Assets[\\/] | \.(shader|unity|mat|asset|hlsl|cs|md)\b
行号      : \bL\d+(\s*[-–]\s*L?\d+)?\b        # 白名单：L0/L1/L2（球谐带）、LOD
第二人称  : 你|我们|咱们|你的|我们的
时间词    : 今天|刚刚|昨天|上次|本次|现在
阶段代号  : \bP0\b|\bP[1-3]\b|\bW[1-9]\b|\bM[1-3]\b   # 需结合上下文白名单
会话词    : 本工程|实测|排查顺序|先证据后结论|会话|课上
```

**误伤控制**：① 只在代码块**外**扫描；② 白名单优先（`L0/L1/L2`、`LOD`、作为专有名词的 `M1/M2`）；③ 全部输出为**警告**并给出改写建议，不阻塞落盘。

### 5.3 反模式清单（"堆砌"的六种形态）

1. **并列无主线**：多段平铺，读者不知道优先级与依赖关系。
2. **结论埋没**：关键结论出现在长段落中部，没有加粗或提前。
3. **术语裸奔**：首次出现的术语没有一句解释。
4. **跨卡指涉无上下文**：写"W2 在组装处加…"，读者不知道 W2 是什么。
5. **代码无上下文**：贴一段代码不说它在干什么、参数从哪来。
6. **重复表述**：同一结论在多个小节各说一遍，措辞略有差异（还会造成口径漂移）。

### 5.4 lint 输出示例

```text
卡片：URP IBL 接入（202609092139_92d2）  模板：工程型  总分：86/100
  ✓ 定义 35 字（放行）
  ✓ 主干线 存在（1 条）
  ✓ 验证实验 4 步（≥3）
  ✓ 排障判据 存在
  ✓ 代码块语言 1/1
  ✗ 会话残留 2 处：L12 "你的工程"、L30 "实测"
  ⚠ 重入点缺失（正文 3167 字 > 3000 阈值）
  ⚠ 自测题 Q2 无答案
建议：删除会话词；补 `### 重入点`；补 Q2 答案。
```

## 7. 验收：遗忘测试与基线

**遗忘测试（人工，每轮迭代做一次）**

1. 随机抽 5 张卡，只给标题（不给内容）。
2. 限时 5 分钟，口述或写：这张卡在解决什么问题、主线是什么、关键结论、怎么验证。
3. 评分：覆盖度（0-5）/ 因果连贯（0-5）/ 可操作（0-5）。
4. 目标：均值 ≥ 10/15；且"完全忘光"状态下不出现"不知道从哪读起"。

**基线**：先对现有 215 张卡跑 `card_lint`，记录各项命中率，作为迭代前后对比的基准。

**回归**：lint 规则必须带单测（尤其正则的误伤控制，例如 `L0/L1/L2` 不能报"行号残留"）。

## 8. 风险与取舍

| 风险 | 说明 | 缓解 |
| :-- | :-- | :-- |
| 取消字数 → 卡片膨胀 | 单卡越写越长，加载与检索变慢 | 单一主题 + 删除测试；主题变大就拆卡 |
| 模板分型增加使用成本 | 每次都要选模板 | 默认自动推断，只在不确定时提示 |
| lint 误伤导致"为过检而写" | 为了消警告而删掉有价值内容 | 全部警告级；白名单优先；人工可覆盖 |
| 折叠滥用 | 把主线藏进 `<details>` | lint 检查"主线小节不得折叠" |
| 前置检查形成依赖网 | 读者被无限引导 | 只列**直接**前置（≤2 条），并允许"不需要知道"清单 |
